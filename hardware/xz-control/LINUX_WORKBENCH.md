# Linux XZ 电机与磁数据工作台

原控制台与 `windows_acquire.py` 保留。新入口是 `linux_workbench.py` / `python -m xz_workbench`，使用现有 requirements.txt 的 PySide6-Essentials 6.8.3 和 pyserial 3.5，Python 3.10 或更新版本。

界面采用深色主题。“手动控制”和“动作函数”分为两个页签；设备连接、运动参数、更多坐标操作和采集设置按需打开。操作日志默认隐藏，可勾选显示。

## 启动

```bash
cd /home/serein/classify-cloth/xz-control
./start_linux_workbench.sh
```

首次缺少虚拟环境或依赖时启动器会创建 .venv 并安装现有依赖。Ubuntu 若缺少 venv，可安装 `python3-venv`。已有环境也可直接运行：

```bash
.venv/bin/python linux_workbench.py
.venv/bin/python linux_workbench.py --demo
```

`--demo` 只连接模拟设备，不打开实物串口；仍需人工设零和使能。模拟记录的 metadata.json 标明 demo，不能作为实验数据。

真实电机应烧录配套 XZ_Controller 1.4.0（XZ1、可调加速度、连续点动和 numeric_ranges）。程序会实际检查握手；启动不会自动设零、使能或运动，不会自动上传固件。

## 串口

选择电机和传感器两个不同串口，也可在输入框输入 `/dev/serial/by-id/...` 稳定路径。连接电机使用 115200，传感器波特率在界面选择。程序检查同一设备的路径别名；请关闭 Arduino 串口监视器等占用程序。

Ubuntu 串口报 Permission denied 时先用 `ls -l /dev/ttyACM0`（替换实际设备）核对所属组。通常可执行 `sudo usermod -aG dialout "$USER"` 后注销并重新登录。无需以 root 启动工作台。

## 第一次使用

1. 在“设备连接”选择并连接设备，在顶部“运动参数”核对 X/Z 脉冲/mm 与 X 向右符号。250 脉冲/mm 来自旧脚本，必须与实物配置核对。
2. 确认机械当前位置，在手动页点击“当前位置设为零点”，再点击“使能运动”。独立的 X/Z 设零位于“更多坐标操作”；只建立一个轴零点时，现有固件仍不允许使能。
3. 用低速短程核对方向、距离及制动距离，再执行更大动作。Z 负向上、正向下。

位置来自发脉冲的软件计数，不是编码器实测。设零不寻找原点开关。重新连接/中途停止后如果零点失效，需要重新确认并设零，不自动恢复动作。

## 手动运动

- X/Z 分别设置速度 mm/s、加速度 mm/s²；“应用参数”提交。运动中不改变当前动作参数。
- 勾选“启用键盘方向键”：左右控制 X，上下控制 Z；按住移动，松开减速停止。
- 方向键仅在工作台前台、未编辑数值/文本时启动运动。点动期间松键或切走窗口均结束点动。键盘自动重复不会重新发起动作。
- 鼠标“连续”模式同样按住移动；“定距”模式点击一次移动所设距离。键盘方向键始终连续点动。
- 一次只接受一个方向。第二个方向不会叠加，也不会在第一方向松开后自动接续，须重新按下。
- 在“更多坐标操作”可执行所选轴绝对坐标定位、X 回零或 Z 回零；另一轴保持当前位置。
- 录制/运动/函数执行期间不能设零；软件零点改变会清空当前工作坐标的软件边界，需重新配置和检查路径。

参数会换算至整数脉冲，实际行程有最多约半个脉冲的四舍五入误差；非零动作若换算为 0 脉冲会被拒绝。UI 软件边界只是附加保护，未配置时没有机械行程保护。

## 编辑动作函数

1. 新建并命名流程，点击“添加”。
2. 每行选择相对移动、绝对定位、回零或等待。选择 X/Z；相对移动用方向和正距离，绝对定位直接填写带符号坐标。
3. 速度/加速度显示“全局”时继承左侧设置，也可给每行单独填写。等待行只使用等待秒数。
4. 可复制、删除、上移、下移或取消某行“启用”。
5. 点击“检查路径”查看每步起终点、脉冲位置和理想用时；检查不能证明机械不碰撞。
6. “保存”输出版本化 JSON；“加载”复用。配置不一致时必须核对并点击“采用当前配置”，再检查路径或重新保存。
7. 点击“运行函数”，或完成传感器校准后点击“运行并采集”。

各步骤串行执行，到位确认后再进入下一步。程序不按预计时间强行推进。单步 MOVE 的最大等待上限为 600 秒，预计动作过长会拒绝启动。第一版没有暂停/继续、循环、分支或任意代码执行。

函数完成后保持最后一步的位置；希望回零就自己添加指定轴回零。X 回零不同于返回函数起始 X 位置。流程加载不恢复旧零点，绝对目标总是相对当前工作零点。

## 磁数据采集

传感器输入为原始四列 CSV：`t_us,Bx_uT,By_uT,Bz_uT`，单位按传感器固件为 µT。不是原始 B 的 ΔB 输入不能直接作为原始磁场接入本采集器。

连接传感器并确保数据持续更新，在“采集设置”中、静止空载状态点击“采集空载基线 · 2 秒”。至少需要 20 个有效样本；程序不会自动移动机构寻找空载。曲线校准后显示 ΔB，保存仍同时保留 B 和 ΔB。

- “开始采集 / 结束保存”自行决定记录边界，可包含静止、点动、定距和普通函数运行。
- “运行函数”不改变已存在的手动录制边界。
- “运行并采集”创建独立记录，收到首个新样本后启动函数，函数完成或中止后结束保存。
- “结束保存”只结束手动录制，不主动停止电机；“停止全部”同时中止运动与活动录制。
- 录制中的传感器断流、控制器异常或写盘失败会中止运动并尽力保留已有记录。

默认写入 `data/experiments_linux/<时间戳>/sensor.csv`，可以选择其他保存目录。辅助 metadata.json 保存基线、配置、流程和完成/中止原因。每次创建新目录，不覆盖旧记录。

CSV 使用 UTF-8 BOM；以下 23 列与 windows_acquire.py 的列顺序、名称和含义一致：

```text
seq,sensor_t_us,device_time_unwrapped_us,device_clock_segment,sensor_t_s,host_rx_ns,host_elapsed_s,stage,motor_x_pulses,motor_z_pulses,motor_target_x_pulses,motor_target_z_pulses,motor_busy,motor_phase,motor_fault,Bx_uT,By_uT,Bz_uT,dBx_uT,dBy_uT,dBz_uT,sample_valid,invalid_reason
```

`stage` 值改为实际工作台状态或稳定动作编号 step_001 等；不是旧四段流程的固定枚举。dB=B-B0，尖峰标记不删除原始样本，格式错误的行计数。设备时间可能回绕或复位，复位时用 device_clock_segment 区分；不能跨时钟分段直接当连续时间。

CSV 分批写盘，尾部最多等待一帧确认尖峰。主机时间是串口接收时间，motor 字段是最近的控制器软件状态；两路串口没有硬件同步。正常中止保留文件，强制杀进程或断电不能保证尾部数据落盘；初始 metadata 的 interrupted 状态用于识别未正常结束。

## 停止与硬件边界

空格或“停止全部”使用固件 STOP，撤销后续动作且取消软件使能；需要检查参考是否失效。松键使用 JEND 减速停止，有制动距离。切换窗口只结束手动点动，已主动启动的自动函数继续运行；关闭工作台会中止函数。

现有硬件控制没有接入机械限位/原点搜索、硬件急停和编码器位置反馈。软件 STOP 不切断动力，也不提供 Z 轴防下滑保护。按实际机械行程、负载和接口配置使用。
