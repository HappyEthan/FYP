# XZ 双轴控制台

本地桌面 GUI + ESP32-S3 配套双轴固件。单位为脉冲、脉冲/秒、脉冲/秒²。保留原单轴测试文件，不自动上传、不自动连接硬件、不在启动时运动。

## 启动

在项目根目录双击 `启动双轴控制台.command`。首次启动会创建根目录 `.venv` 并安装依赖。

也可以先按[项目首页](../README.md)安装依赖，再在项目根目录执行：

```sh
.venv/bin/python -m xz_control
```

默认选择“模拟演示”，点击“连接”即可体验。模拟展示交互、执行顺序及理想梯形/三角形速度曲线，不模拟脉冲输出抖动、负载或失步，也不会打开串口。模拟和真实设备必须先断开再切换。

## 功能与操作

1. 连接 → 确认当前位置 → “两轴设零” → “使能运动”。也可分别设置 X、Z 零点。
2. 每轴输入目标、恒速目标和加速度。初始目标 10 脉冲，速度 10 脉冲/秒，加速度 1000 脉冲/秒²。
3. 选择相对位移或绝对位置：
   - 相对位移：例如当前位置 100，输入 20，最终目标为 120。
   - 绝对位置：输入 20，最终目标为软件零点的 +20。
4. 选择执行顺序，再按“执行双轴任务”：
   - X → Z：X 完成后才启动 Z。
   - Z → X：Z 完成后才启动 X。
   - 同时开始：在同一运动计划中启动两轴，各自按设定速度和加速度运动，可能先后到达；不保证同一微秒启动、同步到达或直线插补。
5. “停止全部”或窗口内空格键：立即停止软件脉冲、取消尚未开始的轴、取消使能。突然停止可能造成实际位置偏差，因此运动中停止后需要重新确认并设零。
6. “取消使能”：禁止新任务；若正在运动，同样立即停止并取消待执行的第二轴。
7. “复位故障”：清除通信故障锁存，不自动使能或恢复运动。
8. “通信记录”：展开串口命令、确认、错误和完成信息。
9. **“一键回零点”**：两轴返回之前设置的软件零点 X=0、Z=0，使用当前所选运动顺序、两轴速度和加速度。无论输入框当前选择相对位移还是绝对位置，回零都发送绝对目标 0；不会改写零点，也不覆盖输入框里的任务。须已连接、两轴已设零、已使能、空闲且无故障。已取消单次 10000 脉冲限制。回零过程中可“停止全部”。这不是寻找原点开关的 HOME。当前 GUI 需要配套固件 1.4.0。

按最新方向反馈，实时点动采用 Z 上＝负方向、Z 下＝正方向。自动任务的坐标正负和固件 DIR 极性没有修改。X 正方向需按机构记录。

传感器位置示意图只显示 X 正半轴（向右）和 Z 正半轴（向下），软件零点在图的左上角。范围自动缩放，两轴刻度独立。X<0 或 Z<0 的点会提示“在显示范围外”，不会镜像或伪装到显示区域内；位置数字仍保留实际软件计数。此显示选择不改变运动方向或限制可输入的坐标。

## 真实硬件使用

先上传 `firmware/XZ_Controller/XZ_Controller.ino`（版本 1.4.0）。GUI 握手要求 XZ1 协议且声明 `move_accel: true` 和 `numeric_ranges: true`；旧单轴固件及旧双轴 1.0–1.3 固件会被拒绝，并提示更新，避免界面加速度未生效。

Arduino 配置：

| 项目 | 配置 |
| --- | --- |
| 开发板 | ESP32S3 Dev Module |
| 库 | AccelStepper 1.64.0 |
| USB CDC On Boot | Enabled |
| USB Mode | Hardware CDC and JTAG |
| Upload Mode | UART0 / Hardware CDC |
| Flash Size | 16MB |
| PSRAM | Disabled；当前程序不使用 PSRAM |
| 波特率 | 115200 |

X 使用 GPIO35（STEP）/ GPIO36（DIR），按用户已测试配置保留；Z 使用 GPIO4（STEP）/ GPIO5（DIR）。标准 ESP32-S3 N16R8 的 GPIO35–37 涉及内部 PSRAM 占用，关闭软件 PSRAM 并不能证明引脚硬件无冲突，实际板卡仍需核对。GPIO 与 HBS57 5 V 共阳输入之间需要适当低侧接口；程序不能证明当前直接连接电气可靠。

上传前固定竖直负载，关闭驱动器动力，USB 为主控供电。上传后关闭 Arduino 串口监视器/串口绘图器，避免占用串口。在 GUI 选择“真实设备”、正确端口，再连接。首次接入仅用 10 脉冲低速测试，确认方向和运动余量。双轴同时带载前，现有 24 V/4 A 电源余量需实测验证。

## 界面显示的含义

- **位置和当前速度来自固件发脉冲的计数和调度值，不是编码器实测。** 编码器仍接在 HBS57 上，ESP32 没有读取它。
- 每次 ESP32 复位后，两轴软件位置为 0，但标为“需要设零”；这不代表机械在原点。重新确认零点后才允许 ARM。
- **设零只改坐标，不移动机械，不执行 HOME。** 运动中禁止设零。
- 当前 ENA、ALM、限位和电源继电器没有接入。界面“使能运动”只控制发脉冲权限；“动力上电：外部手动”明确表示 GUI 无法接通/切断 24 V，也不能控制电机释放或保持。
- **软件停止不是硬件急停。** Z 轴须有适当支撑/防下滑措施。
- GUI 关闭或断开会尝试 STOP；若线缆被拔出、进程卡住，固件在 1.5 秒未收到 PING 后停止脉冲并锁存故障。这不等于立即硬件急停，控制器本身卡死时也不能依赖它。
- 固件自 1.1.0 起与 GUI 已取消人为设定的 1000 脉冲/秒上限；速度须为正整数，仅受串口协议有符号 32 位整数表示范围约束（最大 2147483647），这不是可实现的物理速度。需重新上传新版固件，否则旧固件仍会拒绝超过 1000 的请求。默认速度保持 10 脉冲/秒。
- 已取消单次 10000 脉冲及软件坐标 ±1000000 的人为上限；普通 MOVE、点动、回零及实验模式一致。没有根据机械行程配置物理软限位。 两轴加速度可独立设置，默认 1000 脉冲/秒²，同一数值用于加速和到位前减速。实际速度取决于加减速距离、软件脉冲输出能力和机械负载，设置更大数值不代表电机能达到该速度。

## 快速起步与恒速运行

运动采用静止 → 加速 → 恒速 → 减速 → 到位停止的曲线。加速度越大，起步越快；默认值不是电机极限，也不是经过实物验证的最大加速度。

设速度为 v、加速度为 a、位移绝对值为 D，理想连续模型为：

- 达到设定速度的时间：v / a。
- 加速和减速合计需要的距离：v² / a。
- D > v² / a 时，恒速段距离为 D − v² / a。
- D < v² / a 时，全程为三角形速度曲线，峰值为 √(aD)，达不到设定速度；D 恰好等于边界时也没有持续恒速段。

例如速度 1000 脉冲/秒、加速度 5000 脉冲/秒²、位移 1000 脉冲：约 0.2 秒加速、800 脉冲恒速（0.8 秒）、0.2 秒减速。数值用于说明设置方法，需在实际负载上验证。

界面显示每轴理想加速时间、恒速段距离和减速时间；行程不足时提示预计峰值。执行时冻结预估，完成后按下一任务更新。软件不会为了达到速度而自动延长行程。回零也使用当前加速度。

AccelStepper 的 `run()` 仍由主循环产生脉冲，恒速段表示调度目标恒定，并不保证高频下的脉冲间隔完全均匀或电机实测转速恒定。界面速度是调度值；若要求严格的高频脉冲定时，应另行改用 ESP32 硬件定时/RMT，并测量脉冲与机械表现。

## 通信协议 XZ1

命令为 ASCII 换行结尾，返回为一行一个 JSON 对象。只有确认 XZ1 握手及可调加速度能力后 GUI 才开放运动。

```text
HELLO
PING
STATUS
ZERO X
ZERO Z
ZERO ALL
ARM
DISARM
STOP
CLEAR
MOVE REL XZ 10 10 10 10 1000 1000
MOVE ABS ZX 0 0 10 10 1000 1000
MOVE REL SIM 10 10 10 10 1000 1000
```

MOVE 参数顺序：坐标模式、执行顺序、X 目标、Z 目标、X 恒速目标、Z 恒速目标、X 加速度、Z 加速度。数值参数为整数，速度和加速度均须为正整数且不超过 2147483647。旧的省略两轴加速度的七字段 MOVE 仍可用，明确采用旧值 50 脉冲/秒²；新 GUI 始终发送完整参数。运动中拒绝追加 MOVE。STOP 和 DISARM 清空整个计划。

GUI 每 0.3 秒发 PING，固件约每 0.2 秒发状态。GUI 1.5 秒未收到有效状态就断开、清除当前位置显示；命令 2 秒没有确认时请求停止并断开。真实连接握手后先发 DISARM，断线后不会自动重连或恢复运动。

## ESP32-C3 磁毛传感器监测

右侧新增独立传感器面板，与电机的 ESP32-S3 串口分开。此功能仅修改电脑 GUI，不要求重刷任何固件。I²C 地址 0x0C 为用户给出的板上配置，GUI 不访问 I²C、不改变采样频率、不向传感器串口写入命令。

1. 插入 ESP32-C3 USB，关闭占用该串口的 Arduino 串口监视器或其他监测软件。
2. 在右侧点击“刷新”，选择 C3 的串口；默认波特率 115200（可调整），点击“连接传感器”。左侧电机仍选择 S3 的另一个串口。程序不会自动选择并连接设备。
3. 两张图分别显示 X/Y 分量（传感器原有三轴输出格式保持兼容，Z 不绘图、不显示当前数值），默认最近 10 秒，可选 2/5/10 秒，纵轴分别自动缩放。接收频率是电脑最近约 2 秒的有效样本统计，不是传感器寄存器设定值。横轴是电脑接收时间；串口批量抵达的样本可有相同时间，不保证与电机严格同步。
4. 支持 `Ymin:-600,dBx:1,dBy:2,dBz:3,Ymax:600`、`Bx:1,By:2,Bz:3` 和 `t_us,x,y,z` 四列 CSV。CSV 若收到 `t_us,Bx,By,Bz` / `t_us,dBx,dBy,dBz` 表头，会识别为 B / ΔB；没有表头时不猜测语义。单位 µT 按现有 FYP 固件约定，图中不额外平滑；固件原本输出平滑 ΔB 时保留该结果。
5. “暂停曲线”冻结图像，采集与当前数值继续更新；“清空曲线”只清显示缓存，不设传感器基线或电机零点。未收到有效数据超过 2 秒后，当前数值显示为失效，历史曲线保留并标注状态。
6. 右侧“最近串口行”用于核对实际输出；无法识别的行不会画成数据。支持分包和超长行恢复，缓存有限。传感器中断不改变电机的运行状态；关闭整个窗口会关闭两路串口并沿用原有电机停止流程。

本地已用合成数据检查曲线布局，并测试分包、格式识别、坏值、过期状态、独立连接和串口冲突保护。尚未验证目前 C3 实机输出。[`sensor_preview.png`](images/sensor_preview.png) 是合成数据预览，不是传感器测量结果。

## 实时点动（电机固件 1.4.0）

控制区固定按钮栏增加 X−、X+、Z下 (+)、Z上 (−)。先连接电机、确认两轴软件零点并使能，再按住一个方向按钮。点动使用对应轴的速度和加速度，不使用目标位移输入框；一次只点动一个轴，自动任务运行时不能点动。

- 松开鼠标或主窗口失去焦点，发送 JEND，按设定加速度减速停止；会有减速距离，不是松手瞬间位置不变。正常减速完成后保留使能和软件零点，可以再次点动。
- 点动及自动 MOVE 均取消原有 10000 脉冲和 ±1000000 坐标上限。点动在方向上滚动扩展内部目标，直到松开或达到整数表示边界；边界检查是防溢出，不是机械行程限制。
- “停止全部”/空格、取消使能仍立即停止脉冲。运动中这样停止会使软件零点失效。
- GUI 按住期间每 100 ms 发 JKEEP。固件独立于 PING 检查 350 ms 点动有效期，超时立即停止脉冲、取消使能、锁存 JOG_TIMEOUT 并使零点失效。复位故障并重新确认零点后才能继续。正常松开后的减速阶段仍受原有 1.5 秒通信心跳约束。
- 点动启动命令：`JOG X 1 500 5000`（轴 X/Z、方向 +1/−1、速度、加速度）。`JKEEP` 只续期当前点动，不启动或恢复运动；`JEND` 幂等结束点动，不影响自动 MOVE 任务。
- HELLO 声明 `jog:true`、`jog_continuous:true` 和 `numeric_ranges:true`。新 GUI 会拒绝仍有旧限制的固件并提示上传 1.4.0。只有电机 S3 需要更新，传感器 C3 不需要重刷。

本地新增点动释放、提前释放（先于启动 ACK）、独立续期超时、不自动恢复、边界和停止等测试。尚未操作实物进行点动验证。


## 平面扫描实验（GUI 功能，无需重刷固件）

“平面扫描实验”页执行：Z 到实验高度 → 开始记录 → X 扫描到终点 → 停止记录并保存 → Z=0 → X=0。零点是用户手动设置的零点，不是原点开关位置。

### 操作

1. 连接真实电机 S3 和传感器 C3，确认磁场数据持续更新。模拟电机模式不能生成实验测量记录。
2. 用点动把传感器移到希望的实验起始位置，待停止后按“两轴设零”。实验开始必须处于 X=0、Z=0，且两轴已设零、已使能、无故障。
3. 在“运动控制”页设置两轴速度和加速度，然后进入“平面扫描实验”页设置 X/Z 绝对终点。Z 正向下、负向上；X 不能为零。实验不使用普通任务的相对/绝对选择或移动顺序选择。
4. 选择保存目录（默认 `data/experiments`），点击“开始实验”。每次自动创建时间戳子目录，不覆盖已有实验。
5. 实验锁定手动任务、点动、零点设置和连接切换。“停止全部”、空格、取消使能或“中止实验”可中止整个流程；不会中止后自动恢复或自行回零。

实验终点与普通任务均开放完整的 32 位坐标输入；没有额外的实验位移上限。开始前仍校验去程与回程的整数运算是否可表示，验证失败时不会运动。

### 记录边界和文件

- 在任何运动前，先验证四段运动参数并创建可写的文件。
- Z 到位需要 MOVE 确认、完成通知及目标位置一致的空闲状态；随后开始记录。至少写入一个有效磁场样本后才发送 X 扫描命令。
- 收到 X 完成通知时停止接收记录；确认终点位置后，刷新并关闭 CSV，写入扫描完成元数据，然后发起 Z 回零。Z 回零确认后才发起 X 回零。
- `magnetic_xyz.csv` 保存扫描期间的磁场 X/Y/Z（µT）。每行包括记录相对时间 `host_elapsed_s`、电脑单调时钟 `host_monotonic_s`、UTC 接收时间 `received_utc`、实验相对时间 `experiment_elapsed_s`、实验阶段 `experiment_stage` 和 B/ΔB 语义 `signal_kind`，以及最近一次控制器状态和状态年龄 `motor_status_age_s`。
- 每行控制器字段：当前位置 `motor_x_pulses` / `motor_z_pulses`；目标 `motor_target_x_pulses` / `motor_target_z_pulses`；速度调度值 `motor_vx_pps` / `motor_vz_pps`；使能 `motor_armed`、运动中 `motor_busy`、运动阶段 `motor_phase`、零点有效标志 `motor_refx` / `motor_refz`、故障 `motor_fault`；目标减当前位置计算的剩余脉冲 `motor_remaining_x_pulses` / `motor_remaining_z_pulses`。这些是固件的软件状态，不是编码器实测、电流、扭矩或 ALM 信号。
- `controller.csv` 在整个实验期间逐条保存控制器状态，包含 Z 定位、X 扫描、Z 回零、X 回零。时间列为实验相对时间、电脑单调时钟、UTC，随后是实验阶段及上述控制器字段；不按传感器采样率插值。
- `events.jsonl` 每行一条 JSON 事件，保存带时间的实验开始、MOVE/STOP 请求、控制器 ACK/完成/错误消息、开始记录、扫描保存和实验完成/中止。命令请求不代表已执行，需结合 ACK 和状态；不记录周期性 PING。中止后停止继续采集，因此中止时的 STOP 请求会记录，但不保证包含其后回来的 ACK 或最终状态。
- 三个数据文件都在运动前创建；扫描结束只关闭磁场 CSV，控制器和事件文件继续记录至实验结束或中止。界面仍只显示磁场 X/Y，Z 仅加入数据记录。新版文件格式为 schema_version=3，旧的 `magnetic_xy.csv` 不改写，也不能补出过去未记录的 Z 数据。
- `metadata.json` 保存终点、速度/加速度、串口、磁场样本数、控制器状态数、事件数、文件名、字段语义、扫描是否完成、是否回零和中止原因。传感器已输出 ΔB 时原样保存，不重复扣基线；未知 CSV 语义按未知标记。
- 两路 USB 串口不做硬件同步。CSV 的时间是电脑接收时间，位置是最近一次控制器状态，不是每个样本的编码器同步实测；串口缓存也可能导致边界样本存在延迟。数据包括 X 起步加速及终点减速段，不只是恒速段。
- 采集中每约 0.25 秒刷新 CSV；正常结束时执行刷新与落盘。突然断电/进程被强制杀死可能丢失尚未刷新的尾部样本，不保证执行自动回零。
- 传感器有效数据超时 2 秒、连接中断、控制器故障/拒绝命令、保存失败或用户停止，会终止实验、请求 STOP、关闭文件并尽力保留已采集数据。保存失败会报告错误，不宣称实验成功，也不进入后续回零动作。

本地测试覆盖全流程顺序、只有扫描段记录、无首样本不启动 X、缺少 ACK 不推进、终点不匹配中止、断流保存、三轴磁场及控制器状态正确入 CSV、保存失败不回程及手动操作锁定。尚未运行真实平面扫描实验。

记录扩展测试还覆盖全流程控制器状态、命令事件顺序、返回零点末状态、记录文件创建失败时不运动、控制器记录写入失败时中止，以及中止时关闭所有文件。


## 数字表示边界（1.4.0）

所有人为位移、坐标与速度上限均已取消。以下是当前协议、Qt 整数输入和 AccelStepper 运算格式的边界，不是可实现的物理性能：

- 坐标/输入位移：−2147483648 到 2147483647 脉冲。
- 速度和加速度：正整数，最大 2147483647；方向仍由目标或点动按钮决定。
- 相对移动的最终坐标必须可用 32 位有符号整数表示。
- 单条自动 MOVE 的目标减当前位置的绝对值不能超过 2147483647，否则 AccelStepper 的 32 位差值/绝对值运算会溢出。比如从 −1 直接到 +2147483647 需要拆成两条运动；程序不会静默截断或绕回。
- 点动使用滚动目标避免跨零长距离差值溢出，在 INT32_MIN / INT32_MAX 边界停止。设零仍由用户明确操作，不自动重置坐标。
- 不修改心跳、点动有效期、停止、故障锁定和零点确认逻辑。大数值请求只代表被接受，实际脉冲频率仍受软件调度及驱动器/电机能力影响。

需要重新上传电机 ESP32-S3 的 1.4.0 固件并重开 GUI；传感器 C3 不需要更新。新增验证覆盖超旧限值的普通任务/实验/回零、状态解析、整数溢出拒绝和点动数值边界。


## 接收延迟诊断与设备时间（schema_version=3）

GUI 接收轮询改为 10 ms，绘图/文字刷新为 50 ms；原始串口文本不再逐样本更新控件，而是与显示定时器一起刷新。每个有效样本仍独立发送给记录器，不因降低文字更新次数而删掉记录。

四列 CSV 的第一列按既有 t_us 协议保留为 `device_time_us`，不再丢弃。没有设备时间的标签格式将这些字段留空，不捏造采样时刻。新增记录字段：

- `device_clock_segment` / `device_clock_reset`：设备时间倒退（复位/回绕）时分段，避免跨段拼接时间。
- `relative_transport_lag_s`：当前“电脑读取时间减设备时间”相对连接以来最小值的增量；可帮助识别积压增长，但不是绝对延迟，无法识别连接前就存在的固定延迟，也可能受时钟漂移或错误的时间单位影响。
- `serial_pending_bytes`：本次读取前操作系统报告的串口可读字节数；正常分批到达也会大于零，不直接等于丢样数或延迟秒数。
- `read_batch_id`：同一批读取的数据共用编号；主机接收时间仍可能相同，分析采样间隔应优先使用同一设备时钟分段中的设备时间。
- `host_poll_gap_s`：本次与前次轮询间隔，用于发现主线程长时间未轮询。

界面显示接收频率、按设备时间间隔估计的频率、相对延迟增量和读取前缓冲量。这里不丢弃旧样本来制造实时效果，绘图历史仍以主机接收时间排列。显示和记录仍与电机 GUI 共用线程，此次优化不是硬实时或独立线程采集保证；写盘、其他阻塞或串口积压仍需通过诊断字段检查。磁场与电机位置尚未硬件同步，设备时间保留并不能单独恢复准确的跨板位置对应。

电机未连接运行时的一次实际串口检查接收了 3299 个四列 CSV 样本，按设备时间间隔约 332.6 Hz，最大设备时间间隔约 7 ms，读取前缓冲峰值 179 字节，主机-设备时间差波动约 3.9 ms。这是空闲接收链路检查，没有包含平面滑动，不能据此确认滑动时的延迟原因或采样精度。


## 长时间曲线卡顿修复与实际 C3 固件核对

已通读用户提供的 `mlx_c3_monitor(1).ino`：采样目标间隔 3000 µs（约 333 Hz），读数前等待 2 ms，OSR_0/FILTER_0。输出是原始 Bx/By/Bz（µT），并未扣除基线，也没有 EMA 软件平滑；暖机计算的 B0 只打印参考。第一列来自读数完成后的 `micros()`，32 位微秒计数回绕会由现有时间分段标志标出。GUI 现在识别其 `# now streaming: t_us,Bx_uT,By_uT,Bz_uT` 声明，将信号标记为 B。

旧界面把密集噪声样本逐点画成抗锯齿折线。相同尺寸（400×550、2×像素密度）合成 333 Hz 噪声的本地测试中，积满历史后的单帧重绘约 3003 ms；清空后短时点数减少可掩盖问题。绘图与串口接收共用主线程，慢帧会延后读取，并影响主机时间和控制器位置的对应，因此不应将旧现象认定为纯视觉问题。

修复后：

- 显示缓存按 50 ms 时间段聚合，每段保存 X/Y 各自的最小、最大及首尾值；只保留最近 10 秒，硬上限 202 段，运行更久不会继续增加绘图数据量。
- 使用不带抗锯齿的批量线段绘制极值包络，保留短暂峰值，避免高密度折线的昂贵描边。上述测试场景下，稳定重绘约 14 ms；该数字是本地合成数据性能测试，不是所有电脑上的保证。
- 显示窗口可选 2/5/10 秒。观察快速变化可用 2 秒；纵轴范围按所选窗口更新，旧的大峰值退出窗口后不再压缩当前小变化。
- 包络聚合仅用于显示。每个有效原始样本仍独立传给 CSV 记录器，设备时间和三轴磁场不按显示频率抽样或平均。测试中在暂停/清空曲线的同时输入 5000 个样本，CSV 保留全部 5000 行。
- 100000 个连续合成样本的缓存测试验证了显示段数上限、过期淘汰及峰值保留。仍需重开 GUI 后在真实滑动实验中复测；不需要修改或重刷 C3/S3 固件。

## Recalibration：空载磁场归零

连接 ESP32-C3 并收到数据后，让磁毛保持空载静止，点击传感器面板的 **Recalibration · 空载归零**。GUI 在接下来约 2 秒内对原始 X/Y/Z 样本求平均，作为固定基线；完成后清空旧曲线并显示“当前输入 − 基线”。界面只显示 X/Y，Z 同样校正并记录。空载读数应在零附近波动，噪声不会被强制置零；后续采样不追加平滑。重复点击会用新的原始样本重新计算基线，不会累加扣除。

校准期间禁止从 GUI 启动运动或实验，停止按钮仍可用；运动、等待控制器确认或实验期间不能校准。数据中断、明显积压或样本不足会取消此次校准并保留之前的基线。断开/重连清除基线，需要重新校准。基线仅存在于当前连接会话，不写入 C3 固件；本功能不需要重刷任一开发板。请重启 GUI 以加载更新。

实验 CSV 格式升为 schema_version 4，保留原有全部原始样本和控制器字段，追加：

- `magnetic_x_uT / magnetic_y_uT / magnetic_z_uT`：原始串口数值，字段含义不变。
- `corrected_magnetic_x_uT / corrected_magnetic_y_uT / corrected_magnetic_z_uT`：每个样本减去基线后的数值。
- `baseline_x_uT / baseline_y_uT / baseline_z_uT`：该样本所用三轴基线。
- `calibration_id`：当前连接中的校准编号；0 表示未校准，此时基线为零、校正值等于原始值。

`metadata.json` 的 `context.sensor_calibration` 保存实验开始时的基线、校准编号、完成时间、样本数及计算方法。`signal_kind` 始终描述原始输入是 B 或 ΔB；校正不改变原始输入的含义。实验期间无法更换基线。
