# Linux XZ 电机与磁数据采集工作台设计草案

日期：2026-11-12。状态：供用户审查，尚未实施。

## 1. 已确认的目标

- Linux 桌面工作台，可用鼠标和键盘操作 X/Z 电机。
- 左右方向键控制 X，向上/向下方向键调整 Z；按住持续移动，松开停止。
- 可设置运动速度、执行固定距离运动、自由选择当前位置作为软件零点。
- 用户用界面表格添加、排序和配置动作，保存成命名的 function/动作函数，然后自动执行。
- “前进、抬起、回原点”只是动作函数的例子，不固定成系统唯一流程。
- 磁数据 CSV 沿用 windows_acquire.py 的列名、列顺序及数据含义；不继承它固定的运动流程。

## 2. 实现方式与范围

推荐保留现有 XZ1 设备协议、通信和协议检查，重组 PySide6 工作台界面，新增通用动作执行器及独立 CSV 记录器。现有鼠标点动使用的 JOG/JKEEP/JEND 可以复用；键盘和鼠标必须共享同一套点动状态。

另一种方式是完全重写独立界面和通信程序，但会重复串口、心跳、状态与停止验证，本轮不采用。直接扩展 windows_acquire.py 为主界面不合适：它的同步采集流程和固定四段运动需要重构。既有 GUI experiment.py 的 CSV 与指定格式不同，不能直接当作新 CSV 导出器。

第一版提供串行的单轴动作、等待、流程保存和加载。双轴同时插补、循环嵌套、条件分支、在线分类、运行中修改动作和任意 Python 代码编辑不纳入第一版；这些是方案范围建议，用户可以调整。

本轮仅形成设计，不安装依赖、不修改产品代码、不烧录固件、不控制实物电机。原有脚本、实验记录和原有功能入口保留。

## 3. 工作台布局

```text
顶部：电机串口/连接  传感器串口/连接  状态  [停止全部]
┌─────────────────────┬────────────────────────────────┐
│ 手动控制             │ 动作函数                        │
│ X/Z 当前位置、零点状态│ 名称 / 新建 / 加载 / 保存       │
│ X/Z 速度与加速度     │ 动作表格                        │
│ 上下左右方向按钮     │ 新增 / 复制 / 删除 / 上移 / 下移 │
│ 连续 / 定距模式      │ 检查 / 运行 / 运行并采集 / 中止  │
│ 定距长度 / 指定坐标  │ 当前动作、进度、预计终点        │
│ X设零 / Z设零 / 两轴设零│                               │
│ X回零 / Z回零        │                                │
├─────────────────────┴────────────────────────────────┤
│ 磁场 Bx/By/Bz 实时值与曲线；空载基线；开始/结束采集   │
│ 保存目录、文件名、样本数、阶段、数据状态、简短日志      │
└──────────────────────────────────────────────────────┘
```

单位默认显示 mm、mm/s、mm/s²。高级配置可查看 pulse、pulse/s、pulse/s²。
图示和按钮直接标注 X 左/右与 Z 上/下，避免将 Hall 磁场坐标与机械轴混淆。

## 4. 参数与坐标

X/Z 各自配置 pulses_per_mm，初始建议值为原脚本的 250，但不能未经实物核对就作为标定结论。方向映射分别可配置；原软件采用 Z 正向下、负向上，新工作台沿用这一约定，显示为“上/下”。向右对应 X 的符号以现场核对为准。

默认速度和加速度由每轴控制区设置，动作行可以覆盖。运动中不实时修改当前动作的速度；新值对下一次动作生效。所有动作启动前显示换算后的实际脉冲与可执行距离，四舍五入至最近脉冲；非零距离若小到转换为零脉冲则拒绝启动。速度和加速度也需转换为有效正整数并通过固件范围检查。

所有位置显示为固件软件脉冲位置，不宣称是编码器实测。坐标有未建立、有效、失效三种状态；停止导致参考失效或断连时禁止绝对定位，提示重新确认当前位置并设零。

## 5. 手动控制

### 5.1 连续点动

方向键固定为按住移动：左右控制 X，上下控制 Z。界面方向按钮在“连续”模式下同样按住移动、松开减速停止。

- 首次按下启动 JOG，约每 100 ms 发送 JKEEP；松开停止续约并发送 JEND。
- 过滤操作系统的自动重复键盘事件；不因自动重复造成停走抖动。
- 仅在键盘控制已启用、工作台处于活动窗口、没有文本/数值编辑或模态对话框时响应新的方向键。
- 点动已启动后，无论控件焦点如何变化，松键事件均结束对应点动；失焦、切换模式、打开对话框和关闭窗口也结束点动。
- 一次只接受一个方向和一个输入来源；同时按其他方向或鼠标按钮不叠加运动，也不在第一个方向释放后自动启动被忽略的方向，必须重新按下。
- 键盘和鼠标共用运动占用状态；任何停止命令都撤销点动状态。
- 松开是减速停止，有制动距离；停止全部使用既有 STOP 语义，不能等同硬件断能。

### 5.2 定距与定位

鼠标方向按钮切换到“定距”模式后，点击一次按选定方向移动指定距离，到位停止；按住按钮不会重复发起多段运动。键盘方向键仍保持连续点动，不随鼠标模式改变。

另提供“移动到坐标”：选 X 或 Z，输入当前工作坐标系中的目标坐标并执行。界面明确区分相对位移与绝对位置。手动运动、动作函数、设零之间互斥，停止全部始终可用。

## 6. 软件零点

提供 X 当前位置设零、Z 当前位置设零、两轴当前位置设零。只能在机械已停、无待确认命令、无函数执行和无采集录制时操作；软件零点会改变 CSV 中位置的参考，不能在同一记录内悄然改变。

设零不移动电机，不搜索原点开关。取消固定流程后，不会在启动或执行函数前自动设零。首次使能仍需满足现有固件的两轴参考有效条件。

X 回零只移动 X 到 0 并保持 Z；Z 回零只移动 Z 到 0 并保持 X。“两轴回零”不设计成隐含路径按钮，用户在动作表中显式规定先后顺序。

函数中的绝对位置和回零引用执行时的当前工作坐标系；加载流程不自动恢复或重设之前的零点。重新设零后，流程标记为需重新检查，运行前重算预计终点。函数不包含隐式设零步骤。

## 7. 动作函数编辑器

function 是一个用户命名、可保存和重用的动作表，不要求编写 Python。

建议列：序号、启用、动作类型、轴、方向、距离/目标坐标、速度、加速度、等待时间、名称/备注。根据动作类型禁用不适用的字段。

第一版动作类型：

| 类型 | 参数与行为 |
| --- | --- |
| 相对移动 | 选择 X/Z、方向、非负距离；沿该方向移动指定长度 |
| 绝对定位 | 选择 X/Z、带符号目标位置；移动到工作坐标 |
| 指定轴回零 | 选择 X/Z；等价该轴绝对定位到 0，另一轴不动 |
| 等待 | 在原处等待指定秒数，仍持续通信和采集 |

每个移动步骤可独立设置速度与加速度，未覆盖时使用全局设置。启动时冻结参数快照；运行中不能修改步骤、重排、设零或插入手动运动。

支持新增、复制、删除、启用/禁用、上移/下移、保存、另存为、加载。流程以版本化 JSON 保存，包含单位、动作参数及方向/换算配置摘要；不是磁数据输出格式。加载时检查配置差异，要求用户核对；不直接执行文件内任何 Python 或 shell 内容。

示例仅用于说明编辑能力，假定 X 正向右、Z 正向下：

| 序号 | 动作 | 轴 | 方向 | 距离/位置 | 速度 |
| --- | --- | --- | --- | --- | --- |
| 1 | 相对移动 | X | 右 | 100 mm | 2 mm/s |
| 2 | 等待 | — | — | 0.5 s | — |
| 3 | 相对移动 | Z | 上 | 5 mm | 1 mm/s |
| 4 | 指定轴回零 | X | 自动 | X=0 | 4 mm/s |

该例结束时 Z 保持抬起。若需要降回，用户自己追加“Z 回零”。“回零”不同于“回函数开始位置”；第一版不额外提供后者，若需要可填写明确的绝对目标。

## 8. 函数执行与停止

“检查”按当前坐标、启用步骤、冻结的全局参数和标定，计算每步软件起终点、预计路径、理想用时和最终位置。无法证明物理防碰撞，不显示为安全认证。移动步骤一次只动一个轴。

“运行”逐行动作；“运行并采集”先创建可写记录、确认基线和有效传感器样本，再执行动作。单独运行不要求传感器连接。

下一步只能在 MOVE 确认、完成消息、最新空闲状态和预期位置一致后执行，不能用预估 sleep 替代到位检查。每步有按理想运动时间加容差计算的超时，并有可配置上限；等待动作不阻塞事件循环。界面显示运行行、当前阶段、已完成步数和中止原因。

第一版提供运行、中止，不提供运动中暂停和继续。中止、通信故障、控制器故障、到位不匹配或运动超时均撤销后续步骤，发送 STOP，尽力结束写盘；不能自动重试移动、自动恢复或自动回零。

运行期间切换窗口不打断已经明确启动的自动函数，但必须结束手动点动。关闭窗口则中止自动函数。函数完成保持当前位置，不隐含回零动作。

## 9. 磁数据录制与兼容格式

传感器数据输入沿用 t_us,Bx_uT,By_uT,Bz_uT 原始磁场协议，传感器串口与电机独立。录制前需要用户完成有效的静止基线校准；空载状态由用户保证，不自动移动设备寻找空载。

手动区提供开始采集、结束保存。手动录制可以包含点动、定距、静止和函数；普通“运行”不改变既有手动录制的开始/结束边界。“运行并采集”要求当前无录制，拥有本次记录，在函数完成或中止后结束保存；执行中不允许手动结束它。中止或故障会结束所有活动记录并保留已写入数据。

录制时传感器断流、控制器状态失效或写盘失败，应请求停止当前运动并结束录制。仅显示曲线、未录制时，传感器掉线不打断独立的电机运动。“结束保存”正常结束手动录制，不等于停止电机；停止全部会同时中止运动和结束录制。

每次录制创建唯一目录，输出 sensor.csv。列数、名称和顺序严格如下，保持原 CSV 的 UTF-8 BOM 编码：

```text
seq,sensor_t_us,device_time_unwrapped_us,device_clock_segment,sensor_t_s,host_rx_ns,host_elapsed_s,stage,motor_x_pulses,motor_z_pulses,motor_target_x_pulses,motor_target_z_pulses,motor_busy,motor_phase,motor_fault,Bx_uT,By_uT,Bz_uT,dBx_uT,dBy_uT,dBz_uT,sample_valid,invalid_reason
```

保留原始 B、dB=B-B0、设备时钟分段/回绕、主机单调接收时间和质量标记语义。解析失败计数；可解析的异常尖峰标记而不删除。复用原质量算法，允许保留一帧待下一帧确认后写入。周期性写盘，不只在结束时集中导出。

stage 沿用“当前采集阶段”的含义，但值反映新工作台：manual_idle、manual_jog_x、manual_jog_z、manual_move_x、manual_move_z 或稳定的 step_001、step_002 等动作编号。旧脚本的阶段名称不再作为必需的固定枚举。完整流程、每步对应关系、基线、结果和中止原因写入辅助 metadata.json；有需要时可另存事件日志，不改变 CSV 列。记录附带的配置快照用于解释当次坐标和动作，不能在后续加载时自动重设设备。

磁场和软件位置没有硬件同步；设备时钟分段不能跨复位当作连续时钟。CSV 不追加平滑、重采样或编码器反馈等未经实现的数据。

## 10. 控制结构与连接

界面 → 统一运动调度器 → XZ1 串口 → ESP32。手动点动、定距、动作函数只能有一个运动占用者。传感器采集 → 有界缓存 → CSV 写盘服务，曲线独立降频刷新。

串口通信和采样使用独立工作线程，写盘使用专用写入服务；界面主线程不做阻塞等待。电机串口只有一个所有者，后台持续 PING；GUI 点动续约使用独立的输入存活租约，禁止工作线程在 GUI 停滞后无限自行续发 JKEEP。界面停止指令优先于排队动作，清空未执行运动。控制器状态年龄、串口错误和写入队列积压须可检测。

根据源码握手检查 XZ1、jog_continuous、move_accel 等能力。板上固件是否匹配需实测握手，不因源码存在就宣称已刷入。连接成功不自动使能、不设零、不运动。Linux 枚举设备并支持稳定串口路径，检查权限、占用和同设备别名。

## 11. 行程边界

现有固件没有物理行程限位、原点搜索及编码器位置反馈。工作台可提供可配置的工作坐标范围，运行前检查动作终点，点动接近边界时提前减速；只能称软件边界提醒和保护，不能替代实物限位或独立急停。

软件边界与当前零点绑定：重新设零后不能沿用旧坐标范围，需重新确认/换算。未配置边界时不得显示“行程保护已开启”。实际行程、方向、换算和允许速度留待上机标定，不虚构数值。

## 12. 验收和后续阶段

离线检查：键盘自动重复、松键/失焦停止、鼠标键盘互斥、定距一次执行、数值换算、设零条件、绝对与相对动作、步骤到位验证、等待非阻塞、停止清队列、不同失败中止、流程保存加载、录制边界、CSV 表头与每列意义、基线/尖峰及写盘失败。

模拟模式不得打开实物串口；模拟数据明确标注，不混作真实采集。现有演示器缺少真实链路心跳等完整模型，需要相应串口替身检查，不把理想运动模拟当作机械证明。

上机验收：先核对方向和脉冲换算，低速短程验证 X/Z 点动与定距；核对松键制动距离和失焦行为；运行用户编辑的短流程；比较真实采集 CSV 与原格式。最后填写实际行程/速度范围，不未经标定就执行大行程示例。

用户审查本设计后，下一阶段再制定实施计划。界面细节、模块命名和线程内部实现可由实现者决定；不得擅自改变用户已确认的键盘操作、动作表编辑方式和 CSV 格式。
