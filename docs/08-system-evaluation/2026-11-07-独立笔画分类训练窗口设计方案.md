# 独立笔画分类训练窗口设计方案

当前交付为设计，尚未创建程序代码或启动训练。用户已选择独立窗口；本文把已审阅的完整研究方案变成可重复使用的训练工具，等待对本设计的确认。

## 1. 目标与范围

新建一个可独立启动的笔画分类训练程序。用户可以自己导入实验、确认标签、检查质量、启动训练、查看图表、保存模型，并用冻结后的新数据验收或识别单笔。

研究方法以同目录《2026-11-07-磁响应笔画分类完整训练方案与覆盖审查.md》为准，不重新缩减为A1单模态。幅值、磁向量相对方向、早期／晚期融合、导数对照、分组开发及鲁棒性试验均有明确入口或执行状态。

程序完全离线，不连接机械臂或磁传感器，不修改路径编辑器、机器人配置和原始归档。现有模型与历史报告保留原样。每次训练产生一个新版本目录。

本期不做实时采集／自动起止检测、图片识别、神经网络或未知类别拒识。

## 2. 当前实现中需要替换的固定假设

现有outputs目录里的分析脚本固定使用001～010，固定项目绝对路径、五笔身份和输出位置，适合复现上一轮，不适合作为长期训练入口。

新工具改为：

- 数据从用户选定文件／项目清单读取，不自动采用“最近十个”或根据目录排序决定样本。
- 类别、标签映射、边界协议、分组、研究配置均保存到项目文件。
- 训练核、表示、融合和验证流程由版本化方案配置决定。
- 训练和预测调用相同预处理／模型包，避免两份计算定义漂移。
- 数据质量异常作为可读诊断展示，不以assert报错结束整个窗口。
- 不从outputs旧脚本或临时虚拟环境导入核心逻辑；可以复用经过验证的数值定义，迁移后须重放旧A1基线。

## 3. 使用流程与窗口布局

```text
笔画分类训练工具    项目：随机实验研究    类别：五类    [打开项目] [保存项目]
┌────────────────┬─────────────────────────────────────────┐
│ 数据集         │ 当前页面的列表／参数／图表               │
│ 配置与训练     │                                         │
│ 训练结果       │                                         │
│ 模型与验收     │                                         │
│ 单笔识别       │                                         │
├────────────────┴─────────────────────────────────────────┤
│ 状态：就绪／审计／训练／取消／失败／完成     进度与简短日志 │
└──────────────────────────────────────────────────────────┘
```

主操作顺序：**导入 → 审计 → 训练 → 查看结果 → 冻结模型 → 验收新批次／单笔识别**。

日常页只展示用户需要做的选择。C/gamma网格、方向mask、分数校准和参考窗细节放在“高级训练设置”，并能恢复到已版本化的完整研究方案。

### 3.1 数据集页

支持导入：

1. 一份或多份`.brushrun`归档，首期主要入口。
2. 包含sensor.csv、control.jsonl和运行清单的原始实验目录。
3. 单笔原始CSV及配套样本说明，供独立采集记录使用；缺少边界、标签或时间时不猜测补齐。

导入后显示：是否完成采集、run_id、来源、每类笔数、session/batch、标签状态、基础质量、方向可用率和数据角色。项目可以选择五类或七类，但缺少横／竖时不得显示“七类数据已齐”。

标签来自经确认的采集身份映射；不能仅凭文件名或“这是第几笔”对任意文件自动贴标签。对现有永字可提供一个明确名称的映射模板，展示stroke_id对应关系，由用户确认一次后保存。未知身份保持“待标注”。模型不读取这些身份字段作为特征。

同一run的全部笔画共用数据角色。通过run_id、传感器成员哈希及来源关系识别复制归档；同源记录不能一份进开发、一份进验收。相同run_id但内容／标签冲突时停止该记录导入并给出冲突，不任意取一份。

数据角色分为“开发数据”“标准参照”“冻结后独立验收”。已用于训练／开发的记录不能通过改名重新登记为独立验收。历史十次数据的已知开发身份可从旧清单只读导入；系统同时保留用户声明与工具实际使用历史，不能声称能自动知道所有外部人工查看行为。

### 3.2 数据审计和预览

在训练前执行基础检查：有效状态、类别覆盖、时钟／seq、缺口、baseline切换、完整边界、滤波预热、真实参考／fallback及方向有效性。

结果按三层展示：

- 运行问题：少笔、边界不全、来源冲突等。
- 笔画问题：缺失磁分量、时间断点、参考无效等。
- 分支问题：幅值合格但方向／锚点不足，或某融合缺少分组等。

点选一笔可看原始幅值、EMA、参考窗、书写窗，以及磁方向和有效mask；可在实际时间与归一化时间之间切换。开发数据的人工边界修订需记录理由及新版本，不覆盖原日志；模型或验收冻结后不能一边看错误一边移动边界继续使用同一测试身份。

基础不合格样本不进入正式训练；分支不可用不得静默删样本。训练前显示可用样本数、每类支持数、各分组覆盖，以及不能执行的具体模型分支。

### 3.3 配置与训练页

默认配置为“完整研究方案v2”，包括：

| 部分 | 默认纳入／条件 |
|---|---|
| 幅值表示 | A0、A1、A2、A4；A3按参考响应／增益证据条件开启 |
| 磁方向 | D1、D2、D3；D0诊断；5µT屏蔽及有效性规则 |
| 模型族 | F0、F1、F2、F3、F4，含训练侧选择的参数与权重 |
| 主分类器 | linear与RBF-SVC；LinearSVC辅助对照 |
| 验证 | 固定整次实验留一验证（leave-one-run-out）：十次实验每轮九次训练、一次测试，共十轮；同次七笔必须同侧。参数选择只在当轮训练实验内进行，不提供session/batch验证模式切换 |
| 对照 | 原实测、±100/200/300µT、坐标旋转、位置控制、多数类 |
| 产物 | 全部指标／预测、特征与mask、图表、模型包、来源哈希 |

保留“幅值基线复现”和“自定义”配置，但它们与完整方案明确区分，报告自动注明未执行分支。选择自定义后保存为新的方案版本，不能继续显示“完整方案全部完成”。

每项具有可追踪状态：待执行、完成、条件不满足、用户关闭、失败、取消；记录原因、所用样本、证据路径。A3条件缺失、七类缺类、F3校准组不足等不能被程序自动换成简化方法而不告知用户。

参数来自完整研究设计的初值：EMA=0.3、K=128、方向阈值5µT；C/gamma、早期λ及晚期权重按既定训练侧候选网格。参考协议、mask处理和方向锚点随配置保存。修改会使旧缓存失效，不能混用不同版本特征。

点击“训练前检查”后展示：冻结输入清单、任务范围、可执行分支、预计折数／候选数量。耗时只在有实测依据时估计，不伪造剩余时间。检查通过后可“开始训练”，不再要求用户重复批准每个模型。

训练状态显示阶段、当前模型族、当前折、已完成任务、日志和取消按钮。完成后的结果标题区分“开发回测”“分组外层评价”和“独立验收”。旧50笔即使重复训练，也一直保留开发身份。

### 3.4 训练结果页

至少提供以下视图：

- 模型对比表：Macro-F1、Balanced Accuracy、Accuracy、每类支持、方向覆盖、完成状态。
- 混淆矩阵、各类别precision/recall/F1、逐run/session表现。
- 逐笔预测表：真实／预测类别、分组、参考模式、模型版本、是否正确。
- 单样本图：幅值、方向、有效区、各分支判别分数、误分类与训练侧参考曲线。
- 鲁棒性页：偏移／旋转结果及预测改变；标注数学试验性质。
- 覆盖审计：原44项方法要求的执行、调整、条件不足及证据。

比较幅值与融合时锁定同一队列和划分，同时显示不可评估比例／回退结果。不能让“更少但容易的样本”悄悄变成更高识别率。

用户可浏览和导出候选模型，但“推荐模型”按冻结的训练侧规则产生，不以查看验收集后点击另一个模型来刷新“最终成绩”。判别分数不标成概率。

### 3.5 模型与独立验收页

“保存候选模型”与“冻结待验收模型”分开。冻结内容包含模型、数据／方案／代码版本、标签、处理链、比较基线、质量规则和验收范围。

新独立验收记录在模型冻结后导入；核对来源重叠、类别及基础质量后，使用冻结模型评价，不调用fit或重新调参。结果单独保存。所有预登记代表模型可以按同一清单一次评价，主模型／基线须在查看成绩前指定。

软件无法阻止用户在外部反复查看同一数据，因此展示并保存每次验收历史；同一数据已被查看后再用于新版本调试，自动提醒其身份变为开发材料。新的独立证据需要新的数据集，不能在界面里靠“重置成绩”制造。

模型冻结后任何数据／参数／边界修改都创建新版本，不能原地修改已冻结包。现有2026-11-06模型只读可查看，不能覆盖。

### 3.6 单笔识别页

选择一个已保存模型，导入一笔原始磁CSV或从完整归档中选一个已标定边界的笔画；也支持严格匹配模型schema的已处理特征。

展示输入曲线、方向有效性、预测类别和判别分数。识别无需输入真实标签；可在预测保存后再填写真实类别作人工核验。若样本已用于该模型训练，则显示“训练样本演示”，不作为新测试成绩。

原始输入需足够连续写前采样或等价EMA状态。少模态或方向不足时，仅在该模型包明确保存了幅值回退规则时才回退，并显示实际采用的分支；否则报告无法按该模型定义识别，不能静默换算法。

## 4. 程序结构建议

用户只需一个可启动入口；内部拆分数值引擎，避免把训练、窗口和报告挤成一个大文件。

```text
scripts/train_stroke_classifier.py          独立窗口启动入口
src/brushbot/stroke_classification/
  project.py                              项目／数据／方案schema和版本
  data_io.py                              归档、目录、CSV导入及去重
  audit.py                                边界、采样、参考、方向质量审计
  preprocessing.py                        连续EMA、参考、τ、mask
  representations.py                      A/D特征与注册表
  models.py                               单模态、早期／晚期融合和导数
  validation.py                           分组、内层选择、对照和验收
  jobs.py                                 训练任务、状态和检查点
  model_bundle.py                         保存／加载／统一预测
  reporting.py                            CSV、JSON、PNG/SVG、HTML
  ui/                                     独立窗口各页面
```

具体拆文件粒度可在实施计划中调整，但数据处理与模型引擎必须独立于Qt和机器人控制模块。训练程序不能为了读取数据而加载机械臂连接或执行器。

沿用项目已有PyQt5；数值使用NumPy/SciPy/scikit-learn，科学图用Matplotlib。训练依赖使用独立环境／清单管理，部署时检测Qt和训练依赖，不在点“训练”时自行联网安装。

保留同一引擎的无界面调用入口供测试和复现；这不要求用户日常敲命令，也不再维护一套不同的CLI算法。

## 5. 训练进程、取消和恢复

窗口主进程只管理界面和轻量任务；训练在独立工作进程执行，通过结构化事件返回进度和结果，避免长时间模型搜索阻塞界面。开发与独立验收是不同job类型，验收路径不得调用训练接口。

每次job目录唯一，不复用旧模型文件名覆盖其他job。关键结果采用临时文件完成后原子写入；只有全部必要模型、元数据和校验通过才标记成功。

取消时停止工作进程，保留已完成折的审计和检查点，状态记取消；半成品不显示为成功模型。恢复仅限输入哈希、展开后的配置、代码版本、环境和种子均匹配的任务；不匹配时新建训练任务。首次实现若不能安全恢复某阶段，应明确从该完整阶段重新执行，不冒称逐步无损续训。

用户在训练中改变数据选择或设置，只影响新job。运行中job始终使用冻结快照；不能让当前界面改动悄悄改变已经开始的搜索。

## 6. 保存格式与输出位置

```text
outputs/stroke_classifier/<项目ID>/
  project.json
  dataset_manifest.json
  jobs/<时间戳-任务ID>/
    resolved_config.json
    data_manifest.json / sample_audit.csv / excluded_samples.csv
    coverage.json / progress.json / events.jsonl
    features/ / splits.json / predictions.csv / metrics.json
    models/ / figures/ / report.html / report.md
    artifact_manifest.json
```

模型包是完整处理链，不只是一个SVC：保存特征schema、滤波与参考模式、标签、各模态缩放器、方向mask配置、校准／分数尺度器、融合权重、回退策略和依赖版本。原始数据通过只读路径和哈希引用；是否导出数据副本由用户选择，不默认复制全部实验。

可导出包含模型、说明、报告和校验清单的成果包。不同类数、不同参考协议或特征版本不兼容时拒绝混用。

## 7. 与完整研究方案的对应和数据门槛

本工具是完整研究方案的执行载体，不重新定义研究结论。保留原44项覆盖表，并为每个job写出机器可读执行状态。

- 现有50笔可开发五类完整方法，历史身份保留。
- 数据不足时，只限制相应分支或结论；例如session缺失不能声称跨session，横竖缺失不能声称七类，F3分组不足不能退回逐笔随机校准。
- 真实参考窗和fallback分别形成协议／模型，不能静默混合。
- A3等条件项检查后明确完成或暂缓；不会通过“默认关闭”把原方案遗忘。
- 预登记方向增益判据和数学稳健性性质保留；不保证融合一定优于幅值。
- 当必需分支失败／缺条件时，任务结果标为“部分完成／条件不足”，不显示“完整方案全部通过”。

## 8. 实施顺序与验收

分阶段实现，但默认完整方案的覆盖状态从第一版项目schema就保留：

1. 数据／项目格式与纯数值引擎：导入、审计、A/D、分组和模型包。
2. 完整训练引擎：F0—F4、训练侧参数开发、对照和覆盖清单。
3. 独立窗口：数据、配置、训练进度与结果浏览。
4. 冻结、独立验收、单笔识别及导出。

不是第一阶段只做幅值就交付“完整训练工具”；功能不足的阶段标为开发中，最终验收要覆盖全部约定页面和合理方法分支。

关键验证：

- 从现有10次归档导入50笔，来源和标签可追溯；重复归档不会形成泄漏。
- A1能复现旧特征；D分支通过角度跳变、低幅、旋转、mask和时间一致性检查。
- 每折缩放、参数选择及晚期分数处理只使用训练侧；已保存模型可重放留出预测。
- 切换结果表／样本时，图、预测、真实标签、分数与同一模型版本一致。
- 训练期间窗口可操作，取消后不会把半成品显示为成功，重复运行不会覆盖旧产物。
- 冻结后的验收不触发fit，已有开发记录不能冒充新的独立验收。
- 单笔原始数据和已处理特征两条输入途径得到同定义预测；真实标签不参与预测。
- 控制脚本、原始归档和旧模型哈希保持不变。

确认本设计后再编写实施计划和代码。当前不自动开始训练或新数据采集。

## 9. 设计审查记录

用户已明确选择独立可视化窗口。独立审查代理依据本设计及完整研究方案进行了只读可实施性检查，未发现需要先补问才能制定实施计划的实质性遗漏。当前只新增设计文档，未创建程序代码、启动训练或修改旧模型。
