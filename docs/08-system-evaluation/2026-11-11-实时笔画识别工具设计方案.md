# 实时磁响应笔画识别工具设计稿

日期：2026-11-11（Asia/Shanghai）

状态：最终审查稿，等待用户审查；尚未开始脚本实现。

关联现有入口：`scripts/run_stroke_classifier.sh`、`scripts/train_stroke_classifier.py`。

## 1. 目标与已经确认的行为

制作一个独立启动的 Python 桌面识别工具，连接现有磁响应传感器，并直接使用现有分类工作台训练出的模型。

用户已确认：

1. 每隔固定时间，对“本次落笔开始至当前时刻”的全部数据识别一次；建议默认间隔为 100ms（10Hz），允许调整。
2. 中途预测用于观察和展示，允许分类错误及类别跳变。
3. 确认提笔后结束这一笔，用完整笔画独立复判并锁定最终结果；中途预测标签和分数不参与最终投票。
4. 再次落笔创建新笔画，上一笔数据不能混入新笔。
5. 直接读取训练工具的模型历史，选择已有模型即可使用，同时保留导入模型功能。
6. 模型格式沿用 `run_stroke_classifier.sh` 生成的成果；当前阶段只审查方案。

本稿的工程建议：采用 Python + PyQt5 + pyqtgraph，独立窗口、独立启动器，复用当前串口、模型库、特征提取及预测代码。首版以独立传感器输入工作，不依赖机械臂提供笔画边界；实际使用者和书写方式尚未确定，不将现有实验成绩解释为自由手写准确率。

成功标准有两层：软件上，同一模型、连续传感器记录及笔画边界必须产生与现有离线识别一致的最终结果；实际识别效果上，另用真实书写检查自动分笔及完整笔画准确率。用户尚未规定数值准确率目标，不能以中途展示流畅代替整笔效果验收。

## 2. 采用的方案及取舍

|方案|行为与取舍|决定|
|---|---|---|
|累计片段定时识别，提笔整笔复判|保留当前笔的全部已写信息；直接复用整笔模型；中途预测可能变化，最终计算独立|用户已确认采用|
|只识别最近一段滑动窗口|计算规模容易限制，但起笔信息会离开窗口，输入与现有整笔特征不同|本轮不采用|
|专门训练早期识别模型，并融合中途判断|需要新的训练与评估策略，适合追求中途准确率|本轮不采用；用户重点是展示中途判断|

首版的功能边界为：共享模型历史、导入现有成果包、串口采集、分笔、实时预测、最终识别、记录保存及开发验收所需回放。训练、自动选模型、多模型同时比较、完整汉字识别、从磁响应恢复纸面轨迹、在线更新模型均留在本轮范围之外。首版不新增面向用户的完整回放编辑器。

## 3. 模型历史与导入

### 3.1 共享同一模型库

- 默认模型库为项目根目录下的 `outputs/stroke_classifier`，从入口文件位置解析，避免受启动时工作目录影响。
- 复用 `ModelStore`，读取相同 `tasks/<task_id>/task.json` 及 `models/<model_id>/bundle.joblib`，不另外维护一份模型历史副本。
- 支持与训练入口相同的 `--store` 参数，并提供目录选择。训练工具使用自定义路径时，两边需要指向同一目录。
- 历史按“训练记录 → 具体子模型”展示，延续收藏优先、时间倒序的排序；保留已选模型，刷新不能自动替换选择。
- 展示训练记录名、时间、子模型名、F0～F4 类型、类别范围及已有评价指标。指标标明为原训练记录的评估结果，不标成实时准确率。
- 只列出当前库可用的已完成/部分完成记录中的有效子模型；训练中间文件、删除记录及损坏模型不能被误加载。
- 窗口启动、手动点击刷新及导入成功后刷新；后台每 2 秒检查历史元数据变化。日常轮询不重复读取整个模型文件。
- 自动刷新只同步列表、名称、收藏和可用状态，不向训练记录写入实时识别结果。

### 3.2 模型兼容性

加载沿用现有 `ModelStore.load_bundle` 的文件完整性校验，并将现有导入/预测链的格式版本和特征配置检查前置到开始识别之前。使用成果包中的 `labels`、`feature_config`、分类器、标准化器和相关组件。支持当前工作台保存的 F0～F4 模型；已经通过现有适配器登记到模型历史的五类旧模型也按其保存类别工作。

类别由所选模型决定。五类模型只能输出自身五类，不能把其输出描述为七类识别，也不根据模型分数推断可靠的“未知笔画”类别。未标注真实类别的现场数据不显示准确率。

导入入口接收工作台导出的 ZIP 成果包，复用 `ModelStore.import_package`。导入到当前共享模型库后，两边刷新即可看到。相同内容复用已有记录；相同标识但内容冲突时拒绝覆盖。第一版不开放脱离配套历史元数据的任意裸 `joblib`、`pt` 或 `onnx` 加载。

### 3.3 模型的生效时点

- 启动时恢复上次模型的选择信息，经重新校验加载后显示“已就绪”；设备连接和开始识别由用户触发。
- 每笔落笔时固定该笔的模型标识、文件哈希、预处理配置和分笔配置。
- 书写中选择另一模型时显示“下一笔使用”，当前笔仍使用原模型完成最终识别。
- 新模型必须完成加载及所需预处理准备后才能开始新笔识别；必要时在本笔结束后短暂停在“模型准备中”，采集和记录继续。
- 若模型使用不同预处理参数，从保留的原始数据初始化对应处理状态，不继承另一模型的滤波状态。
- 外部删除当前模型后，已开始的笔画和已提交的最终任务仍使用内存中的冻结模型完成；新笔识别暂停并提示重新选择。

## 4. 传感器采集与处理一致性

复用 `monitor.sources.SerialSource.read_frames()` 获取原生帧，默认串口波特率沿用 115200，并可选择串口及波特率。每个有效帧保留设备 `sensor_t_us`、主机接收时间、原始三轴磁场；采集端补充本会话递增 `seq`、基线标识、差值通道和质量信息。

这里的 `seq` 是本机接收记录序号，不能声称它能发现固件未发送的全部漏采。连续性同时依据设备时间戳、串口解析诊断和数据有效性判断。时间计算处理设备时钟回绕，不依赖 `SerialSource.info` 中的标称采样率。

使用原始帧流进行分笔和推理，不能把展示页面降低频率后的快照作为识别数据源。

连接后先采集空载基线，取得 `ΔB`，再满足模型配置要求的连续有效预热，当前模型要求至少 100 个写前采样。基线测量期间只预览，不接纳新笔。基线在识别期间保持固定；重新取基线前停止接纳新笔，当前未完成笔标为中断。

连续 EMA、重采样、前 10% 参考计算、方向锚点及覆盖要求均遵从模型保存的处理规则。EMA 随原生数据连续运行，每次预测和每次落笔都不能把它从零重新启动。每次预测对对应片段重新计算归一化时间及特征。

分笔用的阈值逻辑与分类特征处理分别管理。此前关于“悬空残值二三十”及其用途的推测已被用户撤回，本稿不据此设计自适应扣底噪算法。

## 5. 自动分笔与边界定义

### 5.1 判据与初次设置

首版采用基于 `hypot(ΔBx, ΔBy)` 的可调落笔阈值、提笔阈值及持续时间确认，满足落笔阈值大于提笔阈值。磁响应阈值仅是接触判据，不能直接当作独立物理触纸测量。

首次使用在实时预览中观察悬空及轻触信号，设置并保存两个阈值，然后开始识别。阈值尚未配置时只允许预览。已有练习工具的固定阈值不能未经验证直接作为这套工具的有效标定。

建议初始落笔确认时间为 40ms、提笔确认时间为 120ms，均可调；它们是待实测调节的工程起点，与 100ms 推理间隔相互独立。配置调整从下一笔生效。

短于提笔确认时间的离纸间隔可能被视为同一笔中的波动。需要根据实际连续书写速度调节确认时间，在抗抖动与区分快速相邻两笔之间取得可验证的取舍；不能同时承诺过滤所有短波动并识别所有短促离纸。

### 5.2 状态与数据边界

|状态|动作及转移|
|---|---|
|未就绪|等待连接、基线、预热、模型和阈值配置完成|
|等待落笔|等待信号达到落笔阈值，保存候选起点|
|确认落笔|超过落笔阈值持续足够时间则创建本笔；否则取消候选。正式起点回溯至本次持续超阈值的首帧|
|正在书写|累计原生数据，按推理间隔提交当前片段；保持接触的笔内停顿不结束本笔|
|确认提笔|信号低于提笔阈值时保存候选终点；若恢复至提笔阈值以上则取消提笔候选，继续本笔|
|结束本笔|低于提笔阈值持续足够时间后，终点取持续低阈值片段之前的最后一帧，提交完整笔画快照，立即回到等待落笔|

确认提笔期间继续接收原始帧，但暂停该笔的新中途预测，保留最近一次显示并标记“确认提笔”。若提笔候选取消，其间原始帧自然归入仍在进行的当前笔；若提笔成立，确认等待期间的悬空帧不进入最终片段。

每笔具有唯一 `stroke_id`。边界事件保存候选时刻、确认时刻及采用的起止 `seq`，便于检查确认延迟。过短或不满足模型输入条件的接触仍保留记录，标明无法识别原因，不伪造正常最终类别。

停止识别、主动断开、断流、设备时钟异常、无效数据或基线切换不能被当成正常提笔；当前受影响笔画保存为中断/无效。恢复后重新满足预热，并确认处于离纸状态再接纳下一笔，避免从一笔中间重新开始。

这套边界与训练数据中 `measure_N` 事件边界可能存在差异。起收笔及轻触信号是否会被阈值误裁切，是硬件验收重点；必要时调整分笔判据并重新验证，不能承诺只靠调用相同分类器就达到已有离线成绩。

## 6. 定时预测与最终复判

### 6.1 定时预测

- 默认 100ms 一次，可选 200ms、500ms，并允许在高级设置中调整。
- 每次取不可变快照 `[本笔起点, 当前最新有效帧]`，复用现有特征提取及 `predict_strokes` 的冻结模型预测。
- 新采样不足、方向锚点不足或方向覆盖未达该模型要求时，显示具体等待原因；不自动改用另一模型。
- 输出当前类别和原始判别分数；类别变化立即显示，不采用连续多次一致才展示的类别防抖，不对类别做时间投票。
- 中途计算可反复修改本笔的展示结果，但不能修改模型、原始记录或已经锁定的历史结果。

### 6.2 最终复判

确认提笔后，以已经固定的起止位置提取完整笔画，按同一冻结模型独立调用完整处理链。中途输出不作为此调用的特征、权重或先验。

结束采集即将该笔放入历史列表，先显示“最终识别中”；计算完成后原子地写入最终类别、分数、耗时及模型标识，状态变为“已锁定”。即使最终结果与上一帧中途预测不同，也如实展示最终结果。

最终输入未满足质量/方向条件时显示“无法识别”和原因。一次最终任务只提交一次正式结果；锁定后，任何迟到的中途结果都不得覆盖它。

### 6.3 调度与容量

采集、推理和 UI 更新分别执行。固定频率指提交预测请求的目标节拍，不将其写成未经实测的硬实时保证。

中途推理最多保留一个正在计算及一个最新待计算快照；过期的待计算快照可被新快照替换。负载不足以达到设定频率时，显示实际完成频率和处理延迟，建议降低频率，不积压旧画面。

最终任务优先于待执行中途任务，按笔画顺序处理。当前正在计算的中途任务可以正常结束，但其过期输出应被过滤。下一笔的原始采集和分笔不等待上一笔最终计算。

每个结果关联会话代次、模型代次、笔画编号及快照结束位置；窗口只接纳符合当前状态的结果。为避免长笔或持久过载造成无界内存，原始会话数据持续写盘；当前笔时长与最终待处理任务设置明确上限，具体上限由实现者按测量确定并写入会话配置。超过上限时暂停接纳新识别并明确记录原因，已接纳的最终任务不能静默丢弃。

中途输出仅更新匹配的当前笔。最终输出按对应历史笔画冻结的模型与会话归属校验，不能因为当前界面已经切换到下一笔或另一模型，就丢弃上一笔合法的最终结果。

## 7. 窗口与操作流程

建议独立暗色窗口，沿用现有训练工具字体、配色和常用控件。下面是功能位置示意，具体尺寸和视觉细节由实现阶段决定。

```text
[模型历史/刷新/导入]   当前模型、类别范围、原评估指标
[串口/连接/基线]      [开始/停止]  推理间隔  状态

实时磁响应曲线与分笔标记     当前第 N 笔
                           已写时长 / 暂定类别
                           各类判别分数 / 实际更新频率

本笔类别变化记录：时间 → 当时的类别
完成历史：笔画编号 / 最终类别 / 时长 / 状态 / 模型
```

实时曲线至少包含 `ΔBx`、`ΔBy` 及磁幅值，可切换通道；图中标出当前笔起点、候选提笔和最终边界。显示数据可降低绘图频率，但原始采集及模型输入不降采样。

“当前暂定类别”和“上一笔最终结果”保持不同区域，新的落笔不会清除上一笔最终结果。各类分数标为“SVM 判别分数”，不加百分号或概率称谓。

常规使用流程为：选择历史模型 → 连接传感器 → 空载取基线与预热 → 首次确认分笔阈值 → 开始识别 → 连续书写 → 停止并查看保存位置。启动时恢复串口、模型库、上次模型、推理间隔及阈值设置，但不自动打开串口或开始识别。

## 8. 会话记录与复现

建议单独保存到 `outputs/stroke_recognition/sessions/<会话ID>/`，与训练模型库分开，避免实时任务修改训练结果。

|记录|主要内容|
|---|---|
|`session.json`|会话状态、起止时间、设备参数、软件版本、模型清单与哈希、完整处理/分笔配置|
|`sensor.csv`|连续原生帧、设备和主机时间、会话序号、原始及基线差值通道、有效性及基线标识|
|`events.jsonl`|连接、基线、落笔/提笔候选与确认、开始/停止、模型切换、异常及配置生效事件|
|`predictions.jsonl`|中途及最终预测的笔画编号、数据终点、类别、分数、耗时和可识别性原因|
|`strokes.csv`|每笔起止位置、边界确认时刻、状态、时长、最终类别及模型哈希|
|模型快照|本会话实际使用的模型文件和必要元数据，按哈希去重；原模型被改名或删除后仍可复现|

记录持续追加，已完成笔及时落盘；正常退出时完成会话汇总。文件写入失败应显示明确错误并停止接纳新识别，不能仍显示“已保存”。异常退出留下可辨识的未完成会话。

会话使用一个模型开始接纳笔画之前，先完成该模型快照及元数据保存；同会话重复使用同一哈希时复用快照。这样，模型在原库被删除后，当前任务仍能完成并保留可复现来源。

开发回放使用同一原生数据、模型快照和起止边界，检查中途展示、最终结果和断流行为。该能力用于验收及排查，不在首版扩展为额外的复杂编辑界面。

## 9. 代码组织建议与复用点

以下均为待实现的文件建议，本次不创建这些脚本：

- `scripts/run_stroke_recognizer.sh`：与训练入口相同的 Python 环境选择方式。
- `scripts/recognize_strokes_live.py`：命令行参数与桌面窗口入口，提供 `--store`、会话输出目录等参数。
- `src/brushbot/stroke_recognition/`：采集与会话核心、分笔状态机、推理调度、模型历史适配、窗口及记录保存。

现有复用点：`monitor/sources.py`（原始串口帧），`monitor/core.py`（基线及数据工具），`stroke_classification/store.py`（历史/导入/校验），`features.py`（处理规则），`predict.py` 与 `models.py`（冻结预测）。可以借鉴 `exhibition_monitor/pressure_practice.py` 的迟滞与持续时间机制，不直接搬用其 S/Z 练习状态机或未经验证的阈值。

实现者负责确定线程/进程方式、内部类划分、控件布局、缓存实现及容量限制；这些选择必须满足原生采集不阻塞、最终结果一致和任务不串笔的要求。首版不改写训练算法及既有模型格式。

## 10. 验收与实施顺序

用户批准设计后，再将本稿拆成实施计划，按以下顺序开发：模型历史及加载 → 采集与连续预处理 → 分笔 → 定时/最终推理调度 → 展示与保存 → 回放及实机验收。

必要验收项目：

1. **模型库共享**：训练工具保存、重命名、收藏或删除记录后，识别列表正确刷新；刷新不切换当前笔模型；自定义 `--store` 生效；ZIP 导入正确处理重复及冲突。
2. **已有模型兼容**：用现有 F0～F4 成果进行加载和预测验证；适配后的五类模型保持五类范围；损坏或不兼容模型显示明确原因。
3. **最终结果一致**：对相同连续记录、相同模型和明确边界，与既有离线特征/预测比对，特征及分数在约定浮点容差内一致，最终标签一致。
4. **中途与最终独立**：改变中途推理频率、跳过中途任务或制造迟到输出，不能改变同一完整笔画的最终结果。
5. **分笔正确性**：覆盖阈值抖动、候选提笔取消、正常笔内停顿、快速连续两笔、短接触、长笔和恢复后的预热；确认等待不能截掉候选起笔，也不能将悬空确认段加到笔尾。
6. **并发与模型切换**：最终计算未完成时继续采集下一笔；旧会话和旧模型结果不覆盖新状态；最终队列不静默丢失记录。
7. **异常记录**：断线、坏帧、时钟异常、基线切换和写盘失败不伪装为正常提笔或保存成功。
8. **真实性能**：在实际运行设备上测量 10Hz 目标下的完成频率、预测耗时、提笔确认及最终锁定延迟；报告实测值和过载行为。
9. **真实整笔效果**：核对真实落笔/提笔与自动边界，记录完整笔画的类别结果；中途错分不作为失败条件。现有模型是否适合实际手写或新的书写方式，以该项实测为依据。

当前待用户审查的工程建议主要是：独立窗口、默认 10Hz、首次配置分笔阈值、共享模型库默认路径、实时会话自动保存，以及模型切换在下一笔生效。核心累计片段预测和提笔整笔复判流程已由用户确认。
