# 毛笔实验数据保存与复现

## 保存位置和文件格式

新实验默认保存到 `runs/毛笔实验数据`，每次成功实验一个文件夹，文件夹内只有一个 `.brushrun` 存档：

```text
runs/毛笔实验数据/
└── 横画测试_001/
    └── 横画测试_001.brushrun
```

只复制这个 `.brushrun` 文件即可保留当次数据，不需要带上原路径文件夹、标定文件、命名设置或整个实验库。文件内部使用 ZIP 容器，带格式版本和 SHA-256 完整性校验；正常使用不需要解压。

原有路径库和历史实验保持原位。手动导出的路径仍存放在 `runs/brush2/plans/interactive`。试写只在隐藏临时目录冻结当次输入，不搬动原路径，也不归档所有历史路径或项目源码。

## 日常使用

1. 编辑路径、磁目标、笔杆角度和速度，点击“试写”。预检后在终端确认执行。
2. 完整执行并回到等待位、采集和记录正常关闭后，生成单文件存档。
3. 在成功后的命名窗口中回车沿用默认名称；修改名称则为该名称自动分配编号。
4. 通过“文件 → 打开实验存档”选择 `.brushrun`，或从“实验记录”中选择“恢复到编辑器”。工具栏“打开”也支持选择 `.brushrun`。
5. 恢复后直接在主画板显示全部笔画、节点和试写范围，右侧参数同步恢复磁目标、姿态和速度；通过“当前笔画”切换编辑各笔。历史路径、磁目标与响应、执行姿态在“实验记录 → 查看数据”中查看，不会随编辑变化。
6. 恢复后可以继续编辑和试写；新的成功实验另存，不覆盖原存档。

默认名称沿用上一次成功实验设置的名称，编号例如 `横画测试_001`、`横画测试_002`。失败和取消不占用成功编号。关闭命名窗口保留已保存的默认名称。“实验记录 → 重命名”同步更新文件夹、存档文件名和内部名称，保留实验唯一 ID；历史重命名不改变下次实验的默认名称。

## 单文件内保存什么

- 当次编辑工作区：路径节点和密集几何、笔画顺序、试写范围、磁目标、笔杆角度、速度及节奏。
- 当次有效的前馈标定、现场设置、进出笔和反馈控制参数。配置值直接内嵌，原路径仅作来源说明。
- 原始磁传感器记录、控制记录、基线和事件，以及当次计算得到的磁目标跟踪指标。
- 原始目标计划和完整执行轨迹；启用实际 TCP 采集时同时保存实测位姿和采集质量信息。
- 实验名称、完成时间、唯一 ID、数据格式版本、程序指纹和依赖版本。

辨识、阶梯、接触等专用实验若没有可编辑的毛笔路径，仍保存其参数和实测数据，打开后显示历史曲线，不替换编辑器当前路径。

## 离线校验与指标重算

在项目目录运行以下命令，不会连接硬件；仅需要 Python 标准库：

```bash
python src/brushbot/experiments/reproduce.py '/任意位置/横画测试_001.brushrun'
```

命令先校验内部文件，再从记录的 `control.jsonl` 重算书写阶段的磁目标跟踪指标。结果应与存档中的 `analysis_summary.json` 一致。

也可通过命令打开编辑器：

```bash
.venv/bin/python scripts/edit_brush_path.py --open-experiment '/任意位置/横画测试_001.brushrun'
```

存档保证当次保存数据和参数的独立恢复。重编译仍使用当前程序；程序指纹可用于判断版本差异。再次实机试写的墨迹还受毛笔、纸面、含水量和设备状态影响。

## 中断、错误和临时数据

失败、Ctrl+C、设备错误、记录错误或实际 TCP 采集错误不生成成功存档；当次已有数据完整移动到 `runs/毛笔实验数据/临时失败实验/日期时间__会话ID/`，不会自动删除，也不占用成功编号。编辑器启动失败或执行前取消时，已生成的路径和日志也保留，并注明未执行。

每份失败目录包含：

- `README.md`：当次原始磁数据和控制、事件记录的相对路径导航。
- `failure.json`：原因、原始记录位置，以及异常堆栈（如有）。
- `run_result.json`：最终状态、进度和已有控制周期诊断（执行器返回结果时）。
- `console.log`：执行前后的终端输出。自动定位和实机执行期间恢复原始终端输出流，实时状态仍在终端显示，但不额外同步写入此文件；异常堆栈和最终诊断在执行结束后保存。
- `raw/`：当次已采集的原始磁数据、控制、事件、实际 TCP 和已有派生数据等。
- `plan/` 或 `inputs/`：当次路径和配置快照（对应入口提供时）。

强制退出或断电留下的记录先留在 `.临时`；下次启动时，已退出会话会被移动到上述失败目录，标注 `recovered_after_unclean_shutdown`，不删除。仍在运行的任务不会移动。原始 manifest 保持原样，可能仍显示 `running`，需结合失败说明判断。强制退出可能留下未完整刷盘的数据；程序不补造缺失帧。

解释器启动前的终端启动故障无法写入 Python 终端日志，可查看已保留的路径和失败说明。此前已被旧版清理的数据无法通过本次修改恢复。

执行已成功、但写入正式存档时发生磁盘错误的记录，会保留已校验的临时数据以便下次恢复，避免丢失成功实验。正式目录只在压缩、校验全部完成后出现。
