# 梯子实验：自动沾水与重取基线

本文把自动沾水方案和已勾选的实施记录合为一份，描述配置、轨迹、baseline 和软件接缝。数值随毛笔与现场配置变化；2026-09-21 文档中的五条路径不是固定项目要求。

## 动作与配置

每个选定测量访问前：起点抬至安全高度→水平移至杯位→原地下降→停留→原地抬起→高位返回测量起点→稳定→重取 baseline→下降到测量 Z。

`path.wetting` 定义 `every_paths`、`x_mm`、`y_mm`、`cup_rim_z_mm`、`safe_z_mm`、`dip_z_mm`、`dwell_s`、`settle_s`。入口脚本提供相应可编辑常量。关闭自动沾水时保持旧手动暂停流程；间隔超过路径数时仍应覆盖首条路径。

原设计案例为测量 X=-200→0 mm、杯位 (-300,500) mm、安全 Z=120 mm、杯沿 Z=100 mm、下探 Z=50 mm；仅用于追溯旧案例。真机实际值以当前配置和 run 安装快照为准。

## 轨迹约束

涉及杯区的 XY 平移均在配置的安全高度；下探和抬升只在杯位发生。安全高度高于杯沿与下探点，下探点低于杯沿；数值有限且处于工作空间内。完整轨迹继续接受步长、速度和加速度检查。末次测量后不额外增加一次沾水。

## Baseline 与分析

启动导航 baseline 供首次导航阶段处理传感器信号。到达自动重取标记时退出 Servo、取得新 baseline，再恢复后续轨迹；每个标记只消费一次，不进入 `WAIT_OPERATOR`。每条路径都沾水的 N 路批次通常有一份导航 baseline 和 N 份测量 baseline。改变频率后须按实际 effective_visit 关联。

正式测量分析使用 `measure_NN` 相位，沾水与移动数据仍保留作运行记录。baseline 超时、传感器故障与 Ctrl+C 遵循实际引擎的中止逻辑，文档不凭空承诺未知位姿下可以安全移动。

## 实现接缝与原验收记录

| 模块 | 职责与原验证点 |
|---|---|
| `experiments/config.py` | 校验 wetting 字段、频率、有限坐标、非负时长和高度关系 |
| `experiments/trajectory.py` | 编译 wet_* 相位、自动 baseline 标记和测量访问关系；验证杯区移动和末次边界 |
| `experiments/engine.py` | 消费自动标记一次、关联有效 baseline，同时保留旧手动暂停 |
| `scripts/run_ladder_experiment.py` | 将现场常量组装为配置 |
| 相关 ladder/engine/runner 测试 | 假设备验证到达 END_WAIT、相位/记录完整、无人工输入和旧流程兼容 |

原实施计划四项任务均记录为完成。这里保留的是当时的软件实施结论；现场效果取决于实际运行记录。原逐步测试命令与任务清单可从本轮备份恢复。
