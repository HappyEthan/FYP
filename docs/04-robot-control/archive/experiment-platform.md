## 磁触觉毛笔首轮实验平台：确认方案

来源版本：`2026-09-09-experiment-platform-design.md`。

> 2026-09-09 的历史设计。下文垂直姿态、候选接触高度和容差实验安排不作为当前梯子批次或正式对照的要求；当前研究与代码状态见根 `plan.md` 和项目交接。

日期：2026-09-09。依据：本会话用户逐项确认，并授权编写实施计划。本文是确认内容的书面归纳，不代表功能已实现或真机参数已获安全验证。

<a id="source-1-目标与边界"></a>
### 目标与边界

在现有 monitor 中选择实验 JSON，统一执行开环采集和 Z 闭环 StrokePlan，自动取基线、记录、抬笔，并提供独立返回起点入口。本轮不采集墨迹、不接相机、不训练模型、不修改 proposal。未授权本轮实现代码、运行设备或提交 Git。

<a id="source-1-已确认需求"></a>
### 已确认需求

1. 机械臂夹爪与笔视为固定装配。准备时指定夹爪宽度；实验、停止、退出及返回流程不自动松开，不逐拍发送夹紧指令。夹持可靠性、断电行为另行现场验证。
2. TCP 在笔杆与笔毛连接根部，自由笔毛长 40 mm；笔杆统一垂直纸面，取消此前 5° 前倾。垂直姿态需从实际 TCP/工作坐标系确认，不默认欧拉角全零。
3. 接触参考 TCP 高度暂取 40 mm，必须现场确认；物理 Z 向上为正，压深 d=接触参考高度−TCP 高度。正 Z 不是防碰撞保证。
4. 开环候选：X 行程 400 mm，TCP Z 从 40 降至 20 mm，Z 随 X 路程线性变化。X 速度候选 5、10、20 mm/s，每次只执行文件当前值，不自动执行三档。长度、Z 与速度可修改。
5. 开环是关闭 Z 控制的 StrokePlan 执行，不建立第二套运动引擎。记录磁响应用于选择磁目标和检查前馈关系；三档同时改变 X 和 Z 速度，不是单独的 X 速度因果实验。
6. 闭环首轮支持横、竖、圆；行笔段为恒定二维磁幅值目标 hypot(ΔBx,ΔBy)，原始三轴保留。磁目标由实测选择，不写虚构默认值。
7. 同条件先比较容差半宽 0 μT，再比较 5 μT；路径、速度、目标、前馈、滤波及增益保持一致。带内 P 误差项为零、积分不因该误差增加，但不突然清除已有补偿。
8. 用户编辑一个 JSON 文件，使用 _comment 记录其他候选速度。monitor 选择、预览、执行，不做实验参数编辑器。
9. monitor 直接输入起点 XY 与抬笔等待高度，运动使用相对此起点的平面路径。输入/加载不触发运动；运行中锁定输入并保存快照。
10. 每次实验在起点上方、笔毛悬空且保持实验姿态时自动取基线，合格后固定本次基线。自动记录前置静止、动作、抬笔及结束阶段；异常也保存已有数据。
11. 正常结束只在终点抬笔等待，不自动返回。点击“回到起点”时先抬笔再平移，停在起点上方；独立脚本与 monitor 共用返回逻辑。
12. 本期只评价信号跟踪、控制修正和运行可靠性，不声称墨迹改善。相机属于后续独立扩展。

<a id="source-1-接入方案及选择理由"></a>
### 接入方案及选择理由

选用“monitor 作为操作界面＋独立实验服务＋统一执行引擎”。不把机器人实时循环塞入 Qt 刷新回调；不另外建立只供采集的执行程序。与彻底重写 monitor 相比，复用现有显示与离线回放；与仅调用独立运动脚本相比，可统一自动录制、状态互锁及停止处理。

模块按串行依赖分三个验收阶段，均有无硬件测试：

- A：JSON 契约、轨迹、坐标、共享采样与记录；假后端可完整回放。
- B：独立执行器、机器人适配、二维控制与标定验证；假设备验证故障及控制行为。
- C：monitor 和返回脚本接入；先无硬件端到端，再另行授权现场验收。

<a id="source-1-坐标与参数边界"></a>
### 坐标与参数边界

实验 JSON 使用带单位后缀的 mm、mm/s、μT、s；进入执行层统一转换为 m、rad。JSON 中 Z 是根部 TCP 的工作坐标高度，不是已有 Stroke.z_ff 的正向压深。接触参考单独保存，禁止重复加减 40 mm。

起点来自 monitor；实验 JSON 不覆盖起点。安全配置独立于实验 JSON，包含已验证的工作空间、压深、速度/加速度、单拍变化、姿态、TCP/UCS 标识与变换、抬笔和停止约束。无安全配置仅可预览或假后端测试，不能执行真机。改变实验参数不会自动扩大安全范围。

ServoP 和点位运动必须使用同一有效 TCP/UCS。适配库中点位运动使用命名 TCP/UCS，而 ServoP 使用数值 tool_coord/user_coord；两者必须实测确认一致。不能仅在示教器命名 TCP 后沿用 ServoP 的零偏置默认值。

<a id="source-1-执行与故障"></a>
### 执行与故障

只有已到达配置起点上方并确认静止时才能“执行”；否则提示先“回到起点”，不暗中移动后取基线。基线失败保持等待/返回可重试状态，不开始行笔。

正常状态：就绪、静止基线、接近接触、行笔、终点抬笔、保存完成、终点等待。返回为独立动作，不能与实验同时执行。

普通停止请求先有界减速停止；确认状态、通信及抬笔路径有效后才允许受控抬笔。急停、失联、状态不可信时不自动撤退、返回或复位。软件停止不替代硬件急停；主机阻塞时的控制柜通信超时行为必须现场验收。

实验期间禁止切源、重取基线、手动开始/停止另一份录制；显示暂停只能暂停绘图，不停止采样、记录或控制。回放/合成源不允许驱动真机。

<a id="source-1-数据协议要求"></a>
### 数据协议要求

每次运行唯一 run_id，保存输入 JSON 原文与解析结果、起点/安全/标定/滤波快照、编译后的 StrokePlan 和阶段时间律、原始磁记录、控制逐拍记录、阶段事件及运行结论。命令位姿与实际位姿不同列；没有实际数据时留缺失并记录原因。

磁记录保留原始 B、ΔB、传感器原始时间戳、主机单调接收时间、质量与样本序号。不能将主机接收时间声称为硬件同步时间。旧 V0 文件仍兼容，新实验数据不静默混入其旧时间戳含义。

单一采样者负责串口，显示、控制与录制独立消费。显示可降采样；原始记录不可默默丢帧；队列溢出/写盘失败须中止并保留故障标志。基线期间先记录 B，取得 B0 后在元数据登记；之前 ΔB 可为空而不是伪造。

<a id="source-1-现场参数的处理"></a>
### 现场参数的处理

不阻塞软件开发，但真机执行前必须通过配置和人工验证门槛：连接信息、夹爪宽度与力/速度、垂直姿态与坐标、起点/等待高度、接触高度、可达区域/压深、速度/加速度、超时、静止判据与基线质量阈值。闭环还需要实测标定有效区间、目标、增益、滤波及方向/速度适用性。

400 mm/20 mm 压深不能自动获准；先短行程、浅下压。沿 X 的数据不自动适用于 Y 或圆的所有切向。若不能建立可用局部关系，允许只完成开环采集并报告原因，不强制导出伪标定表。

## 首轮磁触觉毛笔实验平台操作说明

来源版本：`2026-09-09-experiment-platform-operations.md`。

> 历史首轮平台说明：本文的“实验姿态保持垂直”等要求不适用于当前梯子脚本。当前实验以每次 run 实际记录的姿态为依据；前馈表须记录并匹配其适用姿态。当前脚本对 Ry15/Rz0 批次设有 1° 启动姿态检查，不能把“记录现场姿态”误读为“允许任意姿态”。

<a id="source-2-当时适用范围不作为当前操作指令"></a>
### 当时适用范围（不作为当前操作指令）

本文对应首轮实验平台的软件实现。当前仅完成假设备、合成磁信号和离线文件测试，**没有完成真机验证，也不代表任何候选行程、速度、接触高度或压深是安全的**。本轮不接相机、不记录墨迹、不评价书写质量。

笔与夹爪长期固定。正常完成、停止、故障和返回流程均不得自动松爪；TCP 应位于笔杆与 40 mm 笔毛的连接根部，实验姿态保持垂直，不使用 5° 前倾。

<a id="source-2-依赖与启动边界"></a>
### 依赖与启动边界

程序启动不得自动安装依赖。需要准备开发环境时，由操作者在仓库根目录人工执行项目既有安装命令，例如：

```bash
python -m pip install -e '.[test]'
```

如本机尚未安装 PyQt5 或真实机器人适配库，应由操作者根据现场环境单独安装；不要让 monitor 自动安装，不要修改 `/home/ethan/elfin-dhag-adapter`。仅预览 JSON、导入模块或运行测试不会建立机器人连接。真实适配器只接受外部显式注入的连接对象，并要求已验证安装配置及传输超时。

<a id="source-2-坐标单位与控制量"></a>
### 坐标、单位与控制量

- JSON 中路径、速度、加速度、TCP Z、monitor 起点和等待高度分别使用 mm、mm/s、mm/s²、mm。
- 内部机器人位姿使用 m/rad。TCP Z 是笔毛根部高度；若接触参考为 40 mm，压深 20 mm 对应 TCP Z=20 mm。这里的 40 mm、20 mm 只是候选值。
- 路径从 monitor 指定的世界起点 XY 出发。直线的 `delta_xy_mm` 是局部位移；圆从局部 `(0,0)` 开始，圆心位于 `(radius,0)`。
- 开环没有磁目标，界面和记录应显示“不适用”/`null`，不能用 0 μT 代替。
- 闭环控制量是 `hypot(ΔBx, ΔBy)`；原始 Bx、By、Bz 与三个差分分量仍全部保存。
- 0 μT 与 ±5 μT 是同一目标、前馈、滤波、增益和路径下的后续死区对照条件，不是两个磁目标。

<a id="source-2-实验-json"></a>
### 实验 JSON

从 `configs/experiments/` 选择一个版本 1 文件，复制后每次只填写并执行一个速度。`_comment` 可记录其他候选速度，但程序不会自动执行三档。

开环字段完整示例：

```json
{
  "version": 1,
  "name": "x_press_scan",
  "_comment": "其他候选 X 速度：10、20 mm/s；不是自动批次。以下行程和 Z 均待真机验证。",
  "path": {"kind": "line", "delta_xy_mm": [400, 0]},
  "motion": {"speed_mm_s": 5, "accel_mm_s2": null},
  "z": {"start_tcp_z_mm": 40, "end_tcp_z_mm": 20},
  "control": {"enabled": false}
}
```

闭环还必须填写 `target_uT`、`deadband_uT`、`kp`、`ki` 和 `calibration_file`。仓库中的三个闭环文件把实测目标、增益和标定路径保留为 `null`，因此仅能预览，不能执行。不能借用仿真默认值。

<a id="source-2-操作顺序"></a>
### 操作顺序

1. Monitor 数据源只保留串口和回放；物理参考圆默认 400 μT，显示滤波默认“原始”。录制只有“开始录制/停止录制”，不填写动作名称、不添加人工标记。显示滤波不改变保存的原始 ΔB。
2. 在实验面板中选择 JSON，核对路径预览、单一速度和控制模式。选择文件或编辑起点 X/Y、等待 Z 不会触发运动。
3. 在独立笛卡尔返回面板核对完整目标 X/Y/Z（mm）和 Rx/Ry/Rz（度）。编辑这些值不会运动；返回目标不从 StrokePlan 或实验 JSON 推断。
4. 核对安装配置仍与现场一致。任何真实安装字段未知或未经审核时，到此停止，只做预览或假设备测试。
5. 查看状态；若需要返回，只有点击独立面板的“回到开始位置”才提交完整六维目标。路线先在当前 XY/姿态抬到 `max(当前 Z, 目标 Z)`，再在高位平移到目标 XY、切换到目标姿态，最后按需下降。不得用选择文件、加载或执行按钮代替返回。
6. 点击“执行”后，运行快照冻结。平台先在悬空静止状态自动采集基线，基线通过后才接近纸面；操作者不手动复用上一轮基线。
7. 开环与闭环使用同一 StrokePlan 状态机。运行中持续记录磁数据、控制数据和事件。修改磁目标、增益、坐标或 JSON 不影响当前已冻结的运行。
8. 正常完成后在路径终点抬到等待高度并进入 `END_WAIT`，不会自动回到起点，也不会松爪。需要返回时重新核对独立面板的六维目标后提交。

暂停 monitor 绘图不应停止统一采样。实验模式下不得同时启用旧 monitor 串口源，以免双读传感器。

<a id="source-2-停止故障与恢复"></a>
### 停止、故障与恢复

运行中点击“停止”会请求受控中止。通信故障、未知位姿或无法确认停止时进入 `FAULT`，禁止自动抬笔、自动续跑、自动复位或自动使能。任何分支都不自动松爪。先使用实体急停和控制柜既定流程确保现场安全，再由负责人判断是否允许新的动作。

每次运行目录包含 `manifest.json`、`sensor.csv`、`control.jsonl`、`events.jsonl`、解析后的配置、安装快照和编译轨迹。只有 manifest 状态为 `completed` 才表示软件状态机与记录器正常结束，不表示真机效果通过。异常退出遗留的 `running` 记录可在后续记录器启动时标记为 `interrupted`；保留原目录，不手工拼接两段数据。manifest 的 `execution_environment: synthetic` 明确表示假后端数据，不能用于声称真机效果。

monitor 服务仍运行且实验与另一返回均未处于活动状态时，可从另一终端执行受限返回客户端。六个目标参数全部必填：

```bash
python scripts/return_experiment_start.py \
  --socket /path/to/experiment.sock \
  --x-mm 100 --y-mm 200 --z-mm 60 \
  --rx-deg 0 --ry-deg 0 --rz-deg 0
```

客户端先读取实验和返回状态、打印冻结后的 m/rad 目标，只有明确输入 `return` 才提交 `return_pose` 请求。socket 不可用或服务拒绝时客户端必须失败，不得回退为直接连接机器人。

<a id="source-2-尚未授权的现场验收"></a>
### 尚未授权的现场验收

以下步骤必须另行取得真机授权，并逐步记录为不同结论：静止装配态传感器检查；夹持/TCP/UCS/垂直姿态/纸面与急停检查；空中短路径及返回；浅下压短行程开环；逐级验证适用速度与范围；审核标定和滤波延迟；最后才以同一配置比较 0 μT 与 ±5 μT 死区。软件测试通过、接口联通、真机可运行、标定可用和闭环表现是五个不同状态，不能互相替代。
