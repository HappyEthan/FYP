# ΔB 实时监控（monitor）

> ΔB 实时监控模块：读取触角磁传感器（MLX90393 + XIAO ESP32-C3）三轴磁场变化 ΔB，实时可视化、录制成 V0 格式数据集，并沉淀了 V0 数据集的定稿分析结论。代码：`src/brushbot/monitor/`（core.py / sources.py / recorder.py / window.py）、`scripts/analyze_deltab.py`、数据集 `delta_b_v0_20260724/`。过程细节见 `docs/archive/` 与 git 历史。

## 做了什么

- 原生 Qt 实时窗口：ΔBx–ΔBy 相图（等比例、带拖尾）+ 独立 Y 轴时序图（ΔBz 可选），状态栏显示 `|ΔB|`、`|ΔBxy|`、方位角 φ、极角 θ、三轴瞬时值与门控阈值。
- 三种数据源（串口 / 回放 / 合成）统一接口，可录制成与 `delta_b_v0_20260724/` 一致的 CSV+JSON 格式，直接被分析脚本消费。
- 基线与方向门控：取基线时同时测噪声 σ，门控阈值 = `3·‖σ‖`；`|ΔB|` 低于门控时 φ/θ 显示 `—`、不画方向线（避免噪声主导下的假方向）。
- 离线交互回放页（自包含 HTML，3D 向量 + 罗盘 + 时序，可变速/定位/分享时刻）。
- V0 数据集（5 条记录，100 Hz）完成独立复核分析，产出 E0 噪声底、信噪比、方向可分性等定稿数字（见下）。

## 怎么用

安装与启动（需要图形界面，纯 SSH 无 X11 跑不了）：

```
conda activate brushbot && pip install -e ".[monitor]"
python -m brushbot.monitor
```

三种数据源（窗口内按钮切换，非命令行参数）：

| 源 | 用途 | 参数 | 可录制 |
|---|---|---|---|
| 串口 | 实时读 ESP32+MLX90393 | 默认 `/dev/ttyUSB0` @115200，固件行格式 `t_us,Bx,By,Bz`，端口可在界面改 | 是 |
| 回放 | 读已录制的 V0 数据集 CSV | 选择 CSV 文件；0.25–8× 变速 | 否（不产生新数据） |
| 合成 | 解析模型产生虚拟信号，无需硬件 | `sources.synth_writing_B()`；录制 JSON 中 `sensor` 标为 `synthetic` | 是 |

基线：每次连接整体重置，连上 1 秒后自动取基线，随时可按「取基线」重取。回放源连接时先从记录 JSON 读 `b0` 作初值（ΔB 从第一帧起正确），但方向门控保持抑制，直到 1 秒后自动重取基线测得 σ 为止。

录制流程：先取基线 → 「● 录制」→ 动作起止按「标记 START / STOP」→「■ 停止」，输出到 `recordings/`。CSV 固定 5 列：

```
t_us,t_s,dBx_uT,dBy_uT,dBz_uT
```

单位 µs / s / µT；配套 JSON 记录基线 `b0`、动作起止时刻、传感器与单位元数据。分析与离线回放页：

```
python scripts/analyze_deltab.py recordings out.png
python scripts/make_replay.py delta_b_v0_20260724 deltab_replay.html && xdg-open deltab_replay.html
```

排错速查：

| 现象 | 处理 |
|---|---|
| 打不开信号源 | `ls -l /dev/ttyUSB0` 查权限；必要时 `sudo usermod -aG dialout $USER` 后重新登录 |
| 曲线不动 | 确认已点「连接」；串口源需固件正在输出 |
| φ/θ 一直是 `—` | 正常——信号未超噪声门控；或重新取基线 |
| Qt 报 `xcb` 插件错误 | 需要图形界面，不能在纯 SSH 无 X11 下运行 |

## V0 数据集结论

数据：`delta_b_v0_20260724/`，100 Hz，5 条有效记录（idle 10 s + 线/圆各正反向），无丢包、无时间回退。复现：`python scripts/analyze_deltab.py delta_b_v0_20260724 docs/assets/deltab_v0_analysis.png`。

**噪声底（E0 的一半）**：静止 10 s 全带宽 σ = (3.21, 3.12, 5.30) µT，`|σ| = 6.94 µT`；z 轴显著高于面内（与 MLX90393 z 轴分辨率较差一致）。方向门控阈值由此定为 3×|σ| ≈ 20.8 µT。

噪声-带宽权衡（低通截止 fc → σ，µT；谱能量集中在低频，降带宽收益明显）：

| fc (Hz) | 1 | 2 | **3** | 5 | 10 | 20 | 50 |
|---|---|---|---|---|---|---|---|
| σx | 0.53 | 0.66 | **0.80** | 1.01 | 1.40 | 2.01 | 3.21 |
| σy | 0.46 | 0.65 | **0.79** | 0.96 | 1.37 | 1.93 | 3.12 |
| σz | 1.63 | 1.86 | **2.08** | 2.33 | 2.88 | 3.64 | 5.30 |

提按需求带宽 3 Hz 处 `|σ| = 2.36 µT`。由 E0 判据反推硬件灵敏度门槛 `S_min = 5·|σ|/分辨率`：分辨率 1.0 / 0.5 / 0.2 mm 分别要求 S ≥ **11.8 / 23.7 / 59.1 µT/mm**（E2 标定出真实 S(z) 后对照即判 E0）。

**信噪比**：动作峰值 461–945 µT，SNR 67–136×，信号比噪声大两个数量级——"磁场稳、抖动小"的前提在 100 Hz 下成立。

**方向可分性（E4 部分证据）**：line_lr vs line_rl 夹角 157.5°，circle_cw vs ccw 172.5°（判据仅要求 >60°）。但只有同一动作的正反向是反平行；不同类型动作方向可能很近（如 32.7°）。且数据集无纯压入记录，**未回答 E4 真正的"压 vs 拖解耦"**。

**回零残差**：动作结束 1 s 后残留 12.4–38.6 µT（噪声底的 1.8–5.6×）→ 基线治理是必需项，基线重估等待时间 τ 不能想当然设 1 s，需 E1/E3 实测。段内漂移小（idle 10 s 线性漂移 (0.4, 0.3, −5.4) µT），问题出在动作后与跨会话。

**跨记录基线**：5 次记录 B0 极差 (56.3, 18.3, 93.0) µT（z 轴 ≈13× 噪声底）→ 不同会话 ΔB 绝对值不可直接比较，每段数据必须自带基线（现格式已做到）。

**ΔBz 并不平**：真实数据 ΔBz 与面内同量级（std 比 0.61–1.36×），合成模型"面内随压深增长、轴向平"的结构无证据支持，不能拿它做控制设计；判定需 V1 纯压入记录。

## 已知局限与待办

1. **`feat/monitor-filter-ui` 分支待验收合并**（滤波下拉框五档：原始/EMA 0.3/Butter 5Hz/Butter 8Hz/OneEuro、回放进度条、原始值 raw ghost 叠影；仅影响显示不影响录制）。与 master 0 冲突，待有显示器的机器上 `python -m brushbot.monitor` 手动验收后合入。验收要点：
   - 滤波五档可切换且即时生效；叠影淡灰原始在下、亮色滤波在上，选"原始"时单曲线。
   - 回放/合成源出现进度条，拖动跳转与时间标签正确；串口源隐藏；暂停→拖动→恢复无快进补帧。
   - 换滤波档重录，CSV 数值不变（录的始终是原始 ΔB）；20 s 时窗 + OneEuro 无明显卡顿；接触判定行为与改造前一致。
2. **录制格式与离线管线不匹配**：recorder 落 5 列（`t_us,t_s,dBx_uT,dBy_uT,dBz_uT`），`demo_pipeline` 硬性要求 7 列（另需 `x_m,y_m`）。真实示范录制需要新的生产者——磁流与机械臂 FK 双源时间对齐/重采样层目前零代码（审计 R8，见 `docs/review-2026-08-10.md`）。
3. **MuJoCo→监控 UDP 桥只有 spec 未实现**：`docs/superpowers/specs/2026-07-29-mujoco-udp-bridge-design.md`；monitor 与仿真/控制链之间目前无任何实时通路。
4. **V0 噪声结论的适用边界**：全部噪声数字基于一份约 10 s 的**裸态**（未装机）idle 录音；装配态有电机 EMI 与法兰磁场，属乐观下界，E0 装配态复测后需重估（含门控阈值 20.8 µT 与 S_min 门槛表）。各记录动作前静止段 σ 反而更高（6–8 µT，非真静止），以专门 idle 记录为准。
