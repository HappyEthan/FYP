# ΔB 实时监控窗口 · 设计文档

日期：2026-07-24
状态：已确认，待实施

> 一个原生窗口，既能**回放**录制的 ΔB 数据，也能**实时监控**真实（Arduino/MLX90393）或虚拟（合成模型）信号，
> 并能把实时数据**录制**成与 `delta_b_v0_20260724/` 完全一致的格式。
> 关联：`docs/deltab-v0-analysis.md`（数据分析）、`docs/gate-experiments.md`（E5 采集规范）。

---

## 1. 目标与范围

### 要做的

| # | 能力 |
|---|---|
| 1 | 实时监控 Arduino（ESP32 + MLX90393，100 Hz）串口信号 |
| 2 | 回放已录制的 CSV/JSON 数据集 |
| 3 | 接入合成信号源（解析模型），为将来接 MuJoCo 预留接口 |
| 4 | 绘图：**ΔBx–ΔBy 平面相图** + **各自独立的 ΔBx / ΔBy 时序图**，ΔBz 单独一栏且可折叠 |
| 5 | 录制成 V0 兼容格式（CSV + JSON，含人工动作标记与基线） |

### 明确不做的（YAGNI）

- ❌ ΔB 三轴合并在一张图上（用户明确不要）
- ❌ 3D 向量视图（回放页已有，此窗口不重复）
- ❌ 纸面物理坐标 x–y 轨迹（需要 ΔB→位置标定，尚未解决）
- ❌ 跨平台/打包分发（只在 Ethan 的 Ubuntu 上跑）
- ❌ 界面自动化测试（无显示环境无法验证，改为手动验收）

### 运行环境

Ubuntu（Ethan 本机），conda 环境 `brushbot`，串口 `/dev/ttyUSB0`。

## 2. 技术选型

**PyQtGraph 原生窗口**（新增依赖：`pyqtgraph` `PyQt5` `pyserial`，均已验证可安装）。

| 备选 | 否决理由 |
|---|---|
| matplotlib 动画 | 100 Hz × 多面板会卡；暂停/缩放/折叠等交互需自行实现，体验差 |
| Python 后端 + 浏览器前端 | 需起服务器、两个进程；最大优势（跨平台）在本场景用不上；且不是原生窗口 |

GUI 依赖装成**可选 extra**（`pip install -e ".[monitor]"`），核心包保持轻量——不装 PyQt5 时现有仿真与分析脚本照常可用。

## 3. 架构

三层解耦，沿用仓库既有模式（算法/IO/界面分离）：

```
  信号源(可插拔)              核心(无 GUI, 可测)          界面(PyQtGraph)
┌──────────────┐         ┌──────────────────┐      ┌─────────────────┐
│ SerialSource │──┐      │  RingBuffer      │      │  XY 相图        │
│ ReplaySource │──┼─原始B→│  Baseline(B0)   │─ΔB→ │  ΔBx 时序       │
│ SynthSource  │──┤      │  派生量 |ΔB|,φ,θ │      │  ΔBy 时序       │
│ (MuJoCo 预留)│──┘      │  Recorder        │      │  ΔBz 时序(折叠) │
└──────────────┘         └──────────────────┘      └─────────────────┘
```

### 3.1 信号源接口

```python
class Source(Protocol):
    def start(self) -> None: ...
    def read(self) -> list[tuple[float, float, float, float]]:
        """返回自上次调用以来的新样本 (t_s, Bx, By, Bz)。原始 B，非 ΔB。非阻塞。"""
    def stop(self) -> None: ...
    @property
    def info(self) -> dict:
        """{name, nominal_rate_hz, units, port?, ...}"""
```

**关键决定：信号源一律输出原始 B，扣基线由核心负责。** 理由：

1. 固件本就输出原始 B（`t_us,Bx_uT,By_uT,Bz_uT`），扣基线本就在上位机做；
2. 基线必须能**随时重取**（按钮）——若源直接吐 ΔB，重取基线无从谈起；
3. 回放也能重新调零：`ReplaySource` 把 CSV 里的 ΔB **加回** JSON 的 B0 还原成原始 B。
   默认基线仍取该 B0，故显示结果与原记录**逐点一致**。

三个实现：

| 源 | 说明 |
|---|---|
| `SerialSource` | pyserial 读 `/dev/ttyUSB0` @115200，按行解析 `t_us,Bx,By,Bz`，跳过 `#` 开头的表头 |
| `ReplaySource` | 读 V0 的 CSV+JSON，按记录的时间戳节奏回放；支持播放/暂停、变速、跳转（见 §4.3） |
| `SynthSource` | 先用 `brushbot.tactile.writing_tactile` 离线算出一整段写字的合成 ΔB 序列，再按标称 100 Hz **逐点流式吐出**（叠加标称 B0 还原为原始 B），行为上等价于一个"虚拟传感器" |
| `MuJoCoSource` | **仅预留接口**，待 Phase 3 的 ΔB 发散 bug 修复后实现 |

### 3.2 线程模型

**采集与重绘必须解耦**——若每来一个样本就重绘一次，100 Hz 重绘必然卡顿。

实现方式：**单个 Qt 定时器，约 50 FPS**，每次先把信号源里累积的样本一次性取走写入环形缓冲，
再重绘。环形缓冲为 numpy 定长数组（60 s @100 Hz = 6000 点，O(1) 写入）。

为什么不起独立采集线程：100 Hz × 约 30 字节/行 ≈ 3 KB/s，而 OS 串口缓冲通常 ≥4 KB，
50 FPS 轮询每次只需取走约 2 个样本，`pyserial` 非阻塞读足以覆盖；单定时器省掉了缓冲加锁与竞态。

> **已知代价**：若界面被阻塞超过约 1 秒（如弹出模态对话框），串口数据可能溢出丢失。
> 串口监控的正常流程不会开对话框，故可接受。若实测出现丢样，升级路径是把采集移入
> `QThread` 并给 `RingBuffer` 加锁。

### 3.3 基线 B0

| 场景 | 行为 |
|---|---|
| 连接串口后 | 静置 1 s，自动取该秒均值为 B0，状态栏提示 |
| 手动 | `取基线` 按钮，取最近 1 s 均值 |
| 回放 | 初始用记录 JSON 中的 B0（与原记录一致），可重取 |

取基线的同时计算该秒的三轴标准差 σ，用作**方向门控阈值**（见 §4.2）。

> 依据：`docs/deltab-v0-analysis.md` §6.1，跨会话 B0 极差达 93 µT，基线必须每次重取并随数据存档。

## 4. 界面

### 4.1 布局

```
┌ 工具栏 ─────────────────────────────────────────────────────────────────┐
│ 源[串口▾] 端口[/dev/ttyUSB0▾] [连接] │ [取基线] │ [●录制] [标记START/STOP] │
│ 动作名[line_lr] │ 时窗[10s▾] │ 拖尾[2s▾]                                  │
├────────────────────┬────────────────────────────────────────────────────┤
│                    │ ΔBx ┌────────────────────────────────────────────┐ │
│    XY 相图          │     └────────────────────────────────────────────┘ │
│    ΔBx – ΔBy       │ ΔBy ┌────────────────────────────────────────────┐ │
│    等比例·拖尾      │     └────────────────────────────────────────────┘ │
│    幅值刻度圈       │ ΔBz ┌──────────── ▸可折叠 ────────────────────────┐ │
│                    │     └────────────────────────────────────────────┘ │
├────────────────────┴────────────────────────────────────────────────────┤
│ |ΔB| 648.3  |ΔBxy| 574.3  φ 86.4°  θ 117.6°  ΔBx 36.3  ΔBy 573.2  ΔBz −300.9 │
│ ● 已连接 /dev/ttyUSB0 · 实测 100.0 Hz · 坏行 0 · 录制中 04.2s              │
└──────────────────────────────────────────────────────────────────────────┘
```

- **三个时序图各自独立 Y 轴自动缩放**——不共享量程，否则小分量会被大分量压平。
- 共享 X 轴（时间），滚动时窗可选 5 / 10 / 30 / 60 s。
- ΔBz 面板默认折叠。
- XY 相图：等比例，带拖尾（时长可选）、当前点标记、幅值刻度圈。
- 读数区：`|ΔB|`、`|ΔBxy|`、方位角 φ、极角 θ（与 +z 夹角）、三轴瞬时值。

### 4.3 按源切换的工具栏

工具栏内容随所选信号源变化，不可用的控件置灰：

| 源 | 可用控件 |
|---|---|
| 串口 | 端口下拉、连接/断开、取基线、录制、动作标记 |
| 回放 | 选文件、▶/⏸、进度条、变速（0.25–4×）、取基线；**录制置灰**（回放不产生新数据） |
| 合成 | 选字/参数、▶/⏸、变速、取基线；**录制可用**（合成数据也可存档，JSON 中 `sensor` 标为 `synthetic`） |

### 4.2 方向门控

当 `|ΔB| < 3·‖σ‖` 时：φ / θ 读数显示 `—`，XY 相图不绘制方向线。
其中 `‖σ‖ = sqrt(σx² + σy² + σz²)`，即取基线那 1 秒内**三轴标准差的模**（与回放页口径一致）。

理由与回放页一致：幅值接近噪声时方向由噪声主导，绘制出来是**假信息**。
阈值按当天实测噪声自适应，不写死常数（V0 实测约为 20.8 µT，但换设备/配置会变）。

## 5. 录制

**输出目录**：默认 `recordings/`（仓库根下，git 忽略），可在工具栏切换。

**`repetition` 编号**：写文件前扫描输出目录中同 `action` 的既有文件，取最大编号 +1，从 1 起。

停止录制时写出一对文件，字段与 `delta_b_v0_20260724/` 完全一致：

- `YYYYMMDD_HHMMSS_<action>_r<NN>.csv`，列 `t_us,t_s,dBx_uT,dBy_uT,dBz_uT`
- 同名 `.json`，含 `created_at / action / repetition / valid / sensor / board / port / baud /
  units / delta_definition / baseline_B0_uT / display_smoothing_applied / recording_mode /
  action_window_s / action_start_t_us / action_end_t_us / sample_count / measured_duration_s /
  mean_sample_rate_hz / max_interval_us / csv_file`

`标记START/STOP` 按钮写入 `action_window_s`（对应 V0 的人工标记）。

**收尾自检**：停止录制后立即用 `scripts/analyze_deltab.py` 的加载器回读刚写的文件对，
读取失败则在状态栏报警——避免录完才发现格式损坏。

## 6. 错误处理

| 情况 | 行为 |
|---|---|
| 串口打不开 | 状态栏红字提示，不崩溃，可重选端口重试 |
| 采集中断线 | 停止采集；**安全收尾正在进行的录制**（JSON 标 `valid=false` 并注明断线原因）；状态转红 |
| 坏行 / 半行 | 计数并跳过（串口按行缓冲，正确处理跨包截断的行） |
| 实测频率偏离标称 | 状态栏显示实测 Hz；偏离 >2% 变黄 |
| 缓冲写满 | 环形覆盖最旧样本（设计如此，不报错） |
| 合成源异常 | 捕获并在状态栏显示，不影响已采集数据 |

```

  __init__.py
  sources.py    SerialSource / ReplaySource / SynthSource   (无 GUI 依赖)
  core.py       RingBuffer + Baseline + 派生量               (无 GUI 依赖)
```

```toml

monitor = ["pyqtgraph", "PyQt5", "pyserial"]
```

## 8. 测试策略

`sources` / `core` / `recorder` 三个模块无 GUI 依赖，全部单元测试：

| 测试 | 内容 |
|---|---|
| **往返测试（最关键）** | `FakeSource` 灌已知信号 → 录制 → 用 `analyze_deltab.py` 的加载器回读 → 断言逐点一致。直接保证录出的数据能被现有分析脚本与回放页消费。 |
| 串口解析 | 灌入含表头 `#`、半行、跨包截断、乱码的字节流 → 断言不崩、坏行计数正确、好行解析正确 |
| 环形缓冲 | 写满后覆盖顺序、取最近 N 点、时间单调 |
| 基线 | 取基线正确性；重取后 ΔB 相应变化；σ 计算 |
| 派生量 | 已知向量 → `|ΔB|`、`|ΔBxy|`、φ、θ 的期望值；门控在 `|ΔB| < 3σ` 时置空 |
| ReplaySource 一致性 | 回放 V0 记录 → 输出的 ΔB 与原 CSV 逐点一致（验证"加回 B0 再扣"闭环无误差） |

**界面不做自动化测试**：PyQtGraph 窗口无法在无显示环境验证，改为手动验收——
窗口实际观感需在 Ethan 本机运行确认。核心逻辑的正确性由上述单测保证。
