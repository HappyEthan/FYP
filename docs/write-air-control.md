# 开环写字控制算法详解（write_air.py）

> 真机开环写字：华沿 Elfin E05 + 毛笔，在纸上写汉字。**无触觉反馈**，纯位置伺服。
> 输入：汉字串 + 实测 z 带参数；输出：20ms 伺服流命令。
> 代码：`examples/write_air.py` + `src/brushbot/{calligraphy/hanzi.py, controller.py, runtime.py, backends/huayan.py, backends/vendor/CPS.py}`。
> 配套：模块总览见 `docs/openloop-writing.md`，机械臂实测结论见 `docs/handoff-e05-arm.md`。

---

## 1. 一句话概括

**字形中线数据 → 每笔"抬-落-描-收"路点 → 沿折线弧长匀速插值 → 20ms 伺服流推给机械臂，全程 z 被钳在 [z_min, 抬笔] 内。**

控制上只有两件事：**几何路径怎么来**（数据→路点）和**沿路径怎么走**（匀速插值→伺服流）。没有力觉、没有提按反馈，笔画粗细完全靠"z 压多深"这一个常数决定。

---

## 2. 输入参数（CLI）

| 参数 | 默认 | 含义 |
|---|---|---|
| `--char` | 永 | 要写的字（可多字，横排左→右） |
| `--size` / `--gap` | 自动 | 字框边长 / 字框间留白（mm）；不传按字数自动选档 |
| `--x0` / `--y0` | 自动 | 首字中心 xy（mm，Base 系）；x0 不传则整组自动居中 |
| `--x-min` / `--x-max` | -200 / 160 | x 轨迹硬限制 |
| `--z-work` | **必填** | 正常笔画粗度的写平面 z（mm） |
| `--z-max` | **必填** | 刚触纸 z（mm） |
| `--z-min` | **必填** | 会损坏的下限 z（mm） |
| `--hover-clearance` | 10 | 抬笔比 z_max 高多少（mm） |
| `--speed` | 18 | 笔速（mm/s），上限 60 |
| `--yaw` | 0 | 字在纸上的朝向（度），0 = 字的上方朝 +y |

**z 带语义**（真机实测，永字例）：`z_max=296`（刚触纸，只留痕）> `z_work=287`（正常笔画，压下 9mm）> `z_min=275`（会损坏）。抬笔 `hover = z_max + clearance = 306`。

## 3. 数据链路

```
makemeahanzi/graphics.txt (每字 medians: 每笔有序中线点列, 字体单位)
  │ load_medians()            取某字每笔中线
  ▼
medians (字体单位, 0~1024 量级)
  │ medians_to_strokes()      缩放使长边=size, 包围盒居中到原点
  ▼
strokes (局部米制, 每笔 [(x,y),...])
  │ strokes_to_waypoints()    每笔转成 抬-落-描-收 路点, yaw 旋转放到世界系
  ▼
waypoints (世界 (x,y,z) 路点列表)
  │ OpenLoopController()      沿折线按弧长建累积表
  ▼
每拍: step(t) = 弧长匀速插值 → (x,y,z, 常量姿态)
  │ RealClock 20ms 定频 + clamp_z() 安全钳
  ▼
HuayanBackend.write → HRIF_PushServoP (SI→毫米/度) → Elfin E05
```

数据流里值得注意的分界：

- **笔画几何来自数据**（medians 是书法家按真实笔路画的中线骨架）。
- **"怎么走"来自控制器**（弧长匀速插值）。
- **medians 只含 xy 路径，不含提按/笔宽**（`hanzi.py` 注释明确）——开环阶段笔画宽度恒等，提按留给触觉闭环（phase 2）。

## 4. 每笔路点结构（strokes_to_waypoints）

对每一笔，生成 4 个阶段（`hanzi.py:50-58`）：

```
抬笔  (起笔点,  z_up)     ← 从上一笔收笔位飞到本笔起点上方 (306)
落笔  (起笔点,  z_down)   ← 在起点原地垂直下压 (306→287, 穿过触纸点 296)
描线  (中线各点, z_down)  ← 沿中线匀速走, z 恒 287
收笔  (终点,    z_up)     ← 在终点垂直抬起 (287→306)
```

多字时在每字前插一个该字中心的抬笔点，字间过渡全部发生在抬笔高度（306），纸面零接触。

**这是"笔锋"的来源**：落笔在起点先压后走（起笔顿印），收笔在终点边抬边走（收笔拖尾）。详见 §9。

## 5. 插值控制律（OpenLoopController）

`src/brushbot/controller.py`，全开环、纯几何：

```
构造: 把路点建成 (N,3) 数组, 预计算每段长, 累积弧长表 cum[0..N]
每拍: d = speed * state.t            ← 弧长按匀速推进 (state.t 是节拍累计时间)
      _interp(d): 在 cum 里二分定位当前段, 段内线性插值出 (x,y,z)
      输出 Command(tcp_pose = (x,y,z, 常量姿态))
done: d >= 总弧长
```

要点：

- **匀速 = 弧长匀速**，不是时间匀速。急转弯处线速度不变（角速度变化），保证落墨均匀。
- **无加减速/无圆弧过渡**：起笔落笔切换干脆——这是笔锋清晰的原因之一。
- **姿态常量直通**：全程用启动时读到的姿态（`ori = 当前 tcp_pose[3:6]` 转弧度），笔杆朝向不变，字形形状完全由 (x,y) 路径决定。
- 姿态单位纪律：控制器收**弧度**；`huayan.py` 的 `_si_to_hrif` 只在本文件把弧度→度、米→毫米。

## 6. 伺服流（RealClock + HuayanBackend）

```
RealClock(fs=1/0.02)   # 20ms 绝对节拍 (50Hz), 迟到记 overrun 并重对齐
while not ctrl.done():
    t, ov = clk.tick()
    cmd = ctrl.step(State(tcp_pose=0s, g_meas=0.0, t=t))   # 开环不读传感
    pose = clamp_z(cmd.tcp_pose, z_min_m, hover_m)          # 安全钳
    backend.write(Command(tcp_pose=pose))                   # PushServoP
```

伺服参数来自 `config.py`（2026-08-10 真机 servo_scan 定参）：

- `HUAYAN_SERVO_DT = 0.02`（20ms 推送周期）——滞后 40ms 最低、RMS 0.07mm 的甜点。
- `HUAYAN_LOOKAHEAD = 0.05`（50ms 前瞻）。
- **速度倍率不缩放伺服流**——伺服安全靠指令限幅，不是示教器倍率。所以软件侧的三层钳是唯一防线。

## 7. 多字布局（自动档位 + 自动居中）

`--size/--gap` 不传时按字数选最大可装档（`PRESETS`，随 x 限制 [-200,160] 容量）：

| 字数 | size/gap (mm) | 中心距 | 横排总宽 |
|---|---|---|---|
| 1–2 | 120 / 20 | 140 | ≤260 |
| 3 | 100 / 10 | 110 | 320 |
| 4–5 | 60 / 15 | 75 | ≤360 |

`--x0` 不传时整组字自动居中在 [x_min, x_max]：

```
x0 = (x_min + x_max − (n−1)·(size+gap)) / 2
```

`check_x()` 校验布局 x 范围 [x0−size/2, x0+(n−1)(size+gap)+size/2] 在 [x_min, x_max] 内，越界中止并打印合法 x0 区间。

## 8. 安全设计

| 层 | 机制 |
|---|---|
| 状态检查 | 启动即查 FSM=33（Standby），不在就中止 |
| 动前确认 | 打印完整计划后读 `/dev/tty` 要 `yes`（conda run 会吞 stdin，故直接读 tty） |
| 到位 MoveL | 用位置收敛判定（连续 3 次 <0.5mm）代替 IsMotionDone；停滞超时 10s 中止 |
| **z 安全钳** | 每拍 `clamp_z(pose, z_min, hover)`：越界打印 `[钳位]` 并钳回。z_min 以下是损坏区 |
| x 限制 | `check_x()` 布局级校验 + 当前位姿 x 越界即中止 |
| 失败处理 | MoveL 拒绝（不可达/未使能）立即中止；写循环异常不自动抬笔（操作者在场，用示教器/急停） |

## 9. 为什么会有笔锋

写出来的字带"笔锋"，来源有三，**都不是真正的提按控制**：

1. **落笔在起点原地垂直下压**：每笔先在起笔点从 306 压到 287，水平移动前先压进纸 9mm（穿过触纸点 296），形成**起笔顿印**。
2. **收笔在终点垂直抬起**：从 287 抬到 306，压力从满压渐减到离开，形成**收笔尖/拖尾**。
3. **弧长匀速无加减速**：起落笔切换干脆，印记边界清晰。

数据（medians）只给了笔画骨架的 xy 路径，**宽度是均匀的**。真正的笔锋（宽度渐变）需要提按控制——用 |ΔB| 触觉反馈调 z，那是闭环阶段（phase 2）的内容。

---

## 10. 局限与下一步

- **开环恒定 z_work**：纸面不平 / 笔损耗都会让粗细漂移——没有校正手段。
- **无提按**：写不出宽度渐变，笔锋只是落收笔的副产物。
- **下一步**：触觉闭环——用刷子传感器 |ΔB| 作形变代理，增量式调 z（见 brushpaint 项目的 `controller.py` 思路），把恒定 z_work 换成目标形变带内的反馈跟踪。
