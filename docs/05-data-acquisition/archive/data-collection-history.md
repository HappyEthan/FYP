# 数采方案 · 前期触觉毛笔数据采集构思

> 目的：把"人写一遍书法 → 得到可训练数据"这一步做成**可操作流程**。产出 = 每一笔在时间上对齐的 `(x, y, v, g_press, φ)` 序列 + 字形/笔顺标签，喂给"字形→逐笔运动轨迹 + 提按"的 Transformer。
> 本文为早期采集构思，以下“训练主标签”“干净法向提按”等表述只描述当时设想，未由当前实验验证。当前对应关系实验以 XY 磁变化模长 `|ΔBxy|` 为目标，不把它解释为力或纯法向形变。触角电子/接口与原始信号说明另见早期资料。
> 生成 2026-07-09。诚实性与未决见 §13。

---

## §0 一句话目标 & 最终数据表

**采集 = 同步记录"笔尖在纸面怎么走(视觉)"与"刷毛被压/偏多少(触觉)"，按笔画切好、按时间对齐。**

**最终每一笔的数据记录（训练用）：**

| 字段 | 含义 | 来源 | 备注 |
|---|---|---|---|
| `t` | 时间戳 | 统一时基 | 视觉/触觉共用 |
| `x(t), y(t)` | 笔尖纸面坐标(mm) | 视觉(追标记) | 决定字形 |
| `v(t)` | 书写速度(mm/s) | x,y 微分 | 治形变-运动耦合 |
| `g_press(t)` | **干净提按形变**(法向分量) | 触觉(方向解耦后) | ★训练主标签 |
| `φ(t)` | 偏移角/形变方向 | 触觉(多轴ΔB) | 解耦拖拽 + v2 姿态 |
| `stroke_id` | 笔画序号(笔顺) | 触觉切分 | 配对 & 泛化 |
| `char` | 字 + 该笔是第几笔 | 人工/OCR | 标签 |
| `B_raw(t)` | 原始 Bx,By,Bz | 触觉 | **必存**，供日后重解码 |

> 原则：**原始信号(B_raw)一定要存**，`g_press/φ` 是从它算出来的；解算方法以后会改，别把原始数据丢了。

---

## §1 采什么 & 不采什么（v1 边界）

- **采**：一个书写者、楷书、**固定蘸墨/纸/笔杆垂直姿态**、覆盖基本笔画的几十~百来字。
- **按"笔画覆盖"采，不是按字数**：先覆盖**永字八法**(点/横/竖/撇/捺/挑/折/钩)及常见组合，每种笔画多写几遍拿方差。
- **v1 固定的变量**（让"提按"成为笔画粗细的**唯一主因**，便于建模）：蘸墨量、纸、书写速度档位、**笔杆垂直**。
- **v1 不采**：笔锋 3D 倾侧姿态（→ v2，见 §12）；不同纸/墨；多书写者。

---

## §2 硬件与信号源

| 源 | 设备 | 关键要求 |
|---|---|---|
| **触觉** | 触角 + MLX90393 + 采集模块 | 输出**原始 Bx,By,Bz + 时间戳**，**≥100 Hz**，**有线低延迟**优先（BLE 仅备用）。见 `硬件方案-handoff.md` §8 接口契约 |
| **视觉** | 头顶相机（俯拍纸面） | 全局快门优先；帧率 ≥60 fps；固定机位；能拍全书写区 |
| **标记** | 笔杆上的 ArUco/彩色标记 | 贴在**刷毛上方**，书写时始终不被墨/手遮 |
| **夹具/纸** | 固定纸的夹具 + 平整台面 | 纸不许动；**三点示教定纸面**（执行端要用同一平面） |

## §3 采集方案 A（★推荐）：录过程 + 追笔杆标记

**核心思路**：不追墨迹，**追笔杆上的标记**——墨遮不遮无所谓，标记始终可见。逐帧得笔杆位置 → 直接给 `x(t),y(t)` → 微分给 `v`，**并且一次性解决"时间×空间"配对**。

> ⚠️ 这修正了早前"没法边写边录"的结论：那担心的是"边写墨迹会遮挡最终字形"，而这里追的是**笔杆标记的运动**，不是字形，两回事。**能架相机就优先用 A。**

**为什么 A 严格更好**：
- 直接得"位置对时间" → **有真速度**（方案 B 没有）。
- `x,y,g,φ` 全带时间戳 → **直接同步**，不用再靠"笔顺模板 + 速度假设"去猜笔内位置。

**v1 简化下的近似**：笔杆垂直时，笔尖 x,y ≈ 标记 x,y（差一个固定竖直偏移，标定一次即可）。v2 倾侧后需 `笔尖 = f(标记位姿, 倾角)`（见 §12）。

**步骤**：
1. 相机标定（内参）+ 对纸面做**单应(homography)**：把图像像素映射到纸面 mm。
2. 笔杆贴标记，量一次"标记→笔尖"的竖直偏移。
3. 录像 + 同步录触觉（§4 时间同步）。
4. 离线：逐帧检测标记 → 纸面坐标 `x(t),y(t)` → 平滑微分得 `v(t)`。

---

## §3b 采集方案 B（退路）：静态照 + 笔顺模板

**仅当无法录过程时用。**
1. 写完拍**成品照** → OCR 得字 → 查**标准笔顺模板**抽每笔 (x,y) 形状。
2. 触觉切笔画给**每笔时间轴 + 提按曲线**。
3. **按笔顺序号配对**空间(图像)与时间(触觉)。
4. 笔内"力对到位置"**无实测速度** → 用 **sigma-lognormal**（人类快速运动对数正态速度剖面）**重建**一条速度曲线。

**B 的局限（写进 limitation）**：无真速度、笔内位置靠模型假设、依赖"按标准笔顺书写"。→ 精度不如 A。

---

## §4 时间同步（相机 ↔ 触觉）——关键

两路数据各自带时间戳还不够，**要能对齐到同一时基**。做法（任选其一，从简）：
- **共同事件对齐**：开录后用笔尖在纸角**轻点一下**——触觉出一个尖峰、视觉见标记一个骤停，用这个共同事件对齐两条时间轴。
- **硬件触发/闪光**：一个 LED 闪同时被相机看到、被采集板记录（更准，要接线）。
- 记录两路各自的绝对时间戳，事后做**互相关**微调对齐。

> 同步误差直接变成"提按对错位置"的误差，**务必量一下对齐残差**（放进质量报告）。

---

## §5 触觉信号处理（采集端）

1. **基线 re-baseline**：`ΔB = B − B0`。接触前取 B0；**自重 tare**（毛笔+模块重量给的偏置先归零）。温漂/重装会让 B0 漂 → 每段开始重取。
2. **笔画切分**：提按信号过**下笔阈值**→ 起笔，回**提笔阈值**→ 收笔（**双阈值迟滞**防抖），得每笔时间轴 `stroke_id`。
3. **提按分量 `g_press` 解算**：多轴 ΔB → (幅值 `g`, 方向 `φ`) → **用 φ 投影掉侧向拖拽分量**，只留法向提按 `g_press`。
   - ⚠️ "能干净分离"是设计意图，**幅度靠 E4（恒力横向拖行）实测确认**；分不干净就先存 `g` 和 `φ` 原样，解耦放到离线迭代。
4. **必存 `B_raw`**：以上都是可重算的派生量，原始三轴一定留档。

---

## §6 视觉信号处理

1. 标记检测（ArUco 直接给位姿；彩色点做质心）→ 图像坐标。
2. 经 §3 的单应 → **纸面 mm 坐标** `x(t),y(t)`。
3. **平滑后微分**得 `v(t)`（用无相位滞后的平滑，如 Savitzky–Golay；别用会滞后的滑动平均）。
4. （v2）多标记/PnP 解笔杆 3D 姿态（见 §12）。

---

## §7 对齐与融合（产出最终记录）

1. 把触觉 `g_press(t),φ(t),B_raw(t)` 与视觉 `x(t),y(t),v(t)` **按统一时基重采样对齐**（选一个公共采样率，如 100 Hz，插值对齐）。
2. 用 §5 的 `stroke_id` 把整条时间线**切成逐笔片段**。
3. 每笔片段以**弧长 s∈[0,1]** 重参数化（与执行端 `g(s)` 一致）：便于训练"字形→关于弧长的提按曲线"，与运笔快慢解耦。
4. 输出 §0 那张表的记录（每笔一条 / 每字一组）。

---

## §8 采哪些字（采集内容规划）

- **覆盖优先**：永字八法 8 种基本笔画 + 常见折/钩组合；**每种笔画 ≥ N 次**（N 先取 10~20，拿提按方差）。
- 选字：挑能把基本笔画铺满的常用字（几十~百来字即可，不追字数）。
- **同字重复写几遍**：拿到"同一笔画同一位置"的人书写方差，作评估基线。
- 全程**固定条件**（§1），把变量锁死。

---

## §9 采集流程 SOP（一次采集怎么走）

1. 架相机、定纸夹具、**三点示教纸面**、贴笔杆标记、量标记→笔尖偏移。
2. 相机内参 + 纸面单应标定。
3. 触角接**有线**、确认采样率 ≥100 Hz、数据流为原始 Bx,By,Bz+时间戳。
4. **自重 tare + 取 B0**（笔悬空不接触）。
5. 开录两路 → **纸角轻点做同步事件** → 按 §8 清单书写。
6. 每写完一字：肉眼检查标记全程可见、触觉无饱和/断流。
7. 收工：存 **原始两路 + 标定参数 + 同步事件时刻**。
8. 离线跑 §5/§6/§7 出最终数据表 + §11 质量报告。

---

## §10 数据格式与存储

- **原始层**（必留）：视频、触觉 `B_raw` 时序、标定参数、同步事件时刻。
- **处理层**：逐笔对齐记录（建议 `.npz`/`.parquet`：数值序列；`.json`：字/笔顺/元数据）。
- 目录建议：`raw/<session>/…`、`processed/<char>_<stroke>.npz`、`meta.json`。
- 每条记录带：书写者、日期、蘸墨批次、纸批次、同步残差、解耦是否已做。

---

## §11 质量控制（每条数据过一遍）

- 标记是否全程被检出（丢帧率）？
- 触觉是否饱和（顶到 ±32767）或断流？基线是否漂出量程？
- 同步残差多大（§4）？
- 笔画切分对不对（笔数 == 该字标准笔数）？
- `g_press` 与 `v` 是否明显相关（若强相关，说明拖拽没解耦干净 → 回 §5.3）。
- **不合格就丢**，别把脏数据喂模型。

---

## §12 v2 扩展：捕捉 3D 笔锋姿态（为位姿控制备料）

v1 只采 x,y+提按；要复现**笔锋倾侧（中锋/侧锋）**，人写时得记**毛笔 3D 姿态**：
- 笔杆贴**多标记**或做 **PnP** 解 6D 位姿；或从触角多轴信号反解倾侧方向。
- 笔尖位置改为 `笔尖 = f(标记位姿, 倾角)`。
- 这是个**独立硬子问题**，对应资料库 **#8（3D 笔尖旋转 + 变分模仿）**——先精读再动手。
- 输出多一维：每点笔杆姿态，Transformer 相应扩输出。

---

## §13 诚实性 & 未决

- **方案 A 优于 B**（有真速度 + 直接同步），A 修正了早前"没法边写边录"的结论；**能录过程就上 A**，B 是退路。
- **`g_press` 解耦"能否干净"未证实** → 靠 **E4** 量化；未证实前存 `g,φ` 原样，离线迭代解耦。
- **B 方案的速度是 sigma-lognormal 估计，非实测** → 写进 limitation。
- **同步精度**直接影响"提按对位置"的准确度 → 必须量并报告。
- **v1 单书写者、固定条件** → 泛化到"人/纸/墨"不在 v1 范围。
- **v2 的 3D 姿态捕捉是硬子问题**，尚未落方案，先读 #8。
- 触觉采样率/有线低延迟以 `硬件方案-handoff.md` 为准；**原始 B_raw 必存**，一切派生量可重算。
