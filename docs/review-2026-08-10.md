## 2. 风险与未完成项（按严重度）

### 2.1 高危 —— 真机接入前必须修

**R1 · z_cmd 全链路无限幅**（`z_control.py:115`）
唯一的 clip 是积分器钳位（`:113`）；`kp·S_cal·e` 比例项无界，`z_ff` 只被标定表端点饱和。实测出厂默认增益下：传感器卡 0（断线补零）+ `g_d=250`（量程上限）→ z_cmd 压深 **11.04 mm**（标定量程仅 5 mm）；上游污染 `g_d=1e4` → 压深 246 mm。freeze 完全拦不住（freeze 只冻积分器，Kp 照走，这是设计行为）。**更危险的是** `docs/superpowers/specs/2026-08-05-runtime-integration-design.md:132` 已把"z 有控制器钳位"写成不做安全围栏的理由——**这个前提是假的**，照 spec 实现会把缺口原样带进真机执行链。`plan.md` B2 安全项本就未勾，但 spec 已经"以为它做了"。

**R2 · NaN 失效链：一个坏样本静默废掉闭环**
三段各自成立、连起来是完整事故链：
- `monitor/core.py:88-97`：**定稿的控制环滤波器 EMA 没有 isfinite 分支**——一个 NaN 样本永久毒化内部状态，之后输出恒 NaN（实测确认）。这违反 `filter.py:5` 的 NaN 策略、`sim_loop.py:128` 的 docstring 和 runtime spec §3.3；而 NaN 链路测试（`tests/test_sim_loop.py:185`）用的是 OneEuro——**唯独没测被定稿为生产滤波器的那一个**。
- `z_control.py:97-99`：NaN guard 声称返回"安全 z_cmd"，但 `g_d=NaN` 触发时 `np.interp(nan)` 返回 NaN——**guard 自己输出 NaN**（实测确认；`g_d=inf` 那条才是安全的）。测试盲区：只注入过 `dB_meas` 的 NaN，从未注入 `g_d`（而 `g_d` 恰恰来自离线管线这条外部数据通路）。
- 后果链：断线补 NaN → EMA 恒 NaN → guard 恒触发 → 闭环静默退化为纯前馈甚至下发 NaN 位姿，**全程无告警**。

**R3 · `to_waypoints()` z 符号自相矛盾 + 缺帧变换**（`strokeplan.py:54-58`）
同一个函数里两套 z 语义：抬笔点 `z_surface + lift` 用 B1 帧（z 大 = 离纸），压笔点 `z_surface + z_ff` 里 `z_ff` 是正压深（z-control 帧，z 大 = 压深）。按 B1 帧读 → 笔全程在纸面之上，一滴墨不落（`write_openloop.py` 的 `n_down` 数出 0）；按 z-control 帧读 → "抬笔"变成 15mm 深压。另缺 `CHAR_ORIGIN` 帧变换：直接吐示范原始坐标（合成示范 x∈[0,4cm]，在机器人底座里面），真喂 `Scene.ik()` 解不出。而"Q4 B1 兼容"验收（`tests/test_strokeplan.py:64-73`）只手搓 `OpenLoopController.step` 走了 1cm、断言"z 在 0.19~0.22 之间"，绕过了 Scene/IK/render 整条链——**形状级兼容，不是链路级**。这条至今零成本，是因为没人真跑过它；真机第一跑必现形。

**R4 · S_cal 整表割线隐含"标定曲线是直线"**（`z_control.py:61-64`）
`S_cal = (z_max−z_min)/(dB_max−dB_min)` 是跨全表割线。Phase 1 全部扫描用的是完美线性合成表（0–5mm ↔ 0–250µT），此时割线≡局部斜率，kp 的语义严格成立。真实曲线不是直线——同仓 `calligraphy/calibration.py:4-11` 自家的 `func_brush` 分段斜率差 ~4×。局部斜率/割线一旦 4×，有效环路增益就是 4×kp，层 1 辛苦保出的"2 倍裕度"当场吃穿。**9.47%、116°、残留 45% 全部数字都站在这个未声明的假设上**。E2 真实标定到位时这是第一个要重审的口径。

### 2.2 中危 —— 脱节类（会话接缝处的系统性问题）

**R5 · 闭环链路绕开了 backends 抽象，HuayanBackend 契约只写了一半**
`sim_loop.py` 自建 `Plant`，全链不 import `backends`、不用 `State/Command`（grep 确认 `z_control/sim_loop/demo_pipeline/strokeplan` 零引用）。于是开环臂说 `Command(tcp_pose)`、每拍调 `backend.read()` 两次并靠 `state.t` 驱动弧长；闭环臂（runtime spec）不调 `read()`、时基走 `Clock`。spec §5 的 HuayanBackend 五条契约**只覆盖 write 侧**，开环臂赖以生存的 read 侧（`State.t` 从哪来、read 是否 TCP 往返、每拍两次是否可接受）只字未提。`backends/base.py` 两行协议撑不起两条语义链。附带：`State.g_meas` 在 runtime 设计下成为永久为 0 的死字段，与 `backends/sim.py` 注释（"B2 换成真实 g_meas 流"）互相矛盾。
另外 `docs/brushbot-code-guide.md` §3 还在宣传"上实机只换 backends 层"——与现实冲突，会误导后续会话。

**R6 · "两臂共享前馈由数据结构保证"目前不成立**
这是 status 文档里 StrokePlan 契约的核心卖点，但 Q3 两臂彩排的开环臂（`scripts/demo_target_pipeline.py:80`）没走 `to_waypoints()`，而是 `z_open = 0.20 + calib_lookup_z(g_d)` 现场重算——**`Stroke.z_ff` 字段在整条 E2E 里一次都没被读过**（全仓端到端零消费，只有一个范围断言）。两臂实际共享的是 `g_d` 数组 + `calib_lookup_z` 函数。本期标定表恰好线性，`lookup(interp)≡interp(lookup)` 数值上看不出差别；**换真实非线性标定表两条路径就会分叉，而分叉量会直接混进论文核心数字（开/闭环差值）**，现在没有任何测试锁住这个等价性。

**R7 · 滤波器：归属倒置 + 两个频域基**
- 归属倒置：`filter.py` 里只有 Butterworth/OneEuro，**定稿的主力控制滤波器 EMA 住在 `monitor/core.py`（GUI 包）**，被控制侧 5+ 处 `from brushbot.monitor.core import EMA`；α=0.3 靠字面量在各处各写一遍，无单一常量源。`feat/monitor-filter-ui` 分支又让 `monitor/core` 反向 import `brushbot.filter`，依赖方向开始打结。
- 口径分裂（更实质）：目标曲线 `g_press` 是被 **fc=3 零相位砖墙**塑形的，闭环测量走 **EMA α=0.3**（有相位滞后，等效 −3dB≈5–6Hz）——目标与测量活在两个频域基里，这份系统偏差被算进 Q3 的 10.60% 但**没有任何文档把它单列为误差来源**。另：GUI 接触门用面内 `mag_xy`，管线/控制器用三轴全模 `|ΔB|`——同一个"接触判定"两个物理量。
- 离线砖墙滤波在 `sim_loop.py` 和 `scripts/compare_filters.py` 有逐字双份（注释自承）。

**R8 · tactile/（MuJoCo）与控制/管线是平行世界，真实数据无生产者**
- `tactile/antenna_model.py` 自承输出**任意单位**；`scripts/demo_z_control.py:50` 是它与 `ZController` 之间唯一连线，靠"噪声=峰值 2%"把量纲问题掩盖成相对量——混入真实 µT 数据会静默错配。Phase 1 结论与 MuJoCo 完全无关（用手编线性表）。"模型单位→µT"的换算三处各自打补丁（UDP 桥 spec 的 DEFAULT_SCALE、`synth_writing_B` 的 400µT、demo 的 2%），无统一标定层。
- **录制格式对不上管线输入**：`monitor/recorder.py` 落 5 列（`t_us,t_s,dBx,dBy,dBz`），`demo_pipeline.py` 硬性要求 7 列（多 `x_m,y_m`）且 fail-loud。管线输入的唯一生产者是合成脚本；磁数据与机械臂 FK 是两个异步源，中间必需的时间对齐/重采样层**零代码**——这是换真实示范数据时最先撞墙的地方。
- monitor 与 sim_loop/tactile 之间无任何实时通路（UDP 桥确系"spec 已写未实现"，属实）。

**R9 · 出厂默认增益 ki=0.134 从未被全场景复跑**
`z-phase1-results.md` 的生成命令是 `--ki-pi 0.005`：闭环 RMS 9.47%、相位裕度 116°、Q3 扰动表、Q4 freeze PASS（0.194mm）**全部是 ki=0/0.005 口径的数字**，不是出厂配置的。出厂 ki=0.134 仅有的两处数据：多笔画收敛表（通过）和 freeze 毛刺 **0.2434mm——恰好超 0.2mm 暂定上限**（已列开放项，但要清楚：**出厂配置下已知的唯一逐拍指标是超线的**，而"PASS"结论属于另一个配置）。论文引用这些数字时必须写清口径。

**R10 · 参数回填不完整、复跑脚本默认值带坑**
- `z_control.py:31` `noise_std` 默认仍是裸态的 7.0，**未回填滤后 3.31**——`handoff-z-phase1.md` §3.1 自己警告过"忘了改等于白滤"，恰好踩中。接触/freeze 门限因此偏保守 2 倍多（叠加 R11 的 σ 口径问题）。

- `scripts/demo_z_control.py` 仍是"Phase 0、无滤波"版本，未随 Phase 1 更新。
