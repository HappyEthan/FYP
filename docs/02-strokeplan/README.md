# 02 · StrokePlan

现行 StrokePlan 统一采用格式版本 3：保存笔画的 XY、时间和目标磁响应，执行时先插值目标，再查独立前馈表得到 Z。`z_ff` 是否在未来进入计划、学习所需 Z 标签如何定义，仍待接口裁定。

先读[现行说明与设计](strokeplan.md)，完整阶段关系见[根计划](../../plan.md)。`archive/` 中的旧实施记录仅用于追溯，不定义现行接口。

## 项目目的

定义机器人复现单笔和整字时需要的可执行信息，并为数采、控制算法和后期 Transformer 提供稳定的数据契约。

## 范围

- 区分逐点、逐笔和整字层级的数据。
- 定义几何路径、时间、速度、提按目标、坐标系和元数据。
- 讨论笔杆姿态的表示、来源、缺失策略与版本兼容。
- 定义从模板、图像或示教数据生成可执行 StrokePlan 的边界。

本项目不负责训练 Transformer，也不负责具体机械臂控制律。

## 输入、输出与依赖

- 输入：字帖图像、笔画模板、示教轨迹、触觉曲线和标定信息。
- 输出：带版本的数据契约，以及可供 Robot Control 消费的 StrokePlan。
- 依赖：Data Acquisition 证明字段可采；Robot Control 证明字段可执行。

## 当前讨论重点

在初步对应关系和重复性验证后，检查 Bxy 目标、独立前馈表与执行时派生 Z 的关系；再判断 `z_ff` 是否需要随计划保存，以及实际测得的 Z 在学习数据中应如何记录。离线实现和真实执行证据应分别说明。逐点姿态与动态姿态留到后续研究；当前前馈表仍须记录适用姿态。

## 已知限制与后续讨论

- 单凭最终墨迹图像不能唯一恢复速度、压力或笔杆姿态。
- 计划目标与实验日志必须分开，不能把实测反馈写回目标契约。
- 存储频率与控制频率可以不同，但插值和时间语义必须明确。
