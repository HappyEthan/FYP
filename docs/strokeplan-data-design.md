# 汉字复现所需的 StrokePlan 数据设计

> 定义：在本项目中，`StrokePlan` 就是笔画数据集。它同时保存 XY 几何路径和沿路径变化的控制参考，不再把“路径数据”和“StrokePlan”视为两套独立数据。

## 1. 核心结论

单一 XY 路径只能规定笔尖经过哪里，通常不足以复现毛笔书写的细微效果。

同一条 XY 路径在不同的接触强度、移动速度、笔杆姿态和轴向旋转下，可以形成明显不同的墨迹。因此，可执行的笔画至少应描述：

\[
\text{StrokePlan}
=
\text{几何路径}
+
\text{时间规律}
+
\text{接触参考}
+
\text{工具姿态}
\]

但是不建议一开始把所有自由度都加入闭环。应把数据格式设计得可以扩展，实验则逐级增加控制量。

## 2. 为什么 XY 不足以唯一复现墨迹

对毛笔而言，最终墨迹可近似理解为：

\[
I
=
F\bigl(x,y,v,g,\alpha,\beta,\psi,\text{brush state},\text{ink state}\bigr)
\]

其中：

- \(x,y\)：笔尖或工具中心在纸面内的位置；
- \(v\)：沿路径运动速度；
- \(g\)：磁传感器表示的接触/变形状态；
- \(\alpha,\beta\)：笔杆倾角；
- \(\psi\)：绕笔杆轴线的旋转；
- `brush state`：毛笔弯曲、散开和历史变形；
- `ink state`：含墨量、纸张吸墨等状态。

仅记录 \((x,y)\) 时，系统不知道在该位置应该压多深、走多快、向哪个方向倾斜，也不知道是否需要旋转笔杆。因此它最多复现几何骨架，不能保证复现笔画宽度、折角形状和锋向。

## 3. 建议的数据层级

```text
CharacterPlan
├── character_id / label
├── coordinate_frame / scale
├── brush_and_sensor_metadata
└── strokes[]
    ├── stroke_id
    ├── execution_order
    ├── samples[]
    └── optional metadata
```

一个汉字包含多条 `Stroke`，每条 `Stroke` 是一段连续接触轨迹。笔画之间允许机械臂在安全高度移动，但这些安全动作不需要作为书法语义建模。

## 4. 每个采样点建议保存的信息

### 4.1 第一层：当前实验必需字段

建议当前每个采样点至少包含：

\[
q_i=
\left[
s_i,
x_i,
y_i,
t_i,
g_{d,i}
\right]
\]

| 字段 | 含义 | 是否为原始参考 |
|---|---|---|
| `s` | 归一化累计弧长 | 是 |
| `xy` | XY 路径坐标，单位 m | 是 |
| `t` 或 `speed` | 时间戳或期望切向速度 | 是 |
| `g_target` | XY 磁场变化模长目标，单位 µT | 是 |

这四类信息分别解决路径、采样对齐、运动节奏和接触状态问题。

### 4.2 第二层：调锋和折笔所需的可扩展字段

如果实验确认仅靠 XY、速度和一个磁强标量不能复现折笔或锋向，再增加：

| 字段 | 含义 | 用途 |
|---|---|---|
| `roll_pitch` | 笔杆倾斜姿态 | 改变笔锋受力方向和笔画边缘 |
| `yaw` 或 `twist` | 绕笔杆轴线旋转 | 主动调锋 |
| `g_vec_target` | 目标磁场变化向量 \((\Delta B_x,\Delta B_y)\) | 同时表达变形强度和方向 |
| `contact_mode` | 接触/非接触 | 区分有效书写样本与笔间移动 |

这里不必给字段贴上“起笔、行笔、收笔”等语义标签。它们只是连续的物理控制参考。

## 5. 目标磁强与前馈压深的关系

当前结构同时保存 `g_press` 和 `z_ff`。二者不应被视为两个互相独立的真实标签。

建议定义：

- `g_target` 是 StrokePlan 中的主要接触参考；
- `z_ff` 是由当前装配和标定模型计算出的派生量或缓存；
- 在线反馈根据 `g_target` 修正 `z_ff`。

\[
z_{ff,i}=f_{cal}^{-1}(g_{target,i})
\]

\[
z_{cmd,i}=z_{surface}+s_z\left(z_{ff,i}+z_{fb,i}\right)
\]

这样更换毛笔、磁铁、传感器或重新装配后，可以用新标定重新生成 `z_ff`，而无需修改原始的 `g_target` 曲线。

如果未来的数据由机械臂示教直接采集，也可以同时保留演示 Z 轨迹，但应命名为 `z_demo`，避免和标定前馈 `z_ff` 混淆。

## 6. 时间信息不能只放在整条笔画的 duration 中

目前代码只在 `meta['stroke_durations_s']` 中保存每条笔画总时长，然后按弧长均匀回放。这等价于假设整条笔画速度恒定。

对圆形验证，这个假设合理；对折笔和复杂汉字则可能不足。折角附近常需要减速，而长直段可以更快。因此建议保存每个采样点的时间戳：

\[
t_0=0<t_1<\cdots<t_{M-1}
\]

或者保存期望速度：

\[
v_d(s)=\frac{ds_{metric}}{dt}
\]

推荐保存 `t`，运行时可以直接按时间插值；速度可以由 \((x,y,t)\) 求得。整笔 `duration` 则作为校验和元数据保留。

## 7. 折笔不等于必须增加书法阶段分类

折笔可以用连续控制参考表达，不需要先把它分类为某个书法动作：

- XY 曲线给出折角几何；
- 时间曲线在折角前后调节速度；
- `g_target(s)` 调节接触强度；
- 如果固定姿态仍不足，再加入姿态或磁场方向参考。

因此“不要研究起笔/行笔等阶段”和“复现折笔细节”并不矛盾。前者是不做语义分类，后者是保存足够的物理轨迹信息。

## 8. 磁强标量的能力边界

当前使用：

\[
g_{xy}=\sqrt{\Delta B_x^2+\Delta B_y^2}
\]

它适合表示总体横向变形强度，并用于单输入单输出的 Z 接触闭环。但求模后会丢失方向：

\[
(\Delta B_x,\Delta B_y)
\longrightarrow g_{xy}
\]

多组不同方向的磁场变化可能具有相同模长。因此：

- 若目标只是稳定接触和笔画粗细，`g_target` 标量可能足够；
- 若目标包括细微调锋和弯曲方向，单一模长可能不够；
- 在确认不足之前，应同时记录原始 \(\Delta B_x,\Delta B_y,\Delta B_z\)，即使第一版控制器只使用 \(g_{xy}\)。

保留原始向量不会迫使当前控制器变复杂，却能避免以后重新采集数据。

## 9. 推荐的 StrokePlan V3 概念结构

```yaml
format_version: 3
character_id: example
coordinate_frame: paper
units:
  position: m
  time: s
  magnetic_field: uT
metadata:
  source: demonstration_or_generated
  brush_id: optional
  sensor_id: optional
  calibration_id: optional
strokes:
  - stroke_id: 0
    execution_order: 0
    s: [...]                 # M
    xy: [[x0, y0], ...]      # M x 2
    t: [...]                 # M，推荐新增
    g_target: [...]          # M，主要接触参考
    z_ff: [...]              # M，由 calibration_id 派生/缓存
    orientation: null        # 可选，M x 3 或四元数
    g_vector_target: null    # 可选，M x 2/3
```

实际 `.npz` 可以继续使用，不要求改成 YAML；上面的结构只是为了说明字段含义。

## 10. 哪些字段属于计划，哪些属于实验日志

不要把参考量和测量量混在同一个数组中。

### StrokePlan：执行前已知

- `xy_ref`
- `t_ref`
- `g_target`
- 可选姿态参考
- 标定标识及 `z_ff`

### ExecutionLog：执行时采集

- 实际 TCP 位姿；
- 原始磁场 \(B_x,B_y,B_z\)；
- 基线后的 \(\Delta B_x,\Delta B_y,\Delta B_z\)；
- 实际 \(g_{xy}\)；
- `z_cmd`、反馈修正量、误差；
- 时间戳、限幅和异常状态。

二者分开后，才能比较“要求机器人做什么”和“机器人实际上做了什么”。

## 11. 建议的渐进式验证

### V1：验证通用执行框架

使用圆形：

- `xy(s)`：解析圆；
- `t(s)`：恒定切向速度；
- `g_target(s)`：常数；
- 姿态：固定。

验证 XY 执行和 Z 接触闭环。

### V2：验证变接触参考

仍使用圆，但令：

\[
g_target(s)=g_0+A\sin(2\pi s)
\]

这样无需汉字数据，就能验证 StrokePlan 是否能够按路径位置播放变化的接触目标。

### V3：验证折角

使用折线、L 形或带圆角的矩形，加入折角减速，同时保持姿态固定。由此判断 XY、速度和 `g_target` 是否已经足够。

### V4：判断是否需要姿态/方向控制

如果 V3 的几何和接触跟踪都正确，但墨迹锋向仍无法复现，再引入倾角、旋转或磁场向量参考。不要在证据出现之前直接增加多自由度闭环。

### V5：接入汉字 StrokePlan

把汉字的多笔画数据转换成同一格式。底层执行器不区分“圆”“折线”或“汉字”，只消费统一的 StrokePlan。

## 12. 当前代码的具体修改方向

现有 `Stroke`：

```python
s
xy
g_press
z_ff
```

建议下一版首先变为：

```python
s
xy
t
g_target
z_ff
orientation = None
g_vector_target = None
```

优先级如下：

1. 将 `g_press` 重命名或明确为 `g_target`；
2. 增加逐点 `t`，支持非恒速轨迹；
3. 保留 `z_ff`，但明确其为标定派生量；
4. 保存完整磁场向量到执行日志；
5. 为姿态和磁场方向预留可选字段，暂不强制使用。

## 13. 最终建议

需要优化现有 StrokePlan，但不建议推翻重做。

当前最合理的定义是：

> `StrokePlan` 是完整的可执行笔画数据集。每条笔画至少包含按顺序排列的 XY 位置、逐点时间以及逐点目标磁强；前馈压深由标定关系派生。姿态和磁场方向作为可选扩展，用实验判断是否需要启用。

第一版圆形实验验证的是这个数据契约和底层控制器。之后的折线实验负责判断细微折笔是否需要额外的姿态/方向自由度，最后再接入真实汉字 StrokePlan。

## 14. 定稿：单个时间点究竟保存什么

概念上，`StrokePlan` 的一条笔画可以看作按时间排列的 list：

```python
stroke = [
    {"t": t0, "x": x0, "y": y0, "g_target": g0, "z_ff": z0},
    {"t": t1, "x": x1, "y": y1, "g_target": g1, "z_ff": z1},
    ...
]
```

但在 NumPy 中更适合保存为长度相同的数组，而不是 Python 字典 list：

```python
t.shape        == (M,)
xy.shape       == (M, 2)
g_target.shape == (M,)
z_ff.shape     == (M,)
```

第 \(i\) 行必须表示同一时刻：

\[
q_i=(t_i,x_i,y_i,g_{d,i},z_{ff,i})
\]

其中需要严格区分三种 Z/接触数据：

- `g_target[i]`：StrokePlan 保存的目标接触状态；
- `z_ff[i]`：由标定模型生成的前馈压深；
- `z_cmd[i]`：运行时由前馈和反馈共同生成，不应提前存在 StrokePlan 中。

运行时：

\[
z_{cmd,i}=z_{surface}+s_z\bigl(z_{ff,i}+z_{fb,i}\bigr)
\]

所以“每个时间点包括 XY、g、z”基本正确，但这里的 `z` 应明确叫 `z_ff`，而不是最终机械臂 Z 命令。

## 15. 频率和一秒笔画的长度

当前项目配置为：

| 环节 | 当前频率/周期 | 来源 |
|---|---:|---|
| 传感、滤波、仿真控制主频 | 100 Hz | `config.FS = 100.0` |
| 华沿/Elfin 真机伺服周期 | 20 ms = 50 Hz | `HUAYAN_SERVO_DT = 0.02` |

若某条笔画执行时间为 \(T\)，按执行频率 \(f\) 展开后的命令点数约为：

\[
N=\operatorname{round}(Tf)
\]

因此一秒笔画：

- 按当前软件默认 100 Hz：笔画本体为 100 个样本；
- 当前代码还默认在每笔后加入 0.5 s 间隔，因此共生成 \(100+50=150\) 拍；
- 按真机 50 Hz：笔画本体应为 50 个机械臂命令点；0.5 s 间隔再增加 25 拍。

注意：一秒不是生成 101 个点。当前代码使用 `int(round(T*fs))`，所以 1 s、100 Hz 明确生成 100 个笔画样本。

## 16. StrokePlan 的存储频率不必等于机械臂频率

建议把两件事分开：

1. `StrokePlan` 保存足够密的支持点和真实时间戳；
2. 执行器按照目标设备频率对 `t, xy, g_target, z_ff` 同步插值。

这样 StrokePlan 是设备无关的数据集。相同的一条计划可以在 50 Hz 真机、100 Hz 仿真或其他频率下回放，而不用保存多个版本。

如果数据采集本身是 100 Hz，可以保留全部 100 Hz 数据。真机执行前把它插值到 50 Hz；不建议简单地每隔一个点删除，因为后续若频率不是整数倍会产生时间错位。

## 17. 与当前机械臂控制代码的兼容性

### 已经兼容的部分

现有 `Stroke` 已包含：

```python
s, xy, g_press, z_ff
```

`to_gd_series()` 会把 `xy` 和 `g_press` 按指定时长、指定 `fs` 同步插值。`TactileExecutor` 每拍读取相同下标的 `xy` 和 `g_d`，再由控制器在线生成 `z_cmd`。因此“XY + 目标磁强 + 前馈 Z”的基本思路与当前控制算法一致。

### 尚不完全兼容的部分

1. 当前 Stroke 没有逐点 `t`，只能通过 `s` 和整笔时长回放，等价于默认沿路径恒速；
2. `TactileExecutor` 默认 100 Hz，并且每拍都调用一次 `backend.write()`；
3. 真机伺服明确配置为 50 Hz，因此默认执行频率与真机下发频率不一致；
4. 当前日志使用三轴磁场模长，需要按项目定义改成 XY 模长；
5. `z_ff` 的压深正方向和物理世界 Z 轴符号仍需在真机入口统一。

### 推荐的最终频率架构

```text
StrokePlan（带时间戳，设备无关）
                 │
                 ├── 传感器采集/滤波：100 Hz
                 │
                 └── 机械臂控制与命令：50 Hz（20 ms）
```

每个 20 ms 机械臂控制周期内，可消费这段时间到达的全部传感器样本，更新滤波状态，然后使用最新滤波值计算一次反馈并下发一次机械臂命令。

第一版真机应统一为：

\[
f_{robot}=f_{controller}=50\ \text{Hz},\qquad
f_{sensor}=100\ \text{Hz}
\]

此时 1 秒笔画下发 50 个 XY/Z 位姿命令，但大约使用 100 个磁传感器样本。这样符合当前实测得到的 Elfin 20 ms 伺服周期。
