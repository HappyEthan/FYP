# Transformer 示教-复刻系统 设计（2026-08-24）

> 一句话：人类用触觉毛笔手写一个字（传感器录时序 + 收笔后照一张相），一支 transformer 把"触觉切分的笔画 × 照片的真实几何"融合成 StrokePlan（每笔折线 + 长宽位 + 按压曲线），Elfin5 用现成的 z 轴触觉闭环复刻。目标是**忠实复刻这一次的手写**，不是泛化新字。
> 代码基线：`src/brushbot/`（StrokePlan `strokeplan.py`、Z 闭环 `z_control.py`、开环写字 `examples/write_air.py` + `calligraphy/hanzi.py`）。

---

## 0. 背景与目标

- 历史执行侧设想为前馈主导、PI 修正磁目标残差；旧式 Z 正负号和当时的实现状态不再作为现行接口。当前正向下压深及 Base Z 命令关系见 `docs/04-robot-control/archive/z-control-design.md`。
- 本项目目标 = **复现（Motion Copy）**：示范臂（人手执笔，传感器在笔里）写一个字，复刻臂（Elfin5 夹持的毛笔）照样子写出来，粗细靠闭环压深复现。
- 本设计填补的正是"示范 → 可执行 StrokePlan"这一段（plan.md B4 / 契约2 的真实生产者）。

## 1. 范围与非目标

**范围内**
- 一支 transformer，输入（照片 + 触觉切好的笔画序列），输出（字识别 + 每笔路由 + 类型 + 长/宽/位 + 按压曲线目标），构成 StrokePlan。
- 复刻侧复用现有 z 闭环，只做接口对接，不改控制律。

**范围外（升级项，不阻塞本设计）**
- 泛化新字（B4）——本设计只管忠实复刻，不做"没见过的字也能写"。
- 笔锋姿态 `φ(s)`（B4 v2）、运笔节奏学习。
- F/T 安全网（仅当 E1 失败才触发，与本设计无关）。
- 在线/实时解释——示范分析是离线批处理。

## 2. 总体架构与数据流

```
┌─ 示范侧（人执笔手写）────────────────────────────────────────────┐
│  触觉流 t,Bx,By,Bz ──► 切笔画: 每笔{顺序, 类型(φ+按压判别),         │
│                          按压曲线 |ΔB|(s)}                          │
│  一张照片（收笔后拍）──► 阈值→连通域→骨架化→拓扑图                   │
└───────────────────────────────────────────────────────────────────┘
                              │  两路都进 transformer（离线）
                              ▼
┌─ 解释侧（transformer，唯一学习核心）───────────────────────────────┐
│  输入: 照片特征(CNN) + 骨架图 G + 触觉笔画 token 序列                │
│        （触觉 token 自带 顺序/类型，模型消费为路由先验，不重预测）     │
│  输出: • 每支示范笔画 k ↔ 一条"路由"（骨架图里的有序边序列）          │
│        • 每笔 长/宽/位置（从路由路径读出，不生成坐标）                │
│        • 每个路由笔画带上输入那侧的类型标签 → 打包进 StrokePlan       │
│        • 字识别（辅助头，低置信回退纯几何）                           │
└───────────────────────────────────────────────────────────────────┘
                              │  路由 + 属性 + 按压曲线 = StrokePlan
                              ▼
┌─ 复刻侧（Elfin5）─────────────────────────────────────────────────┐
│  每笔 2D 折线按弧长 s 匀速走; z 轴 |ΔB| 闭环跟示范按压曲线            │
│  （z-control.md 那套，装配态 E2 标定后启用）                          │
└───────────────────────────────────────────────────────────────────┘
```

核心边界：**transformer 不生成任何几何坐标**——几何 100% 来自照片（CV 前端）与触觉（按压缩放曲线）；transformer 学的只是"墨 ↔ 笔"的对应（cross-attention 路由）。

## 3. 模块规格

### 3.1 示范侧：触觉流 → 笔画（依赖：队友 A1/A2 + 本侧传感/滤波）
输入：`t,Bx,By,Bz` 连续流。产出三样：
1. **切笔画**：按压阈值迟滞切分（复用 build_plan 的标度阈值思路），得`stroke_id` 与每笔时间窗。
2. **类型判别**：由形变方向 `φ`（A2 已有"多轴 ΔB → 幅值 g + 方向 φ"）与按压签名判横/竖/撇/捺/…。**这是一个待真实验证假设**（见 §8），若实际只强到"起收笔"，路由监督变弱但架构不变。
3. **按压曲线**：笔画内 `|ΔB|(t)`，按弧长重参数化为 `|ΔB|(s)`，`s∈[0,1]`。

**滤波两口径（沿用现有定稿，勿混）**：按压曲线是**离线**目标 → 零相位砖墙 `fft_lowpass`；复刻臂控制环 → EMA α=0.3（装配态 E0 复测前勿定稿）。先滤向量再取 norm 的铁律不变。

### 3.2 CV 前端：照片 → 骨架图（零学习、确定性）
```
照片 → 灰度+自适应阈值 → 墨迹二值 → 连通域 → 骨架化(Zhang-Suen)
     → 拓扑图 G = {节点 V: 端点/交叉点, 边 E: 有序像素路径}
     → 每条边上每点附带粗细 = 2×距离变换（墨迹宽度）
```
- 输出结构固定：就是一个图 G（节点 + 带宽度剖面的像素路径）。transformer 不接受任意形状输入。
- **宽度天生在这里**：距离变换沿骨架取 2× 即墨宽剖面，不靠模型猜。

### 3.3 transformer：骨架路由（唯一学习核心）

**输入三件套**
1. **照片**：CNN backbone（小 ResNet 级）出特征图 + "字框"全局 token。
2. **骨架图 G**：每条编码成 token = 像素路径 + 宽度剖面 + 方向签名（沿边的角度直方图，告诉模型横竖朝向）。
3. **触觉笔画序列**：每笔一个 token = {顺序、类型、时长、|ΔB| 剖面摘要、φ 方向签名}。

**输出与训练目标**
- **路由主任务**：对每笔 k，autoregressive 地在 G 里选有序边序列（哪条边进、哪条边出、穿不穿交叉点）。stroke token 对 edge token 做 cross-attention 驱动选边；类型 + φ 当先验/监督。
- **属性是读出、不是生成**：路由定死后，长/宽/位置从路经的弧长/宽度剖面/包围盒直接读出。
- **字识别**：全局分类头，**辅助**用。置信度高才采信；低则回退纯几何，不当路由硬闸。

### 3.4 复刻侧：StrokePlan → Elfin5（复用，只接接口）
- 路点喂 `OpenLoopController` 按弧长匀速走（`controller.py`）。
- z 轴：示范臂 `|ΔB|(s)` 经相对归一后当复刻臂 `g_d`，闭环 `z_cmd` 用复刻臂自己的 E2 标定表（`z_control.py`）。姿态常量直通（`write_air.py` 现有做法）。

## 4. 坐标链与跨臂按压传递

**坐标链（确定性，不属 transformer 的活）**
```
照片像素 → homography（像素→纸面 mm）→ 字框内归一 → size/yaw → 机器人 Base 系(mm)
```
`write_air.py` 已有 size/yaw 缩放，只缺 homography 一档（前端标定，非学习）。

**跨臂按压传递（关键假设，需专门验证）**
- 示范臂录的 `|ΔB|(s)` 当复刻臂 `g_d`。两支笔物理不同 → 示范曲线**相对归一**（相对按压深度），复刻臂用自己 E2 `(ΔB↔z)` 落回 mm。
- 意味着**两个独立传感器**（示范臂 + 复刻臂各一支），不是共用。复刻后粗细能不能像，全押在这个假设上——E2 装配态标定后专门验（§8 假设 H3）。

## 5. 数据引擎与训练

**FYP 现实：真实手写量级 30–60 字 × 每字十几次 ≈ 数百~千级，不足以从头训练。** 用合成预训练把数据从"稀缺"变"无限"。

1. **合成预训练（占比大头，标注零成本）**
   用 `data/makemeahanzi/graphics.txt`（数千字每笔中线）+ `hanzi.py` 渲染/变换管线：渲染墨迹（描宽可变）→ 走**同一个 CV 前端** → 得到与真实同格式的图结构与边 token。合成数据的路由真值**按构造已知**（渲染时哪条边属于哪笔已写入）。
   → 小路由 transformer 在成千上万合成字上预训练"图路由 + 字识别"；跨模态部分（cross-attention 对触觉 token）用**合成触觉 token**（渲染时的笔画参数生成）占位练熟。

2. **真实微调（量小，只承担域迁移）**
   几十字 × 每字十几次，处理真墨/真触觉/真抖动。触觉的顺序 + 类型（φ）当监督/先验；干净路由标签从**无交叉种子字**（一 二 三 川 工）的规则路由起步，逐步纳入交叉字。

3. **独立 eval 真值**：留一组真实手写人工标每笔路由，不混训练。自动标注可能自带噪声，不能用它自己验自己。

**设计判据：几何与路由结构在合成/真实之间共享同一套 CV 前端，域差只有墨迹质感 → 学习成本被压到只剩"跨模态路由"这一件事。**

## 6. 评估（三层，全机器断言）

示范端的"最后一张照片"天然当真值，复刻端再拍一张，两大图直接比。

1. **解释层**：手工标真值 eval 集，量 路正确率（笔↔折线配对）、交叉路由正确率、字识别准确率。**唯一需要人工的标注点**。
2. **计划层**：路由复原出的 StrokePlan vs 照片真实几何 → 每笔 长/宽/位置/形状 误差。
3. **系统层**：机器人写后拍照 vs 示范照逐像素 **IoU/SSIM + 提按复现误差**（对标 0.34N）+ 人眼评审 = plan.md B3 核心实验。

**纪律（吸取审计教训）**：所有数字**机器断言**（pytest 升级替换 `demo_target_pipeline` 的 print 式手法）、验收产物 npz/JSON 落盘入库。不能手抄。

## 7. 依赖与前置（含传感/滤波接口）

- **触觉流三样产出**（切笔画/类型/按压曲线）对应 A1/A2 + 本侧实时 `g_meas` 的传感/滤波动作——**真实微调 block 在这里，合成预训练与 CV 前端不依赖它**。
- 合成预训练 + CV 前端**现在就能并行开工**，不卡传感；建模可先行验证路由主干。
- 复刻侧 z 闭环装配态启用需 E2 标定（S_cal 割线口径重审，R4）。

## 8. 假设与风险（待验证）

| # | 假设/风险 | 验证时机 |
|---|---|---|
| H1 | 触觉 φ 能判别笔画类型（横/竖/撇/捺…），用于路由监督 | 真实传感流到位后；若只够"起收笔"，路由监督降级但架构不变 |
| H2 | 合成域 → 真实域的域差只有墨迹质感（同一 CV 前端承保） | 合成预训练 + 少量真实微调对比 |
| H3 | 跨臂按压传递：相对归一化 |ΔB|(s) 在复刻臂 E2 表下粗细可复现 | E2 装配态标定后专项 |
| H4 | 字符框/homography 精度足够（摄像头固定、纸固定） | 采集协议定型时 |
| R1 | 交叉/粘连笔画的 CV 初始骨架质量差→路由样本噪声 | 独立手工 eval 真值承保，不静默 |
| R2 | 真实数据太少 → 过拟合 | 字识别/路由均以合成为主 + eval 集把关 |

## 9. 与现有代码/契约的接缝

- **StrokePlan 契约不变**（执行器只认它）：新生产出来的就是 StrokePlan 产出物，`to_waypoints()` / `to_gd_series()` 原样消费。
- 新增模块建议独立包（如 `src/brushbot/teach/`），不污染 `z_control`/`strokeplan`。
- 单位纪律沿用：计算核心全 SI（米/µT/秒），边界一次换算。
- 身份与流程风险：沿用 risk-register 流程，实现期逐项 TDD、交付把"已做/未做/前提"写进 status，不把口头结论当下会话的既成事实。

## 10. 验收标准（摘要）

- **合成域**：路由 transformer 在合成 eval 集上路正确率、字识别准确率过定型阈值（阈值在实现 plan 里定）。
- **真实域（传感到位后）**：真实 eval 集上三层指标全部机器断言可复现；系统层 IoU/SSIM/提按误差对示范照成立。
- **三件套动作**：homography 标定脚本、合成预训练脚本、真实采集/微调脚本，各带评估入口。
