### 2. 技术选型

**PyQtGraph 原生窗口**（新增依赖：`pyqtgraph` `PyQt5` `pyserial`，均已验证可安装）。

| 备选 | 否决理由 |
|---|---|
| matplotlib 动画 | 100 Hz × 多面板会卡；暂停/缩放/折叠等交互需自行实现，体验差 |
| Python 后端 + 浏览器前端 | 需起服务器、两个进程；最大优势（跨平台）在本场景用不上；且不是原生窗口 |

<a id="source-1-3-架构"></a>
### 3. 架构

三层解耦，沿用仓库既有模式（算法/IO/界面分离）：

```
  信号源(可插拔)              核心(无 GUI, 可测)          界面(PyQtGraph)
┌──────────────┐         ┌──────────────────┐      ┌─────────────────┐
│ SerialSource │──┐      │  RingBuffer      │      │  XY 相图        │
│ ReplaySource │──┼─原始B→│  Baseline(B0)   │─ΔB→ │  ΔBx 时序       │
│ SynthSource  │──┤      │  派生量 |ΔB|,φ,θ │      │  ΔBy 时序       │
│ (MuJoCo 预留)│──┘      │  Recorder        │      │  ΔBz 时序(折叠) │
└──────────────┘         └──────────────────┘      └─────────────────┘
```

<a id="source-1-31-信号源接口"></a>
#### 3.1 信号源接口

```python
class Source(Protocol):
    def start(self) -> None: ...
    def read(self) -> list[tuple[float, float, float, float]]:
        """返回自上次调用以来的新样本 (t_s, Bx, By, Bz)。原始 B，非 ΔB。非阻塞。"""
    def stop(self) -> None: ...
    @property
    def info(self) -> dict:
        """{name, nominal_rate_hz, units, port?, ...}"""
```

**关键决定：信号源一律输出原始 B，扣基线由核心负责。** 理由：

1. 固件本就输出原始 B（`t_us,Bx_uT,By_uT,Bz_uT`），扣基线本就在上位机做；
2. 基线必须能**随时重取**（按钮）——若源直接吐 ΔB，重取基线无从谈起；
3. 回放也能重新调零：`ReplaySource` 把 CSV 里的 ΔB **加回** JSON 的 B0 还原成原始 B。
   默认基线仍取该 B0，故显示结果与原记录**逐点一致**。

三个实现：

| 源 | 说明 |
|---|---|
| `SerialSource` | pyserial 读 `/dev/ttyUSB0` @115200，按行解析 `t_us,Bx,By,Bz`，跳过 `#` 开头的表头 |
| `ReplaySource` | 读 V0 的 CSV+JSON，按记录的时间戳节奏回放；支持播放/暂停、变速、跳转（见 §4.3） |
| `SynthSource` | 先用 `brushbot.tactile.writing_tactile` 离线算出一整段写字的合成 ΔB 序列，再按标称 100 Hz **逐点流式吐出**（叠加标称 B0 还原为原始 B），行为上等价于一个"虚拟传感器" |
| `MuJoCoSource` | **仅预留接口**，待 Phase 3 的 ΔB 发散 bug 修复后实现 |

<a id="source-1-32-线程模型"></a>
#### 3.2 线程模型

**采集与重绘必须解耦**——若每来一个样本就重绘一次，100 Hz 重绘必然卡顿。

实现方式：**单个 Qt 定时器，约 50 FPS**，每次先把信号源里累积的样本一次性取走写入环形缓冲，
再重绘。环形缓冲为 numpy 定长数组（60 s @100 Hz = 6000 点，O(1) 写入）。

为什么不起独立采集线程：100 Hz × 约 30 字节/行 ≈ 3 KB/s，而 OS 串口缓冲通常 ≥4 KB，
50 FPS 轮询每次只需取走约 2 个样本，`pyserial` 非阻塞读足以覆盖；单定时器省掉了缓冲加锁与竞态。

> **已知代价**：若界面被阻塞超过约 1 秒（如弹出模态对话框），串口数据可能溢出丢失。
> 串口监控的正常流程不会开对话框，故可接受。若实测出现丢样，升级路径是把采集移入
> `QThread` 并给 `RingBuffer` 加锁。

<a id="source-1-33-基线-b0"></a>
#### 3.3 基线 B0

| 场景 | 行为 |
|---|---|
| 连接串口后 | 静置 1 s，自动取该秒均值为 B0，状态栏提示 |
| 手动 | `取基线` 按钮，取最近 1 s 均值 |
| 回放 | 初始用记录 JSON 中的 B0（与原记录一致），可重取 |

取基线的同时计算该秒的三轴标准差 σ，用作**方向门控阈值**（见 §4.2）。

> 依据：`docs/01-monitor-filter/sensor-v0-results.md` §6.1，跨会话 B0 极差达 93 µT，基线必须每次重取并随数据存档。

### 4. 界面

<a id="source-1-41-布局"></a>
#### 4.1 布局

```
┌ 工具栏 ─────────────────────────────────────────────────────────────────┐
│ 源[串口▾] 端口[/dev/ttyUSB0▾] [连接] │ [取基线] │ [●录制] [标记START/STOP] │
│ 动作名[line_lr] │ 时窗[10s▾] │ 拖尾[2s▾]                                  │
├────────────────────┬────────────────────────────────────────────────────┤
│                    │ ΔBx ┌────────────────────────────────────────────┐ │
│    XY 相图          │     └────────────────────────────────────────────┘ │
│    ΔBx – ΔBy       │ ΔBy ┌────────────────────────────────────────────┐ │
│    等比例·拖尾      │     └────────────────────────────────────────────┘ │
│    幅值刻度圈       │ ΔBz ┌──────────── ▸可折叠 ────────────────────────┐ │
│                    │     └────────────────────────────────────────────┘ │
├────────────────────┴────────────────────────────────────────────────────┤
│ |ΔB| 648.3  |ΔBxy| 574.3  φ 86.4°  θ 117.6°  ΔBx 36.3  ΔBy 573.2  ΔBz −300.9 │
│ ● 已连接 /dev/ttyUSB0 · 实测 100.0 Hz · 坏行 0 · 录制中 04.2s              │
└──────────────────────────────────────────────────────────────────────────┘
```

- **三个时序图各自独立 Y 轴自动缩放**——不共享量程，否则小分量会被大分量压平。
- 共享 X 轴（时间），滚动时窗可选 5 / 10 / 30 / 60 s。
- ΔBz 面板默认折叠。
- XY 相图：等比例，带拖尾（时长可选）、当前点标记、幅值刻度圈。
- 读数区：`|ΔB|`、`|ΔBxy|`、方位角 φ、极角 θ（与 +z 夹角）、三轴瞬时值。

<a id="source-1-43-按源切换的工具栏"></a>
#### 4.3 按源切换的工具栏

工具栏内容随所选信号源变化，不可用的控件置灰：

| 源 | 可用控件 |
|---|---|
| 串口 | 端口下拉、连接/断开、取基线、录制、动作标记 |
| 回放 | 选文件、▶/⏸、进度条、变速（0.25–4×）、取基线；**录制置灰**（回放不产生新数据） |
| 合成 | 选字/参数、▶/⏸、变速、取基线；**录制可用**（合成数据也可存档，JSON 中 `sensor` 标为 `synthetic`） |

<a id="source-1-42-方向门控"></a>
#### 4.2 方向门控

当 `|ΔB| < 3·‖σ‖` 时：φ / θ 读数显示 `—`，XY 相图不绘制方向线。
其中 `‖σ‖ = sqrt(σx² + σy² + σz²)`，即取基线那 1 秒内**三轴标准差的模**（与回放页口径一致）。

理由与回放页一致：幅值接近噪声时方向由噪声主导，绘制出来是**假信息**。
阈值按当天实测噪声自适应，不写死常数（V0 实测约为 20.8 µT，但换设备/配置会变）。

<a id="source-1-5-录制"></a>
### 5. 录制

**输出目录**：默认 `recordings/`（仓库根下，git 忽略），可在工具栏切换。

**`repetition` 编号**：写文件前扫描输出目录中同 `action` 的既有文件，取最大编号 +1，从 1 起。

停止录制时写出一对文件，字段与 `delta_b_v0_20260724/` 完全一致：

- `YYYYMMDD_HHMMSS_<action>_r<NN>.csv`，列 `t_us,t_s,dBx_uT,dBy_uT,dBz_uT`
- 同名 `.json`，含 `created_at / action / repetition / valid / sensor / board / port / baud /
  units / delta_definition / baseline_B0_uT / display_smoothing_applied / recording_mode /
  action_window_s / action_start_t_us / action_end_t_us / sample_count / measured_duration_s /
  mean_sample_rate_hz / max_interval_us / csv_file`

`标记START/STOP` 按钮写入 `action_window_s`（对应 V0 的人工标记）。

**收尾自检**：停止录制后立即用 `scripts/analyze_deltab.py` 的加载器回读刚写的文件对，
读取失败则在状态栏报警——避免录完才发现格式损坏。

<a id="source-1-6-错误处理"></a>
### 6. 错误处理

| 情况 | 行为 |
|---|---|
| 串口打不开 | 状态栏红字提示，不崩溃，可重选端口重试 |
| 采集中断线 | 停止采集；**安全收尾正在进行的录制**（JSON 标 `valid=false` 并注明断线原因）；状态转红 |
| 坏行 / 半行 | 计数并跳过（串口按行缓冲，正确处理跨包截断的行） |
| 实测频率偏离标称 | 状态栏显示实测 Hz；偏离 >2% 变黄 |
| 缓冲写满 | 环形覆盖最旧样本（设计如此，不报错） |
| 合成源异常 | 捕获并在状态栏显示，不影响已采集数据 |

> 日期：2026-07-29
> 分支：master（新分支 feat/monitor-filter-ui）
> 前置：`docs/01-monitor-filter/archive/filter-history.md`（滤波器库）、`docs/01-monitor-filter/filter-comparison.md`（选型报告）、`docs/01-monitor-filter/archive/monitor-history.md`（窗口现状）

<a id="source-2-1-背景与目标"></a>
### 1. 背景与目标

监控窗口目前用 EMA 批量重滤做显示平滑（`window.py:363-364`），滤波器库（Butterworth/OneEuro）已并入 master 但窗口未接入。

**目标**（三块，均为显示层改造）：
1. 工具栏滤波器选择器 + 原始信号淡色叠影，实时对比降噪效果与滞后代价。
2. XY 圆方向点改用选中滤波器，加最近 3 s 拖尾轨迹。
3. 回放进度条（可拖动 seek）。

**非目标**：
- 不改接触判定、门控、录制语义——**录制的永远是原始 ΔB**，滤波仅影响显示。
- 不做流式增量滤波（保持每帧批量重滤架构，见 §2）。
- MuJoCo 联动（UDP 桥 + SocketSource）为下一个独立项目。
- CLI 参数、XY 幅值刻度圈（用户明确不选）。

<a id="source-2-2-架构决策"></a>
### 2. 架构决策

**保持每帧批量重滤**：`_redraw()` 里 `filt.reset(); dB_smooth = filt.update(dB)`，与现状同构。理由：显示效果与流式一致；基线重取后下一帧自动用新 ΔB 重滤，无状态失配；改动最小。OneEuro 批量模式用固定 dt=1/fs（V0 实测 dt 抖动 <0.2%，可忽略）。

选"原始"时 `filt = None`，跳过滤波直接画。

<a id="source-2-3-滤波器选择器--叠影"></a>
### 3. 滤波器选择器 + 叠影

- 工具栏 "滤波α" 下拉（`cb_alpha`）替换为 "滤波" 下拉（`cb_filter`），选项与工厂：

```python
FILTERS = {  # label -> 构造函数(每次切换/连接时新建); None = 原始
    "原始": None,
    "EMA 0.3": lambda: EMA(0.3),
    "Butter 5Hz": lambda: ButterworthFilter(5.0),
    "Butter 8Hz": lambda: ButterworthFilter(8.0),
    "OneEuro": lambda: OneEuroFilter(0.5, 0.03),
}
```

- 默认选中 "EMA 0.3"（与现状行为一致，不惊动用户习惯）。
- 四个时序图（ΔBx/ΔBy/|ΔBxy|/ΔBz）各加一条原始曲线垫底：淡灰 `#8b949e`、宽 1、约 35% 不透明度；滤波曲线保持现有亮色在上层。选"原始"时叠影隐藏、只画一条原始色曲线。
- `derive()`/接触指示/状态栏读数继续吃**原始** `dB[-1]`，与录制一致。

<a id="source-2-4-xy-圆升级"></a>
### 4. XY 圆升级

- 删除独立标量 EMA（`_prev_norm`/`_xy_alpha`）与 "XYα" 下拉——方向平滑统一由滤波选择器负责。
- 方向点 = 滤波后最后样本 `dB_smooth[-1]` 的 (x, y) / `_norm_radius`。
- 拖尾：最近 `TRAIL_S = 3.0` 秒的滤波后归一化轨迹，半透明细线（方向点同色系、约 30% 不透明度）+ 现有端点亮点。数据直接从 `dB_smooth` 切片取，无新增状态。
- 拖尾无独立状态（每帧从 `dB_smooth` 重算），重放/断开/seek 后下一帧自动恢复；`_restart` 现有的 XY 清空逻辑保留不动。
- 选"原始"时方向点/拖尾用原始数据（行为等同现状 α=1）。

<a id="source-2-5-回放进度条"></a>
### 5. 回放进度条

- `sources.py` `ArraySource` 加公开属性 `progress -> float`（0~1，`_i / len(_t)`，空数组返回 1.0），配套单测。
- 窗口：工具栏下方一行 `QSlider(0..1000)` + 标签 `"%.1f / %.1f s"`，仅当 `src` 有 `seek` 时显示（回放/合成），串口隐藏。
- 播放中每 `_tick` 用 `blockSignals(True)` 更新滑块位置防回环；用户 `sliderReleased` → `src.seek(value/1000)`；seek 不改变暂停状态。
- 与既有 ⟳ 重放（seek(0)）、倍速、暂停共存，不改它们。

<a id="source-2-6-测试与验收"></a>
### 6. 测试与验收

## Monitor / Filter 设计审查与研究路线建议

来源版本：`2026-09-07-design-review.md`。

日期：2026-09-07。性质：当前工作区的审查结果和待讨论建议，不是已批准的实现规格。

<a id="source-4-结论与证据边界"></a>
### 结论与证据边界

当前系统可以作为磁信号观察、录制和滤波候选比较的基础；尚不能判定满足装配态触觉闭环或笔锋状态检测的要求。优先重构采样时间、数据留存、基线与信号语义，再决定界面外观和最终滤波参数。

本次读取当前工作区（含用户既有未提交修改），没有改动生产代码。复核 filter.py、monitor 各层、runtime.py、z_control.py、compare_filters.py、compare_z_arms.py、既有设计/报告及研究计划书。相关 99 项测试通过；未运行显示器 GUI 验收、装配态传感器或机器人实验。测试通过不代表下列设计要求已满足。

<a id="source-4-一gui-选型与边界"></a>
### 一、GUI 选型与边界

| 方案 | 适合情形 | 本项目取舍 |
|---|---|---|
| 保留 Qt Widgets + PyQtGraph，重构内部数据流 | 本机串口、连续曲线、实验操作 | 当前首选，复用现有 PyQt5；PySide6/Qt6 迁移可另立小任务 |
| NiceGUI 浏览器界面 | 远程查看、演示、统一 Python 开发 | 有明确远程需求时可选；后台采集和控制必须独立于网页生命周期 |
| FastAPI + React/Vue | 长期、多用户、复杂工作台 | 自由度高，但当前前后端与部署维护投入较大 |

Qt 的 worker object / queued signals 可用于隔离采集与界面；PyQtGraph 支持实时交互及降采样等绘图优化。[Qt 文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)、[PyQtGraph 文档](https://pyqtgraph.readthedocs.io/en/pyqtgraph-0.14.0/api_reference/graphicsItems/plotdataitem.html)。NiceGUI 基于 FastAPI、Vue/Quasar 与 Socket.IO，适合 Python 驱动的网页工作台。[项目说明](https://github.com/zauberzeug/nicegui/blob/main/README.md)

建议界面分为实时观测、标定实验、回放比较三个任务页。实时页展示原始/滤波三轴、物理单位下的 XY 相图、信号质量与基线状态；标定页引导空载、纯压入、纯拖动、压拖组合并记录事件；回放页比较同一原始记录的滤波配置和指标。控制配置与显示平滑分别标识。

<a id="source-4-二主要审查发现"></a>
### 二、主要审查发现

<a id="source-4-p1旧延迟要求与当前工作点不一致"></a>
#### P1：旧延迟要求与当前工作点不一致

旧设计 `design/2026-07-29-filter-design.md` 要求 3 Hz 信号带宽、滤波份额约 5–10 ms、总预算约 30 ms。对 EMA α=0.3 在 100 Hz 下直接计算：3 Hz 增益 0.88543、相位滞后 22.776°、相位延迟 21.089 ms、群延迟 17.213 ms。不能判为满足原延迟预算。

群延迟、正弦相位延迟、阶跃稳定时间和代码运行耗时是不同量。旧比较报告把 OneEuro 慢态等效群延迟 3.5 ms 用于 10 ms 预算，但同一等效模型的 3 Hz 相位为 75.3°（相位延迟约 69.7 ms），该论证无效；它也不是实际自适应动作的固定延迟。OneEuro 应报告分幅值/速度的输入输出动态响应。作者明确要求分别在慢速和快速运动下调参，且 beta 依赖输入单位。[原作者说明](https://gery.casiez.net/1euro/)

仅在 3 Hz 处算相位不足以证明闭环相位裕度，必须结合被控对象、控制器、采样保持、传输延迟和实际增益交越频率。建议先验证任务带宽与总延迟预算，保留 EMA 作为基线，不凭静态降噪改生产参数。

<a id="source-4-p1采样显示与回放时钟语义没有统一"></a>
#### P1：采样、显示与回放时钟语义没有统一

- `window.py:573` 起，GUI 的 20 ms 定时器串行执行读取、录制累积和重绘。暂停使读取停止，因此当前暂停不是独立的“冻结视图”。串口积压/丢失程度需实测。
- `window.py:607` 每帧 reset 后重滤当前窗口，窗口左边缘重新冷启动；窗口末端对 EMA 可能近似连续流，但不能当作严格相同的流式实现。
- `window.py:630` 附近 XY 平滑只更新最新点，频率取决于重绘；暂停后仍重绘，还可能反复滤同一旧样本。因此同名 alpha 不代表与时序曲线相同的动态响应。
- `runtime.py:177` 会处理所有新样本，这一点合理；但 ReplaySensor 丢弃源时间戳，滤波接口缺少时间与质量元数据。不能据控制频率直接推断滤波更新频率。
- `compare_filters.py` 固定 FS=100，读取 t 后没有据实际采样间隔设置滤波器/评估频率。更换采样率或带缺口数据后不能直接沿用结果。

例如同一个 EMA α=0.3 若实际仅每秒更新 50 次，其 3 Hz 增益变为 0.69132、相位延迟变为 33.730 ms。此为条件性数值示例，不表示当前所有执行路径都以 50 Hz 更新滤波。

<a id="source-4-p1磁场特征还没有被验证为物理提按笔锋状态"></a>
#### P1：磁场特征还没有被验证为物理提按/笔锋状态

`z_control.py:127` 使用三轴模长，GUI 接触指示使用原始 XY 模长与三轴噪声范数阈值比较（`window.py:652`）。二者统计口径不同。过阈值只说明磁特征较强；磁干扰、横拖、回弹残差也可能触发。

当前数据缺纯压入参考与压拖解耦，不能断言 |ΔB| 唯一映射压深或力，也不能把磁场方位角直接命名为中锋/侧锋。建议暂时显示“磁响应超过阈值”，在有独立接触标注后建立滞回、持续时间及质量门控的接触估计。

GUI 的 X 增益、负 Y 增益和边界钳位会改变显示几何；各轴 OneEuro 自适应增益不同也可能造成方向瞬态畸变。需保留物理原始视图，并把向量夹角误差纳入评价。若使用标定变换，应存版本、坐标系与拟合证据。

<a id="source-4-p1基线可靠性缺少条件约束"></a>
#### P1：基线可靠性缺少条件约束

连接约一秒后直接估计基线；`Baseline.take` 只检查形状/非空，未验证非有限数据、静止或脱离接触。动作中均值可能被误当空载零点。回放虽保留 B0，仍从起始窗口重估 sigma，窗口不一定静止。

应要求有效空载窗口，并记录 baseline_id、时间、样本数、协方差及质量；接触时冻结。长断流后的状态恢复与重新标定要有明确规则。不可自动去掉一切低频量，因为持续压入本身包含 DC/低频信号。

<a id="source-4-p2滤波器参数与评估契约不完整"></a>
#### P2：滤波器参数与评估契约不完整

- OneEuro 构造器接受 beta=-1、min_cutoff=NaN、fs=0（本次实测），update 未对 dt 的正有限性作检查。部分非法参数可能导致错误状态或运行时异常。
- 三类滤波器对非有限样本透传、状态不更新的策略已有测试，应保留；同时记录无效原因与缺口长度，不能把数值恢复等同于测量可靠性恢复。
- `compare_filters.py:94` 的 dynamic_rms 对照同一信号经 3 Hz FFT 截断的结果。这是参考模型偏差，不是独立真实运动误差，且有频带假设与边界效应。
- `recommend()` 按动态 RMS 和 100 ms 阶跃门槛筛选，没有直接实施原 5–10 ms 延迟要求。降噪和同截止砖墙 FFT 接近 10% 也不是普适正确性判据，不同传递函数的等效噪声带宽不同。
- `compare_z_arms.py:668` 仍默认 OneEuro，而生产工厂默认 EMA；运行报告必须明确参数和版本，避免使用不同配置的结果作同一系统证据。

<a id="source-4-p2记录足以复查-v0不足以支撑完整论文链路"></a>
#### P2：记录足以复查 V0，不足以支撑完整论文链路

现有 Recorder 保存未经显示滤波的 ΔB 和 B0，这是正确基础；可在记录精度范围内还原 B。它把数据先累积在内存，结束时写文件，长实验/异常退出缺少增量持久化。五列 CSV 没有机器人实测位姿、多源同步与状态估计字段。

建议增量保存原始传感流及时间信息，单独保存派生结果，用 run_id 关联计划、ExecutionLog、标定与墨迹图。不要把实测结果写回 StrokePlan。旧 V0 保留兼容读取，不假造缺失的机器人坐标。

<a id="source-4-p2旧文档对工频混叠的解释错误"></a>
#### P2：旧文档对工频混叠的解释错误

100 Hz 均匀采样下，50 Hz 位于 Nyquist，并不一般折回 DC。例如 cos(2π·50·n/100)=(-1)^n；某些相位的正弦采样可能全零。50 Hz 未充分滤波便抽取到 50 Hz 时才可能变成 DC；传感器内部采样/输出链路也需分别检查。不能笼统断言该工频分量都无法数字抑制。真正已混叠到任务频带的分量则无法仅靠后置低通恢复。[NI 采样与抗混叠说明](https://www.ni.com/en/shop/data-acquisition/measurement-fundamentals/analog-fundamentals/acquiring-an-analog-signal--bandwidth--nyquist-sampling-theorem-.html)

<a id="source-4-三建议的最小重构结构"></a>
### 三、建议的最小重构结构

1. Source：输出设备时间、主机接收时间、序号（设备支持时）、三轴 B、质量标志。
2. SignalPipeline：按每个新样本依次进行质量判断、基线处理、因果滤波、特征计算；固定采样滤波器明确采样率，变间隔算法使用设备时间差；长缺口按协议恢复。
3. Recorder：独立记录原始流、派生流、标定事件和配置；增量落盘，异常可恢复。
4. Controller adapter：50 Hz 消费最近的有效估计与样本年龄；保留 100 Hz 所有样本的滤波更新；控制动作与看门狗不由 GUI 定时器驱动。
5. GUI：20–30 Hz 获取快照绘图；暂停只冻结视图；显示降采样不丢采集/记录样本。
6. Replay / evaluation：复用 SignalPipeline 与原设备时间，倍速仅改变播放节奏；跳转明确重建历史状态或标记预热区。

验收重点：窗口长度/刷新率/暂停/回放倍速不改变同一时刻的处理结果；变更显示滤波不改变原始记录；超时、乱序、无效样本有可追溯标志；同一输入与配置离线可复现；GUI 卡顿时采集和控制继续按各自契约工作。

<a id="source-4-四面向会议论文的阶段路线"></a>
### 四、面向会议论文的阶段路线

暂按“触觉反馈改善书写质量与抗扰动能力”作为首篇论文主线，等待用户明确优先级。不要把换 GUI 或比较三个通用滤波器单独包装成主要贡献。

已有 E-Antenna 论文把磁触须嵌入刷毛，并通过触觉反馈调整机器人位置/姿态完成曲面刷涂。因此“毛笔中加入磁触觉并反馈”本身不足以构成新颖性主张。本项目应证明书法任务中时变提按、方向/状态信息及墨迹质量的新增收益；当前检索不足以宣称“首次”。[Ren 等，Nature Communications 2025，Fig. 7](https://www.nature.com/articles/s41467-025-58403-3)

| 阶段 | 最小实验/交付 | 放行依据 |
|---|---|---|
| A 可观测性 | 装配后电机关闭/开启静止/悬空运动；纯压入、不同方向拖动、压拖组合、加载卸载 | 用参考位移、侧视形变/接触标签，必要时参考力，验证灵敏度、迟滞、交叉敏感和重复性 |
| B 滤波选型 | 多会话独立记录；0.5/1/2/3 Hz 与小/中/大幅动作作为起始测试网格；含断流/尖峰 | 比较 raw、EMA、Butterworth、OneEuro 的噪声、幅相、事件延迟、向量方向误差及任务误差；阈值从需求和 pilot 确定 |
| C 最小闭环 | 同一 StrokePlan、同一 XY/速度/笔纸条件下固定 Z、标定前馈、前馈+触觉低增益反馈 | 在平面、可控纸高偏差/倾斜等条件下比较；没有足够感知证据前不开强反馈 |
| D 论文结果 | 预注册主指标、分组与异常处理；独立测试会话；配置/计划/日志/墨迹可追溯 | 报告效应量、重复间离散性与置信区间；样本量由 pilot 方差决定，时间点不当成独立重复 |

评价同时包含：触觉特征跟踪误差、独立位移/形变参考误差、接触事件、Z 平滑性、局部线宽/断笔/轮廓与中心线误差、失效/安全事件。滤波后的反馈误差不能单独作为胜负依据，避免平滑直接制造“更好指标”。IoU 也不足以单独表示书法质量。

如果论文强调“笔锋状态优于普通测力”，需加入可比的力反馈基线与独立笔锋状态标签；如果强调“优于视觉反馈”，就需要实际视觉反馈基线。只做开环对照只能支持相对开环的结论。Transformer 可在这条实验链成立后加入。

<a id="source-5-三种信号源"></a>
### 三种信号源

| 源 | 用途 | 录制 |
|---|---|---|

<a id="source-5-界面"></a>
### 界面

- **左**：ΔBx–ΔBy 相图，等比例，带拖尾与当前点。
- **右**：ΔBx / ΔBy 两个**独立 Y 轴**的时序图；ΔBz 勾选后出现。
- **状态栏**：`|ΔB|`、`|ΔBxy|`、方位角 φ、极角 θ、三轴瞬时值、缓冲计数、门控阈值。

<a id="source-5-基线与方向门控"></a>
### 基线与方向门控

每次连接（无论何种源）都会整体重置基线：连上后 1 秒自动取基线；任何时候可按「取基线」重取。
**回放源的特殊处理**：连接时立即从记录 JSON 读取 `b0` 为初值（使 ΔB 从第一帧起正确），但方向门控保持**抑制**（φ/θ 显示 `—`、不画方向线）直到 1 秒后的自动重取基线完成——因为初值 `b0` 之外还需测得噪声 σ 才能设门控。
取基线时同时测得噪声 σ，门控阈值 = `3·‖σ‖`。
当 `|ΔB|` 低于门控时，φ/θ 显示 `—` 且不画方向线——此时方向由噪声主导，显示出来是假信息。

<a id="source-5-录制"></a>
### 录制

先取基线 → 「● 录制」→ 动作开始时按「标记 START」、结束按「标记 STOP」→「■ 停止」。
输出到 `recordings/`，格式与 `delta_b_v0_20260724/` 一致，可直接被分析脚本消费：

```
python scripts/analyze_deltab.py recordings out.png
```

<a id="source-5-排错"></a>
### 排错

| 现象 | 处理 |
|---|---|
| `打不开信号源` | 确认串口路径与权限：`ls -l /dev/ttyUSB0`；必要时 `sudo usermod -aG dialout $USER` 后重新登录 |
| 曲线不动 | 确认已点「连接」；串口源需固件正在输出 |
| φ/θ 一直是 `—` | 正常——信号未超过噪声门控；或重新取基线 |
| `Could not load the Qt platform plugin "xcb"` | 需要图形界面，不能在纯 SSH 无 X11 下运行 |
