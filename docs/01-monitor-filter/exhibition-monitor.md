# 展示 Monitor：桌面架构、界面与交付

本文合并桌面展示工作站、视觉、人工页 Qt 规格和交付安排，归属 Monitor 展示支线。三页工作站与单人工页原型是两个范围不同的设计版本，不能把所有页面同时当作已交付功能。

## 版本与范围

| 版本 | 页面与职责 | 阅读定位 |
|---|---|---|
| 完整工作站 | 首页、人工信号观察、机械臂书写；由后端管理传感器和动作 | 展示系统总体设想 |
| 人工页 Qt 原型 | 启动直达人工页，只提供连接、取基线和信号显示 | 较小的独立交付规格 |
| 网页前端 | 使用相同后端状态与动作 API | 独立设计文档已删除；现行实现需核对 `src/brushbot/exhibition/` |

人工信号页不从磁信号恢复数字笔迹或识别汉字。XY 图显示 `ΔBx/ΔBy`，不是笔尖在纸面上的 XY 位置；“接触”来自后端判据，不能当作已标定的法向力。

## 组件与数据流

串口由后端 `SensorMonitorService/SerialSource` 持有；Qt 通过 HTTP/WebSocket 读取快照。采集、控制与 UI 刷新分开，前端只绘制最新快照，不把每个采样帧排入绘制队列。

`exhibition_monitor/` 的入口负责 QApplication，窗口绑定状态，theme 管理视觉，gateway 管理 HTTP/WebSocket 与重连，state_store 保存最新状态，sensor_panels 负责 XY/X/Y 图，connection_panel 负责连接和基线交互。客户端保持一份状态存储和一条订阅。

已有设计接口：`GET /api/status`、`POST /api/sensor/connect`（port、baud）、`POST /api/sensor/disconnect`、`POST /api/sensor/baseline`、`GET /api/sensor/stream`。客户端使用后端的 connected、error、bad_lines、port、sample_rate_hz、contact、xy、series、display 字段；不在客户端再次计算基线。

## 页面与视觉

适配 1920×1080 和 1366×768；默认窗口设计为 1360×860，主要按钮点击区域至少 44×44 px。功能字体使用中文无衬线。共同颜色：宣纸 `#eee9dc`、画布 `#faf5e9`、墨色 `#203f38/#293e38`、青绿 `#2d9c86`、浅青绿 `#74b8a7`、标题 `#356d62`、边框 `#c6d4cc/#d2c8b8`、提醒橙 `#b56b2f`、底稿灰 `#b9c3bd`。

人工页左侧约 65% 为等比例 XY 图，右侧约 35% 为连接区与独立 X、Y 时序图。XY 参考圆为 400 µT，标注单位、坐标轴和零点；越界仅在显示层沿方向钳位。每张时序图保留时间轴、零线、对称范围、最新值和无数据占位。

完整工作站首页使用连续墨迹动画及人工／机械臂两个入口。机械臂页提供单字输入、预览、动作与后端状态；执行阶段禁用互斥控件。单人工页原型不创建这些页面。米白纹理保持静止，青绿用于普通交互，橙色用于异常；避免快速闪烁与高频装饰。更细的像素、线框和动画初稿保存在重组前备份。

## 连接、基线和任务状态

连接失败与无数据保留图表框架并显示原因。取基线的设计窗口为 1 秒，期间绘图继续；完成后更新状态。WebSocket 恢复时先获取完整状态，再订阅实时流，避免重复连接和重复任务。

完整工作站的机器人动作由后端单一所有者调度，前端不得发送任意位姿。软件停止、故障、返回和沾墨水的状态须按具体后端契约处理；桌面设计不自动授权动作，也不替代当前实验控制器的停止行为。关闭时释放订阅、定时器和线程。

## 交付与验证口径

交付顺序是人工数据页、后端对接、可选完整工作站与机械臂页面。旧文给出的显示 30–50 FPS、p95 延迟不超过 100 ms、单帧不超过 64 KB、重连不超过 2 秒均为设计目标，不能读成测量结果。人工页原型建议约 30 FPS 消费快照。

验证覆盖 API/网关、空数据和超界显示、X/Y 独立图、断线恢复、不同窗口尺寸、按钮状态及关闭清理。具体已实现范围应核对代码与测试记录；本文件合并不重新判定交付完成状态。
