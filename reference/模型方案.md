# 模型方案 · 字形 → 逐笔运动轨迹 + 提按 翻译器

> 定位：项目软件线的"大脑"。输入目标字，输出**每一笔的平滑运动轨迹 + 提按曲线**，交给执行端复现。
> 上游 = `数采方案.md`（训练数据），下游 = `执行方案-力控.md`（把输出跑出来）。借鉴 = `2024_CalliRewrite_精读.md`。
> 生成 2026-07-09。诚实性与风险见 §10。

---

## §0 定位与三条硬约束（不可违背）

**模型 = "字形 → 逐笔画运动轨迹"的翻译器**，seq2seq/自回归 over 笔画。它把"标准字骨架"翻译成"人怎么运笔 + 怎么提按"。

| 硬约束 | 含义 | 为什么 |
|---|---|---|
| **① 不是 ACT 反应式模仿** | 不做"看当前状态→出下一步动作"的反应式策略 | ACT 会抖，你要平滑笔迹 |
| **② 输出曲线控制点，不是逐点轨迹** | 输出 Bézier/B样条控制点 + 提按曲线控制点 | 曲线**天生 C² 连续**，平滑由表示保证，与执行频率解耦 |
| **③ 分层，不端到端力矩** | AI 出**设定值**(轨迹+提按曲线)，经典控制器执行 | UR 无力矩接口；分层才可控可调 |

> 一句话：**模型只负责"写成什么样、每处按多重"，不负责实时伺服**。实时闭环是执行端的前馈+反馈干的。

## §1 输入 / 输出定义

### 输入（目标字，可分解到笔画）
为了**泛化到新字**，输入必须能拆成笔画（用标准笔顺/字体分解，与数采配对同一套）：
- **字级**：目标字的笔画序列、间架/包围盒（风格与布局上下文）。
- **笔级**（每一笔）：`(笔画类型 embedding, 该笔目标骨架形状, 在字中的位置, 前序笔画上下文)`。

### 输出（每一笔）
| 输出 | 表示 | 说明 |
|---|---|---|
| **平面路径** | 三次 Bézier / B样条**控制点** `{(x,y)_i}` | 笔画中心线；控制点少、曲线光滑（关联资料库 #15 双三次 Bézier） |
| **提按曲线** | 关于弧长的 1D 曲线控制点 `{g_press(s)_j}`, s∈[0,1] | ★核心增值；与运笔快慢解耦 |
| （辅助）笔宽 | `w(s)` | CalliRewrite 的宽度=提按视觉表现，作**辅助监督**，非最终执行量 |
| （v2）姿态 | `φ(s)` 笔杆倾侧 | v1 不出，v2 加 |

**为什么是控制点不是 waypoint**：逐点轨迹高维、易抖、要靠反应式策略去平滑（=ACT 的病）；控制点低维、样条**构造上就光滑**，采样多密都不抖。**这是满足硬约束①②的关键。**

## §2 为什么这样设计能泛化（核心论证，答辩必考）

**关键推论（本项目的立论）**：提按力度**不是字形的函数**，而是"**风格 × 笔画类型 × 笔内位置**"的函数。
- 例：所有"捺"收笔都有个重顿，所有"横"都是起笔顿→行笔匀→收笔顿——**这是笔画类型的属性，与具体是哪个字无关。**
- 所以只要**把提按曲线 condition 在"笔画类型 + 笔内弧长位置"上**，模型学到的就是"每类笔画怎么提按"，**换个由相同笔画组成的新字照样能生成** → 泛化成立。
- **推论直接决定数采策略**：按"**笔画覆盖**"采（几十~百来字覆盖基本笔画），不是按字数——见 `数采方案.md` §8。

## §3 架构

```
目标字 ──► [字级编码器] ── 风格/布局上下文 ──┐
  │  (笔画序列+类型+骨架+间架)               │
  └─► 逐笔特征 ─► [笔画解码器(自回归 over 笔)] ◄┘
                        │  第k笔 attend 字上下文 + 已写笔画
                        ├─► [空间头] → Bézier/B样条控制点 {(x,y)}
                        ├─► [提按头] → 提按曲线控制点 {g_press(s)}
                        └─► [宽度头(辅助)] → w(s)
```

- **字级编码器**：编码整字笔画序列（类型 + 骨架 + 位置）→ 上下文，管风格一致性与间架。
- **笔画解码器**：自回归逐笔生成，第 k 笔条件于"字上下文 + 前 k−1 笔"→ 保证笔画间呼应、风格连贯。
- **输出头**：空间控制点 + 提按控制点（+ 宽度辅助）。
- **右尺寸**：⚠️ 自示范数据量小（见 §10），**模型要小、强正则**，别硬堆大 Transformer。v1 甚至可退化成"笔级 GRU/MLP + 类型条件"，把"Transformer 自回归"留给数据变多后的 v2。**结构大小必须匹配数据量。**

## §4 训练

- **监督学习，不是 RL**（RL 是 CalliRewrite 阶段二，我们**扔掉**）。数据 = `数采方案.md` §0 的逐笔对齐记录。
- **损失**：
  - 空间：预测曲线 vs 人书写曲线的 **Chamfer Distance**（借 CalliRewrite）或采样后逐点误差。
  - 提按：`g_press(s)` 回归（采样 s 上 MSE）+ 宽度 `w(s)` 辅助监督。
  - **平滑/曲率先验**：惩罚过大曲率/角度突变（借 CalliRewrite 的 smoothness/angle prior）——样条已光滑，此项防病态解。
- **渐进训练**（借 CalliRewrite）：粗→细，或按笔数做课程。
- **数据增强（对抗数据稀缺，关键）**：
  - 几何抖动（平移/缩放/小旋转）。
  - **笔画重组**：从"笔画库"里抽笔画拼成**合成新字**，直接教泛化。
  - （可选）用字体/骨架数据或公开书法数据**预训练**空间头，再用你的数据微调提按头。
- **提按标签质量**依赖 `g_press` 解耦是否干净 → 见 §10 / E4。

## §5 数采 → 模型（上游接口）

| 数采字段（`数采方案.md` §0） | 模型用途 |
|---|---|
| `x(t),y(t)` → 按弧长重参数化 `x(s),y(s)` | 空间头的**监督目标**（拟合成控制点） |
| `g_press(s)` | 提按头的**监督目标** |
| `w(s)`（若从图像恢复） | 宽度辅助监督 |
| `stroke_id` + `char` | 笔画分段、类型标注、配对 |
| `v(s)` | v1 不进模型（执行端定速用）；v2 可作"运笔节奏"输出 |

- **统一弧长参数化 s∈[0,1]**：训练/输出/执行三端一致，运笔快慢解耦。

## §6 模型 → 执行（下游接口）

模型每笔输出 `{空间控制点, 提按控制点}` → 采样成 `x(s), y(s), g_d(s)=g_press目标` → 交 `执行方案-力控.md`：
- `x(s),y(s)` → **前馈位置**喂 x,y 轴（照走）。
- `g_d(s)` → **z 环目标**：`z_cmd = z_surface + z_from_calib(g_d) + Kv∫(g_d−g_press)dt`。
- 弧长→时间 `s(t)`：v1 用**设定的速度剖面**（定速），v2 用模型输出的节奏。

> 闭环全景：**`数采方案.md`（采）→ 本文件（模型出设定值）→ `执行方案-力控.md`（前馈+反馈跑出来）**。

## §8 评估

- **三件套**：① 字形 **IoU/SSIM**（写得像不像）② **提按复现误差**（对标论文 0.34N 量级，经粗略 ΔB→牛顿换算）③ 人眼评审。
- **关键基线对比**：**恒力回放 vs 带提按** → 证明触觉有用（这是卖点的实验证据）。
- **泛化测试**：在**留出字**（训练没见过、但笔画见过）上评估 → 验证 §2 的立论。

## §10 诚实性 & 风险

- **最大风险 = 数据稀缺 vs 模型容量**：自示范几十~百来字对 Transformer **偏小、易过拟合**。对策：小模型 + 强正则 + 笔画重组增强 + 可选预训练；**"用 Transformer"是既定方向，但结构必须右尺寸**，别为了名头堆大网络。这条要在报告里如实写。
- **泛化立论（§2）是假设，需实验证**：留出字评估通过才算数，别提前声称"能泛化"。
- **提按标签质量依赖 `g_press` 解耦**（E4 未过则标签含拖拽污染）→ 见 `数采方案.md` §5.3。
- **笔内"力对位置"的对齐**：方案 A（追标记）有真时序；方案 B 退路是 sigma-lognormal 估计 → 误差会传进标签。
- **平滑的边界**：样条保证**几何平滑**；但**执行平滑**还取决于控制器 + 触角带宽（E1）——模型平滑 ≠ 笔迹一定平滑。
- **"翻译器优于反应式"是设计选择**，其平滑优势有表示层依据（曲线 C² 连续），但**最终笔迹质量仍需端到端验证**，不是纸面保证。
- 立论/表示借鉴 CalliRewrite、#15、#8、#19，均为真实来源；**"力控闭环复现提按"这一步无直接前作**（CalliRewrite 无力觉），是本项目贡献点，如实标注。
